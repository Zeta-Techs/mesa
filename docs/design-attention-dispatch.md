# Mesa 设计草案：少占人的注意力——结构化问人、决策账本与事件规则

> 状态：**2026-11-02 已拍板**（architecture §10 同日条）：用户要求按最终合适的方向做、不受旧拍板约束；§9 各项按建议采纳，
> 其中撤回 2026-10-23「不做事件触发」的本机事件部分。§4.1 落地时把问人文件定为「同名文件 + 固定字段的 Markdown」，不换 JSONL（理由见该节）。
> 细则随各期写进 `docs/conventions/pipeline.md` / `terminal.md` / `agent-workbench.md`。

## 0. 一句话

Agent 单件活越来越不用人管，卡住产出的是人的注意力：一个人同时盯得住的对话只有三五个。Mesa 下一步不是让 Agent 干更多，
而是让**找上人的事更少、更准、点一下就能答**，并让一部分活在人不开口时按人写好的规则开始——开始之后仍然隔离、仍然要人验收。

## 3. 判据（每一期都按它取舍）

1. **注意力有价**：一张卡片、一次通知、一个设置项，都要比它占用的注意力更值；不值就不出现。健康状态不占地方。
2. **只在被叫或规则允许时动**：人点了，或人写的规则命中；没有第三种开工来源。
3. **只在人必须行动时开口**：要人回答、要人验收、跑不下去了。进展不推，「没新内容」不推。
4. **一次一个具体问题，结构化地问**：给建议和选项，人点一下能答；不让人读完一段报告再组织回复。
5. **按影响停，不按工作量停**：可逆、只动隔离副本的事自己定完写进报告；不可逆、对外、花钱、改方向的事停下来问。
6. **人的事永远插队**：人回答、人点继续，不排在规则触发的活后面。

## 4. 第一期：结构化问人与决策账本（建议先做，不碰任何否决项）

### 4.1 问人文件改成固定字段

仍是 `.ccode/help-wanted.md`（gitignored、一步一份）。不换成 JSONL：三十多处流程简报都指向这个文件，评审页「过程」里人也要直接读它；
固定字段的 Markdown 同样能严格解析，旧的单行写法照读。每条问题一个「- 」开头的行，下面缩进写字段：

```markdown
- 纳入标准是否包含会议论文？
  建议：B
  A：只要期刊 —— 候选从 212 篇降到约 140 篇
  B：期刊 + 顶会 —— 保留 CVPR、NeurIPS 等 9 个会议
  不回时：按 B 做可逆的准备，不写 included.json
  类别：范围
  依据：papers/screening.md「检索主题假设」
```

- 字段闭集：问题（条目行本身）、`建议`、选项 `A`–`D`（「——」后写一句后果）、`不回时`、`类别`（§4.3 闭集，缺省「一般」）、`依据`（只引位置，不抄全文）。
  其他缩进行算问题的补充说明。只有一行、没有字段的旧写法照样是一条问题，卡片上只给自由回答。
- 解析在 Rust 层（上限 20 条，每个字段截 300 字）；建议指向不存在的选项时当没写。
- 人在卡片上答了，Mesa 在该条下面加一行 `已答：B（期刊 + 顶会）`；交给 Agent 时再加 `已送：<时间>`。Agent 读到「已答」就照办，
  把答案写进 TASK.md「已定口径」或本步报告，再删掉这一条（沿用 2026-10-22「只放没答的」）。
- 任务书规则（替换 `HELP_WANTED_RULE`）：按上面格式写；同时未答不超过 3 条；每条给建议和兜底；不是七类之一的自己定。

### 4.2 卡片：票拟与批红

收件箱「人工请求」条目展开成卡片：问题一句、建议选项高亮、各选项后果一行、兜底一行、依据链接。人点选项（或写「其他」）后：

| Run 状态 | 回答怎么送到 |
|---|---|
| 交互 Run，终端还开着 | 点「交给 Agent 继续」，经聊天层送一句「help-wanted 里 N 条已答，按回答继续」，走现有提交核对 |
| 交互 Run 已关 | 记下回答，点「交给 Agent 继续」接回原会话（与「让 Agent 按决定继续」同一条路） |
| 无头 / 定时 | 记下回答；下一次运行的任务说明带上「上次你问的，人已答」 |

答完的卡片原地变成结论一行，送出之前可以改答。收件箱条目在「有没答的」或「答了还没送」时出现。

### 4.3 必须问人的清单（写进任务书，叠加在步骤的决策暂停策略上，不替代）

「类别」闭集，只有这七类可以停下来问；其余 Agent 自己定，写进本步报告「我自己定了什么」一节，人评审时看：

- 数据：删除或改写原始资料（`papers/` 原文、原始数据）、改数据剔除口径
- 范围：改研究问题、纳入 / 排除标准、主要结论方向
- 对外：任何对外发送（邮件、投稿系统、公开仓库）
- 花钱：付费全文、超出本步预算的大批量调用
- 合规：隐私、伦理、授权（与 auto_continue 原有的必等项对齐，落地时补）
- 人写的内容：改人手写的内容（笔记里的「我的想法」、人写的段落）
- 保护路径：碰保护路径

步骤自己的决策暂停策略（hard_pause / soft_pause）照旧更严；这七类是下限。

### 4.4 决策账本：定过的不问第二遍

- 卡片上有勾选「以后同类照此办」，**默认不勾**。勾了，这次回答作为一条项目知识写入 `.ccode/memory.md`，分类「已定」；人在卡片上选「不做」或写了拒绝理由时，分类「不做」。依据自动填问题原文、所选项与日期，人可当场改。走 `project_memory.rs` 现有写入（人确认、依据必填、revision 锁、改前留历史）。
- Agent 侧：上下文包已带项目知识；任务书加一句「提问前先查项目知识的『已定』『不做』，命中就照办，在报告里引用条目 id」。
- Mesa 侧不替人自动回答：新问题与有效的「已定」条目相似（复用研究档案提议的字二元组相似度）时，卡片顶部提示「你 10-28 定过：……」，给一键「照旧」。
- 跨项目：标了「适用于所有项目」的条目继续走研究档案的现有提议链。

### 4.5 注意力预算

- 同一 Run 的多张卡片在收件箱合并成一行「3 个问题待你答」，展开逐条答；胶囊数字等于展开后的条数。
- 已答、已撤回的不再计数；「没新内容」的后台运行不进收件箱（已是现状）。

## 5. 第二期：事件规则（需先撤回 10-23 的一部分）

### 5.1 规则是定时任务的扩展，不另起中台

`Schedule` 现有的「什么时候跑」从只有时间扩成触发闭集：

| 触发 | 条件 | 去重对象 |
|---|---|---|
| `time` | 现有频率 | 应跑时刻 |
| `folder` | 项目内指定目录落入新文件（可限扩展名） | 相对路径 + 内容哈希 |
| `radar` | 某条雷达有新命中且人留下了 | 文献标识 |
| `phone` | 手机投递的文件被人放进项目 | 落点路径 + 哈希 |

其余字段沿用：技能、连接（钉或项目默认）、隔离 worktree、超时、积压闸门、自动暂停。新增：

- `mode`：`off` / `record`（只记录）/ `run`（真跑）。**新建默认 `record`**。
- `batchWindow`：同一规则多少秒内的事件合成一单，默认 120 秒（一次拖进十个 CSV 是一单，不是十单）。
- `costCap`：每周花费上限，超了按现有自动暂停收口（`paused_reason`），进收件箱。

不做：webhook 入站、GitHub 事件、邮件、IM。它们要么需要公网入口，要么需要常驻进程。

### 5.2 只记录档

`record` 档命中时不调用任何模型、不花钱：在任务历史里记一行「本来会开一单：技能 data-clean，处理 `data/raw/2026-11-02.csv` 等 3 个文件」。人看过几次觉得对，再把开关拨到 `run`。规则是确定性的，所以只记录档零成本，这一点比 DeepSeek 的观察档（仍要模型研判）更省。

### 5.3 每个 Run 记依据

Run 加 `origin`：`{kind:"rule", ruleId, ruleVersion, trigger, objects[], summary}`，人点开的 Run 为 `{kind:"human"}`。`ruleVersion` 取规则内容哈希，改规则不影响在跑的 Run，只在历史里能看出它是按哪一版跑的。研究记录、Run 历史、收件箱卡片都显示一句「因为〈规则名〉：〈事件一句话〉」。

### 5.4 执行与收口

- 只开流程外的活（巡检类技能、清洗草案、精读草稿），不开步、不改步骤状态、不写流程正典（沿用雷达对 `included.json` 等的硬排除）。
- 产物照旧冻结、评审、人点采纳才进项目；**不自动采纳**。
- Mesa 开着才跑。关着期间落的文件：启动后按目录快照差补一次，多个合成一单（同补跑的合并口径），历史记「补收」。
- 文件稳定检测与重复事件去重照搬 `download_inbox.rs` 口径（大小稳定、同文件短时去重）。

## 6. 第三期：同对象并回原 Run 与卡住检测

### 6.1 同对象并回

事件对象与一条**未采纳、未关闭**的 Run 相同（同一数据文件又更新、同一审稿意见文件又补了一段），不新开，记为那条 Run 的「待送输入」：

- 交互 Run 活着 → 经聊天层送一句「〈文件〉更新了，变化：……」；
- 已结束未采纳 → 下次「继续」时一并带上，卡片提示「有 1 条新输入」；
- 已采纳 → 视为新事，新开一单。

`reuseKey` 闭集加 `rule:<ruleId>:<objectKey>`，同时只允许一个活跃 Run。

### 6.2 卡住检测（确定性，不用模型）

后台运行连续 N 分钟（默认 10）既没有会话输出、隔离目录也没有文件变化 → 收件箱「可能卡住」，给「看过程」和「停止」。现有超时（默认 30 分钟）照旧。不判断「有没有实质进展、方向有没有偏」——那是模型裁判，研究护城河稿 §6 已列不做。

### 6.3 人插队

规则触发的运行受同项目互斥锁约束；人点「继续」「回答」或新开交互对话不进这把锁的队列，永远立刻执行。

## 7. 以后再议（不在本稿立项）

- **消息外推**：只把「有卡片待你答」的提醒推到飞书 / 邮件，回答仍回桌面。触及 §11.5，与 architecture §12 Backlog「对标云端电脑型 Agent」第④项、「消息通道」批次一起拍。
- **第二台机器**：SSH 远程执行 Runtime（Backlog 已有），规则可钉到某台机器。
- **编程项目的 PR / CI 事件**：要先有不用常驻进程的取法（`gh` 轮询）再议。

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| 模型当 Router 决定派给谁、要不要做 | §11.5 智能路由 / meta-agent；跨厂商中立（Claude 不调度 Codex） |
| 模型研判事件是否值得处理 | 同上；规则写不出来的事件就不自动做 |
| 投机执行（没人要求先干起来） | 花人没要求花的钱；最多以只记录档的形式出现 |
| 云端状态 + 本机 daemon、webhook 入站 | §11.5 daemon 化；需要公网入口；DeepSeek 自认安全问题未解 |
| 自动采纳、自动合并 | 底线：改文件必须人验收才进项目 |
| Watchdog 用模型判断方向 | 自动语义裁判，研究护城河稿 §6 已列不做 |
| Mesa 替人自动回答已定过的问题 | 人拍板原则；只做提示与一键「照旧」 |
