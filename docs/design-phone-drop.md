## 0. 决策条目（原文已进 architecture §10，以那边为准）

### 2026-10-20 · 从手机添加：手机往桌面单向投递，Mesa 开着才收；§11.5「手机同步」收窄

用户要「手机上发消息、传文件，直接显示在 Mesa 上」。§11.5 自 v3.8 起把「手机同步」列为不做（贬值层）。当时否决的是
双向同步与后台常驻，本次需求是单向投递，范围小得多，收窄后放行。定下：

一，**定位是采集口，不是手机版 Mesa**。手机只把东西送进来：拍照、照片或文件、写一句话。看会话、批准操作、启动 agent、
看 diff、采纳一律不在手机上做——拍板留在桌面，与「AI 干活、Mesa 管活、人拍板」的分工一致。

二，**单向、Mesa 开着才收**。人在 Mesa 里点「从手机添加」才开始监听；点停止、30 分钟没有收到新东西、Mesa 退出，任一发生
即停。不做后台常驻，不做双向同步，不做云中转。

三，**一期只走局域网**。Mesa 在本机起一个只收不出的小服务，手机扫码打开网页上传，手机上不装任何东西；数据不出本机所在
网络，我方零基础设施。网络禁止设备互访（校园网、公司网常见）时，绕法是电脑连手机热点。飞书机器人等第二条通道，等隔离网络的
反馈再定，并与 Backlog「评审请求外推微信 / 飞书 / 邮件」合成一个「消息通道」批次一起拍板，不各做各的。

四，**先暂存，人点了才进项目**。手机来的文件先落 Mesa 自己的暂存目录，不直接写项目：项目根多出未跟踪文件会挡住工作区合并
（`review_contract` 闸门），东西放哪也该人点一下。进项目只走已有入口——PDF 走浏览器扩展「存到 Mesa」同一条入库链进
`papers/`，图片进 `notes/assets/`，文字进 `notes/clips.md`；编程项目不往里放（同「存进笔记」口径）。

五，**从对话输入框打开时，收到的东西直接变成这个输入框的附件卡或文字，不自动发送**。发不发由人决定。

§11.5 改为：「Docker/VM 沙箱、daemon 化、手机同步（双向、常驻）、云中转（贬值层；手机往桌面单向投递已于 2026-10-20 放行，
见 §10 当日条目）」。

## 1. 用户看到什么

### 1.1 两个入口，同一个弹层

| 入口 | 位置 | 收到的东西默认去哪 |
|---|---|---|
| 对话里 | 聊天输入框「+」菜单，「文件或图片」下面加一行「从手机添加」 | 直接成为**这个输入框**的附件卡或文字 |
| 不针对对话 | 命令面板（⌘K）「从手机添加」 | 进「手机收到的」列表，逐条处理 |

终端层不加入口（终端层可以切到聊天层再用）。全应用同一时间只有一个接收会话；已在接收时从另一个输入框再点，接收会话不重开，
只把「收到的东西去哪」换到新的输入框。

### 1.2 桌面弹层

- 标题「从手机添加」。正文一张二维码，下面一行「用手机相机扫这个码。手机和电脑要连同一个 Wi-Fi。」
- 二维码下是地址原文（可复制，给扫不了码的情况），多张网卡时旁边有「换一个地址」。
- 状态行：「等手机扫码…」→ 手机打开网页后变「手机已连上」→ 正在传时「正在接收 IMG_0012.jpg…」。
- 「收到的」列表：每条一行（缩略图或文件图标、名字、大小、时间、状态、动作，动作见 §2）。
- 折叠帮助「扫了打不开？」三条：确认两边连的是同一个 Wi-Fi；校园网或公司网可能禁止设备互访，让电脑连手机热点再扫；电脑弹出
  防火墙提示时点允许（Windows 要勾「专用网络」，见 §4）。
- 底部一行小字：「只在同一网络内传输，没有加密。在公共 Wi-Fi 上别传敏感文件。」
- 按钮：「停止接收」；从输入框打开时另有「收起」——弹层收成输入框上方一行「手机接收中 · 已收 3 · 停止」，接收继续，人可以
  接着打字（见 §8 待拍板第 2 条）。

### 1.3 手机网页

- 标题「发到 Mesa」，一行状态「已连上你的电脑。发出的东西会出现在 Mesa 里。」，前面带状态点（绿＝连着，红＝连不上，文案同步变）；
  页面一打开就探一次状态，状态点才是真的（2026-10-21）。
- 两个大按钮（浅底描边卡片加线条图标——黑色只留给「发送」这一个主按钮）：「拍照」（`<input type="file" accept="image/*" capture="environment">`，直接开相机）、「照片或文件」
  （`<input type="file" multiple>`，系统让人选相册或文件）。
- 一个文字框「写一句话…」和「发送」。
- 已发列表（空时写「发出的东西会列在这里」；免责提示沉在页面底部）：「上传中 42%」「已送到」「没送到 · 重试」。按顺序一件一件传，带进度（XHR `upload.onprogress`，fetch 拿不到上传进度）。
- 电脑停止接收后，页面每 15 秒问一次状态，问到已停就显示「电脑那边已停止接收。要再发，在 Mesa 里重新点『从手机添加』扫码。」
- 超限时：「超过 100 MB，没有发送」。
- 跟随系统深浅色；不引任何外部资源（字体、脚本、统计都不引）。

### 1.4 收件箱

列表里还有没处理的（没附到对话、没放进项目、没另存、没删）且弹层已关时，收件箱出一条「手机发来 N 条还没处理」，新类别
`phone:`，胶囊名「手机」，排在「待发送」之后，进「全部已读」的通报类。点开打开弹层的列表（不重新开始接收）。

不发系统通知：发东西的人就拿着手机，知道自己发了。

## 2. 落点与动作

| 收到的 | 对话模式下自动做什么 | 「放进项目」去哪 | 其他动作 |
|---|---|---|---|
| 图片 | 成为附件卡（带缩略图） | `notes/assets/phone-<时间>.<扩展名>` | 另存为…、删除 |
| PDF | 成为附件卡（文件名卡） | `papers/`：校验沿用 `attach_pdf_at` 三道（.pdf 扩展名、`%PDF-` 魔数、60 MB），落盘走 `save_paper_bytes`（字节去重、勘误替换、资源登记相位感知），与浏览器扩展同一条入库链；重复时提示「项目里已有同一份」 | 另存为…、删除 |
| 一句话 | 插进输入框（有字时另起一行），不发送 | `notes/clips.md` 追加一条，来源标「手机」 | 复制、删除 |
| 其他文件 | 成为附件卡（文件名卡） | 不提供（见下） | 另存为…、删除 |

- **「放进项目」去哪个项目**：对话模式 = 这个标签工作目录所在的已注册项目（与「存进笔记」同一套判定：`pathWithin` + 非编程项目，
  取最长匹配）；⌘K 模式 = 最近打开的科研 / 办公项目，列表右上角下拉可换。编程项目和随手聊目录不显示这个动作。
- **其他文件为什么不给「放进项目」**：放到项目里不被豁免的位置会让主仓变脏、挡住工作区合并。一期只给「另存为…」（系统存储
  对话框），存到哪是人自己的明确选择。
- **附件卡里的路径**指向暂存区的文件（与粘贴图片指向 `ccode/tmp` 同一做法）。发出去之后 agent 按路径读；暂存文件 7 天后清掉，
  与粘贴图片的保留期一致。
- **附件卡人可以 × 掉**，被 × 掉的条目在列表里回到「未处理」，可以再放进项目或删除。
- `notes/clips.md` 现有文件头写的是「终端摘记」。新建时文件头改成通用的「摘记」（来源：终端选中、手机），已有文件不改写
  （见 §8 待拍板第 3 条）。

## 3. 安全规则（审过后进 safety.md）

- **只在接收期间监听**：开始接收才绑定端口，停止、30 分钟无新内容、Mesa 退出时关闭；不随应用启动，不常驻。
- **只绑一张网卡**：绑到选中的局域网 IPv4 地址，不绑 `0.0.0.0`；端口由系统随机分配。
- **一次性令牌**：每次开始接收生成新令牌（`uuid` v4，122 位随机），放在 URL 路径里；令牌比较用定长比较。错令牌、未知路径、
  方法不对一律 404，响应完全相同，不暴露服务存在与否之外的信息。停止后令牌作废，再扫要重开。
- **Host 校验**：请求的 Host 头必须等于「绑定地址:端口」，否则 404（防 DNS 重绑定）。
- **只收不出**：路由只有手机页三个静态文件、状态查询、上传文件、上传文字。没有列目录、没有下载、没有读暂存区的接口。
- **响应头**：`Cache-Control: no-store`、`Referrer-Policy: no-referrer`（令牌在路径里）、
  `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:; connect-src 'self'`。
  手机页的脚本和样式各自是单独的静态文件，不写内联（与 Mesa 生产 CSP 同一纪律）。不发 CORS 头。
- **上限**：单个文件 100 MB，一次接收合计 1 GB，文字 2 万字；同时进行的上传最多 3 个，多出的回 503 让手机稍后重试。
  上传必须带 `Content-Length`，超限在读正文前就拒。
- **落盘**：边收边写 `*.part`，收满 `Content-Length` 才改名；断开或长度不符删掉半截文件。文件名 =
  `<YYYYMMDD-HHMMSS>-<paths::sanitize_fs_name(原名)>`，同名加 `-2`；原名只当显示用，不参与路径拼接。
- **暂存区**：`<config_dir>/ccode/phone-inbox/`，unix 上目录 0700、文件 0600；索引 `items.json` 读改写走进程锁 + OS 文件锁 +
  原子写（同配置读改写口径）。7 天清理（开始接收与打开列表时顺手清）。删除直接删，不进回收站（Mesa 自有临时目录）。
- **读取白名单**：`pdf::read_whitelisted_sync` 的根加上暂存目录（缩略图和预览要读），与 `ccode/tmp` 同等对待。
- **不出站**：暂存区不进诊断包；令牌不进日志、不进诊断包、不进 Run 记录；应用日志只记「开始 / 停止接收、收到 N 个文件」，
  不记文件名与地址。
- **收到的东西不执行、不自动打开**，只存。
- 界面如实说明是明文 HTTP；一期不上 HTTPS（自签证书会让手机报「不安全」，用户无从判断真假，反而更糟）。

## 4. 网络与平台（坑与待实测）

| 项 | 现状判断 | 处理 |
|---|---|---|
| 客户端隔离（AP isolation） | 校园网、公司网、酒店网常开，手机根本连不上电脑 | 帮助里写热点绕法；这是一期最大的已知短板，收集反馈决定要不要做第二通道 |
| 代理软件 TUN 模式 | Clash 一类开 TUN 后默认路由走虚拟网卡（常见 `198.18.0.0/15`、`utun*`/`tun*`），用「默认路由那张网卡」选地址会选错 | 用 `if-addrs` 列网卡，只取私网 IPv4（10/8、172.16/12、192.168/16），排除回环、169.254、198.18/15 和虚拟网卡名；优先 Wi-Fi / 有线；多个候选时给「换一个地址」 |
| 手机开了 VPN / 代理 | 访问局域网地址可能被 VPN 接走 | 帮助里加一句「手机开了 VPN 先关掉再扫」 |
| macOS 防火墙 | 系统防火墙默认关；开着时第一次监听会问「是否允许传入连接」 | 待实测：dev 构建每次重编签名会变，是否反复弹 |
| macOS 15+ 本地网络权限 | 不确定只监听、不主动连局域网是否需要「本地网络」授权 | 待实测；若需要，Info.plist 补 `NSLocalNetworkUsageDescription` |
| Windows 防火墙 | 第一次在非回环地址监听会弹提示，分「专用网络 / 公用网络」两个勾；新连的 Wi-Fi 常被归为公用，只勾专用会照样被拦 | 帮助里写清；dev 与正式包路径不同，各弹一次。待实测 |
| iPhone HEIC | 从相册选图时 Safari 一般会转成 JPEG，拍照入口可能保留 HEIC | 待实测；一期 HEIC 原样收，附件卡标「HEIC，有些 agent 读不了」；是否在 macOS 用 `sips` 转 JPEG 看实测再定 |
| 手机息屏 | 传大文件时息屏会中断 | 页面显示「没送到 · 重试」；一期不做断点续传 |
| 换了 Wi-Fi | 电脑地址变了，旧码失效 | 一期不自动处理，状态行在连续失败后提示「地址可能变了，停止后重新开始」 |

## 5. 实现结构

**后端 `src-tauri/src/phone_drop.rs`（新）**

- 生命周期：`PhoneDropSession { token, bind_addr, port, started_at, last_item_at, bytes_total }`，全局 `Mutex<Option<…>>`；
  服务线程收停止信号退出，应用退出流程里一并停（`join_with_timeout`，禁无限 join）。
- HTTP：`tiny_http`（同步、小，MIT / Apache-2.0）。不手写 HTTP 解析——这是暴露在局域网上的口子，不赌自写解析器。
  `hyper` 已经作为 reqwest 的传递依赖在锁文件里，但要另开 server 特性加 hyper-util，代码量与面都更大，不选。
- 二维码：`qrcode` crate（MIT / Apache-2.0）在 Rust 侧出 SVG 字符串给前端。
- 网卡：`if-addrs`（MIT / BSD-3）。
- 手机页三个静态文件放 `src-tauri/resources/phone-drop/`（`index.html` / `app.js` / `app.css`），`include_str!` 嵌进二进制。
- 命令：`phone_drop_start(bind?) -> { url, qrSvg, addresses, bindAddr }`（已在接收则返回现有会话）、`phone_drop_stop()`、
  `phone_drop_list() -> items`、`phone_drop_place(id, projectRoot)`、`phone_drop_save_as(id, dest)`、`phone_drop_delete(id)`、
  `phone_drop_set_status(id, status)`（附到输入框 / 被 × 掉；命令族还有 status/devices/remove_device/set_standby，见 §10）。
- 事件：`phone-drop-state`（`receiving` / `connected` / `stopped` 及原因）、`phone-drop-incoming`（开始收某个文件，给状态行）、
  `phone-drop-item`（收完一条）。DTO 整结构体 `#[serde(rename_all = "camelCase")]`。
- 进项目：PDF 调 `lit_watch` 的校验 + `save_paper_bytes`；图片把 `reader::save_reader_capture_sync` 里「根门槛 + symlink 双校验 +
  同秒避让」抽成公共内核，截图与手机共用，手机这边放宽到 PNG / JPEG / WebP / GIF / HEIC（魔数校验，20 MB）；文字调
  `projects::append_notes_file_at`（`notes/clips.md`）。

**前端**

## 7. 一期不做

- 手机上看会话、批准操作、启动 agent、看 diff、采纳。
- 后台常驻（Mesa 关着也能收）、双向同步、云中转、HTTPS。
- 断点续传、在手机上选项目。（「记住配对的手机」已在二期做了，见 §9）
- 终端层入口。
- 安卓系统分享菜单直接投递：需要装成 PWA，PWA 要求 HTTPS，局域网 HTTP 做不到，**不再列为二期候选**。
- 飞书机器人等第二通道（三期候选，与「评审请求外推」合并拍板）。

## 8. 拍板结果（2026-10-20 全部按推荐）

1. **PDF 要不要同时写进积累账（`papers/reading-list.md`）？**积累账一行要标题、作者年份、来源，PDF 里只能可靠拿到文件名，
   标题要从 PDF 内容里猜。**建议一期只进 `papers/`**（与浏览器扩展「存到 Mesa」一致），之后在文献卡里照常加入积累；
   确有需要二期再做「从 PDF 抽题录、人确认后写积累账」。
2. **从输入框打开后，弹层能不能收起、接收继续？**建议能：收成输入框上方一行「手机接收中 · 已收 3 · 停止」，30 分钟没新东西自动停。
   另一种是「关弹层即停止」，更简单，但人在实验室拍照期间桌面上的弹层得一直开着，也没法同时打字。
3. **`notes/clips.md` 混放手机文字可以吗？**建议可以：新建时文件头从「终端摘记」改成通用的「摘记」，每条标来源（终端 / 手机）；
   已有文件不改写。另一种是手机文字单独一份 `notes/phone.md`，多一个文件。

## 9. 二期：记住这台手机（2026-10-21 已实现，待真机点验）

用户要「扫码配对一次，手机页加到主屏，以后在 Mesa 里点开始接收，手机直接能发」。决策见 architecture §10 2026-10-21 条，
安全口径见 safety.md「从手机添加」（八条）。

**流程**

1. 第一次：「从手机添加」弹窗出二维码，地址是 `http://<主机>:<固定端口>/p/<本次配对令牌>/`。手机打开后页面自动 `POST pair`，
   电脑发一个长期设备令牌，页面把设备地址存进本地存储并跳到 `/d/<设备令牌>/?new=1`，显示「已记住这台手机」与加主屏说明
   （iPhone：Safari 分享 → 添加到主屏幕；安卓：Chrome ⋮ → 添加到主屏幕），随即用 `history.replaceState` 去掉 `?new=1`，
   免得主屏图标每次都弹说明。
2. 以后：电脑上点「从手机添加」（有已配对手机时聊天输入框入口直接开始接收、不弹窗），手机点主屏的「发到 Mesa」就能发。
3. 电脑没在接收时：主屏图标打开会是浏览器的「无法打开页面」（局域网 HTTP 没法装 service worker 做离线页）；页面已开着时显示
   「电脑那边没在接收」，每 4 秒问一次，连上后把排着的自动补发。
4. 同一台手机再扫码：先用存过的设备地址问一次 `state`，还有效就直接跳过去，不重复配对；被移除了就重新配。

**地址**

| 项 | 做法 |
|---|---|
| 端口 | 第一次由系统挑，记进配对簿 `port`，之后每次用它；被占时这次临时换端口、弹窗黄条说明，记下的不改 |
| 主机 | 电脑 mDNS 名优先（macOS 默认）；IP 作备选。人在「换一个地址」里改选过就记 `hostPref`（name / ip） |
| 监听 | 所有局域网候选网卡同端口各起一个 tiny_http，单线程轮询；Host 认 `绑定 IP:端口` 与 `电脑名:端口` |

**路由**：`/p/<配对令牌>/…` 与 `/d/<设备令牌>/…` 两种前缀，子路径相同（页面、`app.js`、`app.css`、`manifest.webmanifest`、
`icon.png`、`state`、`file`、`text`）；`pair` 只在 `/p/` 下。`state` 多回一个 `paired`。

**待实测（真机）**

- iPhone / 安卓解析 `xxx.local`：iOS 原生支持 mDNS；安卓 Chrome 能否解析待测，打不开就在弹窗换成 IP。
- iPhone 解析到 Mac 的 IPv6 链路本地地址时（我们只监听 IPv4），Safari 应回落 IPv4，确认没有明显卡顿。
- 主屏模式（standalone）下拍照、选文件、上传都正常；主屏图标与名字显示为「发到 Mesa」。
- Windows 上 `COMPUTERNAME.local` 能否被手机解析；不行就保持默认 IP。

**不做**：Mesa 开着就自动接收（会把「人点了才收」变常开，需另行拍板）；手机端列出电脑上的项目或对话（破「只收不出」）；
配对手机改名（名字按浏览器标识自动起，够认）。

## 10. 三期：已配对的手机随时能发（2026-10-21 已实现，待真机点验）

用户：「能否手机直接传，然后 Mesa 打开弹窗」。决策见 architecture §10 当日「已配对的手机随时能发」条。

| 项 | 做法 |
|---|---|
| 两种监听 | 主动接收（人点开始，有二维码、可配对，30 分钟无新内容结束）；常驻等候（配对簿 `standby` 缺省开且有配对手机时随 Mesa 开着，只认 `/d/`，`/p/` 404，不因空闲停） |
| 切换 | 主动接收结束（停止 / 空闲 / 网络变了 / 出错）→ 该等就转常驻等候（`ensure_standby`）；常驻中点开始 → 同端口重开成主动接收 |
| 启动 | 前端 `usePhoneDropEvents` 挂载时调 `phone_drop_sync`；移除手机、改开关后后端自己对一次 |
| 网络 | 比网卡地址集合，变了就以 `network` 结束、1.5 秒后按新网卡重开常驻等候。触发：Windows / Linux 用 `if-addrs::IfChangeNotifier` 系统通知立刻比（20 秒轮询兜底）；macOS 的 if-addrs 没有变更通知，4 秒轮询。现在一个地址都没有（Wi-Fi 刚断）不算变，等新地址出现再换（否则停了没有地址可重开、永远不恢复）。需要重扫的（主动接收的二维码令牌作废；常驻等候但电脑没有 mDNS 名、手机记的是 IP）以 `network-rescan` 上报，前端弹提示「请重新扫码」 |
| 弹窗 | `phone-drop-item` 到达且没有目标输入框 → 打开弹窗；窗口不在前台再发系统通知（长任务 OS 通知开关） |
| 上限 | 合计 1 GB 改为 24 小时窗口，没收完的退回额度 |
| 手机页 | 连不上时写「确认电脑上的 Mesa 开着、同一个 Wi-Fi」，排着的连上后自动补发 |

**待实测**：macOS 防火墙开着时，Mesa 启动即监听会不会每次弹「允许传入连接」；Windows 防火墙同理；笔记本合盖睡眠醒来后常驻等候能否自己恢复（网卡变化检测应能接上）。
