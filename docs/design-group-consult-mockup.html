① 发起研讨

入口在对话页「新对话」旁的 ▾ 里（左上角展开的那个菜单）。另两个入口不在这屏：对话回放 ⋯「请几家研讨这个问题」、项目助手回答里的「找几家研讨」按钮，都会预填问题和材料。

请谁按模型族挑，不按 CLI：第一位是「问 AI / 聊想法」那条连接；之后每位先保证模型族和已选的不同，同族里优先外壳能看项目的（Claude Code、Codex）。记住上次的选择。

这里 Kimi 这位是 Claude Code 外壳接 Kimi 模型的连接，所以「能看项目」——档位看 CLI，不看模型。Gemini 走 Gemini CLI，只能「只看材料」，默认没勾。

Claude·Sonnet 和 Claude 同族，不进默认；手动加上时卡片标「同一家模型，意见可能雷同」，不拦。

看完别家后再答就是交叉轮，默认 1 轮。

预估花费只显示、不拦。

不放在这里的

步骤卡不加按钮（主路径唯一）；没有「放手干」档位可选，研讨永远只读。

② 第一轮进行中

三家同时开跑。Claude 先答完，但卡片只写「已答完 · 等其他几家」，不展开内容——防止你先读了一家，带着它的看法读别家（待拍板 §11-2）。

进行中的卡片只给读了哪些文件，不给内容；每张卡有「停止」，顶栏有「全部停止」。单家 240 秒没答完按超时处理，不挡别家。

三位都能看项目：Kimi 经 Claude Code 外壳，读文件的工具和 Claude 一样，几家的差别落在判断上，不混进「谁读得更仔细」。

输入框此时也能打字，发出去的话等第一轮结束后再叫人。

③ 亮答案 · 交叉 · 追问

每条回答固定尾段：结论 / 依据 / 没把握。Mesa 把各家「结论」原话排成下面的对照条，只排版、不判谁对、不投票、不出共识。

依据核对：GPT 写的 analysis/loo.csv 项目里没有，标黄「找不到这处」；交叉轮里 Claude 也指出了这一处——这是研讨该有的样子。

交叉轮自动跑 1 轮，每家看别家第一轮的回答，只写补充、反驳或改判。Kimi 回了 [PASS]，聊天流里不显示，对照条写「交叉：没补充」。

追问：@GPT 只叫那一家；不 @ 就是问所有人。画面下方展开的是输入 @ 时的成员菜单。

输入框上方一行小字说明接力上限：你不说话时它们最多再互相叫 2 次，到了就停，写一句「先停一下，等你发话」。

左栏研讨行用成员的厂商图标叠代替 Agent 胶囊，meta 写「研讨 · 3 家」；标题照 MMDD|类型|主题。

④ 收尾

顶栏「收尾 ▾」或每条回答悬停时的动作：

记进项目知识：项目助手同一张卡，预填这条回答的结论，你改写后点了才写进「已定 / 不做」。一次一条，不批量采纳。

起草派活单：把问题、对照条和你选中的回答交给项目助手作为本次重点，它起草派活单，派不派你在项目助手里点。研讨自己不出派活单，派活单只有一个出处。

研讨不用「关闭」：没有调用在跑时它就是一份记录，随时能接着追问。记录在项目 .ccode/consults/，不进 git。
