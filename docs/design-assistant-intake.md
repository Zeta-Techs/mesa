# Mesa 设计稿：项目助手接活——范围内的需求都接得住

> 状态：**方向与 §9 细则已拍板，一期已落地**（2026-11-05，用户「按建议定并开工」）；落地与设计不同处见 §11。
> 起因：用户设想「把实验数据和实验记录放进项目，告诉项目助手需求，让它总结进度和实验现象、规划实验、画图、准备组会」，
> 讨论后补充：「这不过是一个方面，科研需求很多，**不要补浅层的**，而是项目助手可以接住用户的任意需求，或在范围内的所有需求。」
>
> 已定（用户原话即拍板）：不按场景逐个加专门功能（组会按钮、周报页、实验规划页一类都不做）；项目助手是接需求的通用入口。
> 同日用户问「那些科研任务不做了吗」，答复：照做，但做成内置任务包而不是专门功能，并建议提前到一期；用户「按推荐做」（§5、§8）。
> 本稿回答「通用」具体怎么做，§9 是待拍板的细则。

## 0. 一句话

用户用自己的话提任何需求，项目助手判断它属于哪种去向：问、做、定、常做、改流程，或者范围外。
属于「做」的，它先看项目里有什么、问清楚缺的关键信息，再起草一张**完整的任务合同**（依据哪些材料、交付什么、怎样算做完、用哪些技能、哪些事做的时候要停下来问你）。
你点「派出去」后，由干活的 AI 在隔离副本里完成，做完照常评审、核验、验收。
具体到某个课题组的做法（组会怎么讲、周报什么格式、记录怎么写），不由 Mesa 内置，而是做成一次以后「存成我的任务」，在用户手里越用越深。

## 1. 为什么不按场景补功能

科研需求列不完：组会、周报、实验规划、数据异常排查、画图、改图、写给导师的进展说明、答审稿意见、合并几批数据、准备答辩、整理一周的实验记录……
每个场景加一个入口，界面就多一套东西，而且永远补不完；更要紧的是做得浅，因为 Mesa 不知道你们组的组会讲什么、记录怎么写。

拆开看，这些需求底下只有五样共同的东西，Mesa 把这五样做到位就够了：

1. **知道项目里有什么**：数据、记录、文献、稿件、图、以前的产出，各在哪里，最近改了什么。
2. **知道 Mesa 能干什么**：装了哪些技能、有哪些「我的任务」、连接能不能出图和读 PDF、能不能定时。
3. **把一句话变成一份能执行、能核对的合同**。
4. **按合同干活，做完能评审、能核验**（已有：隔离副本、评审冻结、核验三档）。
5. **把做成的做法留下来**（已有底子：任务包、项目知识「已定 / 不做」、定时任务）。

具体做法放在 5 里，由用户和课题组自己积累；Mesa 只出通用能力，不出场景功能。

## 2. 需求的六种去向

| 去向 | 例子 | 项目助手做什么 | 落到哪个已有机制 |
|---|---|---|---|
| 问 | 「到哪了」「为什么失败」「这个按钮干嘛的」 | 直接答，写依据 | 已有（快照、说明书、只读查看） |
| 做 | 「把这周的记录整理成组会汇报」「看看第三批数据为什么离群」「画一张剂量-响应曲线」 | 看材料 → 问清楚 → 起草合同 → 你点了才派 | 派活单 v2（§3），交给第 N 步或新目标 |
| 定 | 「这两个方案选哪个」「这条人工请求怎么答」 | 只解释选项和各自依据，不替你选 | 原卡片、决策项、评审页 |
| 常做 | 「以后每周五都给我出一份周报」 | 起草定时任务或事件规则，你点了才建 | 定时任务、事件规则（默认只记录） |
| 改流程 | 「流程里加一步统计检查」 | 说明改法，带你去流程编辑器 | 流程编辑器 |
| 范围外 | 「帮我把邮件发给导师」「去订试剂」 | 说清楚为什么做不了、能做到哪一步（例如把邮件正文起草成文件） | §6 |

一句话里常常混着几种去向（「看看数据有没有问题，有的话画个图，下周组会要讲」），项目助手按顺序拆开：能答的先答，要做的合成一张单，要你定的列出来。

## 3. 接活怎么走

### 3.1 听懂

本地分流（`classifyQuestion`）新增 **「要做事」** 一类：句子里有「帮我 / 给我 / 做 / 画 / 整理 / 写 / 准备 / 规划 / 汇总 / 改」一类动作，并且指向项目里的东西。
这一类带上快照、项目地图（§3.2）、能力清单（§4），规矩里带派活条款。分流只决定带哪些材料，判错不要紧：其他类问题照旧可以在回答末尾带派活单（现状如此）。

### 3.2 看材料

- **项目地图**（新增，纯机械、不用 AI、不读内容）：项目根下的文件树，列相对路径、大小、修改时间、是否被 git 忽略，以及「上次问以来新增 / 改动」。
  排除 `.git/`、`.ccode/`、工作副本、依赖目录；有条数和字数上限，超了按目录折叠并写明「下面还有 N 个文件」。项目助手据此知道数据和记录在哪、最近动了什么。
- **起草前只读查看**：现在只读查看只用于查错（11-04 拍板）。接活时放宽到起草前：要写清「依据哪些文件、第几行、哪几条记录」，就得打开看一眼。
  进程级只读、不落盘的口径不变，只支持 Claude Code / Codex；别家起草时只凭地图，单子上写明「没有看过文件内容，依据按文件名推断」。
- **实验记录不定格式**：Mesa 不规定实验记录写在哪、怎么写。项目助手靠地图、只读查看和项目知识认出哪些是记录。
  用户在项目知识里写一句「实验记录在 `lab/`，一天一个文件」，以后每张单都照此办（项目知识已经进快照）。

### 3.3 问清楚

合同缺关键信息时先问，不猜：一次只问一个问题，尽量给可点的选项（同综述大纲「一问一答」的做法）。
最多问三个；还有不清楚的，按最稳妥的做法起草，并把假设写进单子的「先定下的假设」一栏，让你在派出前看得到、改得了。
这里问的是「要什么」；执行中那七类必须停下来问的事照旧由干活的 AI 在做的时候问，不在这一步预先替你答。

### 3.4 起草合同（派活单 v2）

派活单从现在的四栏（交给、标题、要做、怎样算做完）扩成与目标 / 步骤同一套合同字段，派出后不用转换就能直接开工：

| 栏 | 内容 | 落到 |
|---|---|---|
| 交给 | 第 N 步 / 新目标 / 定时（§3.6） | 去处 |
| 标题 | 十来个字 | `TaskDto.name` |
| 要做 | 具体到文件、位置、做法 | `description` |
| 依据材料 | 要读的文件和目录（只读） | `inputPaths`，派出前先算隔离输入预算，超了在单子上就报 |
| 交付物 | 产出什么、写到哪里 | `outputPaths` + 要做里写明 |
| 怎样算做完 | 能核对的标准 | `description` 的验收段 |
| 用到的技能 | 只从已装技能里挑（§4） | `TaskDto.skills` |
| 先定下的假设 | §3.3 没问清、按默认处理的几条 | `description` |
| 做的时候要停下来问的 | 这次特有的必问（只能加，不能减七类） | 任务书 |

单子在面板里可以逐栏改，「派出去」之前什么都不发生。

### 3.5 科研通则（每张单都带）

不按场景写规矩，只写一套所有科研单子都带的通则，进任务书：

- 数字由脚本算出，脚本留在交付物里；不手抄、不估。
- 每条结论标出处：哪条记录、哪个数据文件、哪篇文献（bib 键）。
- 不编造数据、不生成冒充实验结果的图像。
- 「规划」类的交付物只给两三个候选方案，各写依据、假设、风险和所需样本量，由人来选，不写「建议采用」。
- 原始资料只读；人改过的文件为准，在它上面局部改。

其中能机械检查的（出处是否存在、数字是否来自脚本输出）走核验，判定照旧三档。

### 3.6 派出与回来

- 去处：第 N 步（问题出在某一步的产物上）、新目标（不属于任何一步的活）、定时（「常做」，起草的是定时任务，人点了才建，跑在隔离副本里，经评审进项目）。
- 派出后的状态显示沿用现有 `dispatchStatus`。
- 做完、验收后，在项目助手里可以接着说「第二张图纵轴改成对数」：项目助手把已采纳的那份产物作为依据，起草新的一张单，局部修改，不从头再做。

### 3.7 一句话要做好几件事

- 能串着做的（先查数据、再画图、再做汇报），合成**一张单、多个交付物**，由一个 AI 按顺序做完，只评审一次。
- 能并行、量又大的（三十篇文献各抽一份表），带着草稿去「拆成几路做」，照旧由 AI 提议、人批准一次。
- 不做自动链式调度（做完 A 自动派 B）：每张单都由人点。

## 4. 能力清单：让项目助手知道 Mesa 能做什么

快照里加一块「能做什么」，全部来自已有数据，不调用 AI：

- 已装技能：名字 + 描述里的「什么时候用 / 什么时候不用」。
- 我的任务（任务包）：名字、说明、参数表。
- 这个项目的流程步骤和各步现状（已有）。
- 连接能力：项目默认连接能否无头运行、能否出图、能否读 PDF（取自 AgentSpec 能力表）。
- 定时、事件规则能做的触发种类。

起草时，项目助手在单子的「用到的技能」里点名技能，或说明「按我的任务『组会汇报』来做」。这需要窄放开一条既有拍板（§9 第 1 项）。
清单里没有合适的技能也照样接：单子上写「没有现成技能，这次按通用做法」，做成之后可以存成我的任务（§5）。

## 5. 越用越深：一次性的单子变成我的任务

这是「不补浅层」真正落地的地方：深度由课题组自己的做法积累，不由 Mesa 内置。

- 一张单派出、验收通过后，卡片上出现「存成我的任务」：单子各栏直接映射成任务包字段（要做 → `brief`，依据 → `inputs`，交付物 → `expectedArtifacts`，怎样算做完 → `acceptanceCriteria`，技能 → `skills`）。
  每次会变的部分（时间范围、哪一批数据、哪本期刊）由 AI 起草成参数，人确认才存；走任务包现有的预览、确认入库流程。
- 下次再有同类需求，项目助手在能力清单里看到这项我的任务，就按它起草，课题组的做法得以延续。
- 「以后同类都这样」写进项目知识「已定」（已有机制，Mesa 不替人自动回答）。
- 「每周都做」起草成定时任务（§3.6）。

**内置三个常见科研任务**（已定，一期就做）：组会汇报、进展周报、实验规划。

- 做法：~~作为内置模板写进 `pipeline-presets.ts`~~（落地时改，见 §11）：单独写在 `builtin-tasks.ts`，不当流程模板；用在派活单「按任务」与科研项目新建目标「用任务当模板」。
  「另存为我的版本」与三期「存成我的任务」同一机制，届时一起做。不另做按钮、页面或入口。
- 接活时：项目助手在能力清单里看到它们，起草单子时写「按内置任务『组会汇报』来做」，单子正文由模板的步骤合同展开（与「记目标用我的任务当模板」同一条 `goalTextFromPack` 口径），人照样能改每一栏。
- 用途有两层：一是新用户第一次用就有一套比通用做法扎实的做法；二是给「存成我的任务」当范本，用户照着改就知道一个好的任务长什么样。
- 三个任务的写法都受 §3.5 科研通则约束：组会汇报每页结论标出处、图只取项目里已有或脚本现画的；进展周报只写有记录的事；实验规划只给候选方案，并写明需要你来定的变量。
  它们同时是一期验收的十条干跑需求里的三条。

## 6. 范围：接什么，不接什么

**范围内**：能在这个项目里，由连接好的 Agent 在隔离副本里做成、产出能评审的文件的活；以及关于这个项目和 Mesa 的所有提问。

| 不接 | 怎么回 |
|---|---|
| 跨项目（「把 A 项目的数据拿来比」） | 说明只管当前项目；可以先把那份数据导入这个项目 |
| 电脑之外的动作：发邮件、订试剂、操作仪器、提交投稿系统 | 起草成文件（邮件正文、采购清单、仪器参数表），由你来发、来执行 |
| 替你做科学判断、选方案、答人工请求 | 列出候选和依据，你来定 |
| 修 Mesa 自己的毛病 | 整理记录，「报告给开发者」（已有） |
| 绕开 Mesa 的不变量（跳过评审、关隔离、直接写项目根） | 不做，说明原因 |
| 编程项目里的「做」 | 本稿不包括：带你去从基准开一条分支（现状），后续单独设计 |

## 7. 和既有拍板的关系

| 既有拍板 | 本稿 |
|---|---|
| 项目助手只解释不动手、自己永远不写文件（11-04） | 不变。接活只是把单子起草得更完整，干活仍归工作者 |
| AI 提议、人批准一次 | 不变。每张单、每条定时都由人点 |
| 不按任务特征自动推荐或套用任务包 / 技能（09-07、10-11、11-03） | 需要窄放开，见 §9 第 1 项 |
| 不做模型路由 | 不变。单子不挑模型，派出后走绑定解析塔 |
| 少占注意力：只有七类必须停下来问 | 不变。§3.3 问的是「要什么」，最多三问 |
| 只读查看只用于查错（11-04） | 放宽到起草前，见 §9 第 2 项 |
| 快照不放文献 / 数据 / 稿件正文 | 不变。地图只有文件名和元数据，内容只经只读查看 |
| 实验数据自动分析放后期，触发由人设（10-27） | 由「常做」去向接住：项目助手起草，人点了才建 |

## 8. 分期

- **一期：把单子写对，并带上三个内置科研任务**。「要做事」分流、项目地图、起草前只读查看、问清楚、派活单 v2、科研通则；
  内置任务「组会汇报」「进展周报」「实验规划」（§5）；精简版能力清单：只列内置模板、我的任务、已装技能的名字和一句话说明，单子能点名它们。
- **二期：能力清单补全**。加上连接能力（能否无头运行、出图、读 PDF）与定时 / 事件能做的触发种类，单子按连接能力说明能做到哪一步。
- **三期：越用越深**。「存成我的任务」、起草定时任务。

每期验收：
- 用十条不同类型的真实需求干跑（组会汇报、进展周报、实验规划、数据异常排查、画图、改图、给导师的进展说明、答审稿意见、合并数据表、整理实验记录），
  每条都要落到 §2 某个去向；落到「做」的，单子要能不改一字就开工。
- 按「动真实数据先干跑」，在用户的一个真实项目上派出一张，走完评审和验收。

## 11. 落地记录（2026-11-05 一期）

与上文不同处（以这里为准）：

- **内置科研任务不是流程模板**：内置模板都是整条流程，把「组会汇报」做成第七套，人在「更换模板」里选中会把整条流程换成一步。改为 `src/builtin-tasks.ts` 单独一类，
  只用在派活单「按任务」与科研项目新建目标的「用任务当模板」下拉（「内置科研任务」一组）；「另存为我的版本」挪到三期，和「存成我的任务」一起做。

## 13. 「让它真正像个助手」与三期（2026-11-05）

用户问「项目助手的对话要不要都留、和新对话有什么区别、怎么让它真正像个助手」，看过分析后说「按你推荐的全部做完善」。定：

- **记录与记忆分开**：问答记录照旧留（每项目 200 轮），满了只丢普通问答，派过活的轮次与它的回音不丢（审计线索）；记忆不靠翻记录——
  用户说出以后都要照办的偏好时，项目助手起草一句「以后照这样办」，人点了才记进项目知识「已定 / 不做」（与项目设置同一份），以后项目助手和干活的 AI 都照着办。
