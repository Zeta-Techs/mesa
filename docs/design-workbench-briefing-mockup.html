1简报条 一期

一句话报总数。「上次查看」是 Mesa 自己存的基线（每个项目一份：时间 + HEAD + 未提交改动的指纹），不碰各家 CLI 目录。点「全部看过了」或卡上的「看过了」才挪基线，打开工作台本身不算看过。

取代：页头「N 个运行中」。

2要你拍板 二期

「待你处理」和「待你验收」并成一个队列，只放非你不可的：Agent 在问、待验收、冲突、需确认。每行带等了多久。信息类通报（文献新命中、可合并）收进「还有 N 条通知」。

「Agent 在问」直接摘出那句问题，你不用点进去才知道问的是什么。回复仍然回到那段对话里发，不在工作台代答。

3各项目发生了什么 一期

只列基线之后有动静的项目，Mesa 里和外部客户端里的一视同仁；没动静的折成一行。

谁动过：按 Agent 和客户端分，虚线芯片 = 外部客户端。
改了什么：git 项目看新提交 + 未提交改动的行数统计，展开到文件，并标出哪一家改的；非 git 项目按修改时间扫。
停在哪：每段对话的结局——在问你 / 做完了 / 中断 / 正在干。

数据来源：会话文件（已在扫，只读）＋ git ＋ 基线。新增一个后端汇总命令。

待核实：能不能分出「客户端」——Codex 会话的 originator、Claude Code 会话的 entrypoint 要拿真文件看；分不出就只按 Agent 分，不假装。「结局」现有解析是否给得出也要查。

4没验收的改动 一期

外部客户端和「＋新对话」是直接写进项目的，绕过了 Mesa 的验收。这里把它点名：哪几个文件、谁改的、什么时候。

编程项目走现有的逐段验收再提交；科研项目额外指出「派生产物直写项目根」（现有规则下算未验收产物）。

5搁着的事 二期

按搁置天数排，超过 7 天变黄：记下没开工的目标、领先没合的分支、停在提问没人回的对话、连续失败的定时任务。这些现在散在项目页和收件箱里，看不出放了多久。

6交接摘要 三期

点按钮才跑，一次性内部调用、不落盘。输入就是上面的结构化数据加各对话最后几句。只给草稿用来复制进日报、组会，不写进项目记忆（现有规则：Agent 结论不自动采纳）。

撤掉的：「最近对话」区块（侧栏和对话管理页已有，改由项目卡里的「停在哪」承担）。主卡「正在进行」不再单独占一大块，只在都看过了时出现。

空闲态（上方切换）：没有新动静时回到「接着上次的」大卡，下面是搁着的事和「这一周」的验收、提交统计。

不做：用量摘要、最近产物（10-26 已否）；自动拆任务、替你选 Agent。
