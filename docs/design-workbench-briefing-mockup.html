这一稿减了什么

项目从大卡改成一行：名字、一句话、时间；点开才看提交、文件、对话。默认只展开第一个有事的项目。
「谁动过」芯片、改动行数、每张卡的黄框都撤了：要你拍板的统一进上面的队列，一件事只出现一次；外部改动只在项目行里如实写一句。
「搁着的事」折成一行，「交接摘要」收成页头一个按钮。最近对话不再列出。

要你拍板一期二期

只放 Mesa 自己发起的活里非你不可的事：Agent 在问、交回来待验收、合并冲突。一行一句话加一个按钮，最多四行，多了折起。通知类（文献新命中、可合并）不进来，只在右上角写「另有 N 条通知」。外部改动不进这里——那不是 Mesa 要你拍板的事。

外部改动：只看，不碰一期

Mesa 是监控台和控制台，不跟用户在别处的改动抢。外部客户端、其他 Agent 改的东西，可能已经提交，也可能还在改，Mesa 一律只读：

Mesa 发起的活照旧：隔离副本里干，交回来你验收才进项目。
外部的提交列出来、能看 diff、标出是谁提交的。不撤回、不 revert、不改历史。
外部没提交的列出文件和最后改动时间。不逐段验收、不暂存、不提交、不丢弃——那边可能还在改。
看到哪「看过了」只挪 Mesa 自己记的位置（每个项目每条分支一个提交号），不往仓库里写任何东西。
要改怎么办「在 Codex 客户端打开」等跳回改它的那个地方去处理；或者你在 Mesa 里新开一个目标，走 Mesa 自己的验收。

Mesa 自己写的时候让路：Mesa 要往项目里写（采纳评审、合回 main、提交）之前，先看目标位置有没有外部没提交的改动或刚来的新提交；有就停下，说清是谁、哪些文件，交给你决定，不覆盖。现有的采纳三向判定和「同名冲突点名交人」已经是这个口径，这里把它推广到合并和提交。

谁提交的：按提交时间对上同一目录里在跑的对话，再看提交信息里的 Co-Authored-By 尾注；都对不上的写「来源不明」，不猜。

待核实：时间对齐在多个 Agent 同时干活时会不会认错；Codex / Claude 各家默认写不写尾注；记的提交号被 rebase 掉时怎么回落（初步想法：回落到按时间）。

非 git 项目只能列「哪些文件在什么时候被改了」。

不做：动外部改动（撤回 / 验收 / 提交 / 丢弃）；往用户仓库装钩子或改规则文件来拦外部提交；用量摘要、最近产物（10-26 已否）；自动拆任务、替你选 Agent。
