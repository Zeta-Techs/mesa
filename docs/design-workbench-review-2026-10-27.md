# Mesa 工作台 UI 与功能完善建议

日期：2026-10-27。用户已确认实施本方案。对应交互原型：[design-workbench-refinement.html](design-workbench-refinement.html)。

## 结论与审查范围

当前结构值得保留：**等你拍板 → 项目分组 → 定时任务**，已经能把跨项目工作收拢到同一页。下一步应完善可读性、窄窗排版、状态解释和导航落点，减少看见问题后还要猜的地方。

总体评价：**需要完善**。存在可从颜色令牌确认的小字对比度问题；固定列布局、模糊的「继续」以及只靠悬停解释的定时点，也有明确的改进空间。设计方向是安静、可扫读的项目工作台，让人的注意力集中在待决定的事与正在做的事。

本次查看了 `WorkbenchPage.tsx`、项目分组、定时总览、任务面板、相关纯逻辑与主题令牌，并按关键词读取工作台产品约定。确认当前仓库有 `tauri dev --config src-tauri/tauri.dev.conf.json` 进程，Vite 来自本仓库并监听 17575；原生界面工具未能绑定该开发窗口，因此**现状判断来自源码，不是原生界面实测**。

本文件保留首轮审查依据；首轮与 HTML 只交付设计提案。随后用户「按你设计的执行」确认落地，正式工作台已按本方案修改，费用收进任务详情，规则记录在 codex-style-ui.md §5.2 与 architecture §10。原型中项目、文献、金额、文件数量和时间均为虚构示例；不能把它们当作项目实情。

## 应保留的部分

- 分组列表适合任务名、状态和时间的横向比较，继续沿用，不增加网格或多种视图。
- 拍板队列有稳定优先级，审批、结果和通知分层；已有撤销机制、键盘导航、失败恢复，不再提议重复造一套。
- 项目下列任务，点任务看详情；继续依赖现有 Project → Task → Run 的归属与恢复机制。
- 同一件事只提供一个处理入口。工作台负责看清上下文与带路，开工和验收继续在原页面完成。
- 实时活动只表达已经知道的事实，读不到时保留「正在干活」，不编造百分比或剩余时间。
- 首页不增加大标题、统计仪表盘或重复的「新对话」入口；侧栏收展继续由用户手动控制。

## 必须修的可读性问题

### P0 / Critical：类别与最近活动文字的对比度不足

**证据**：`src/components/WorkbenchProjectGroup.tsx` 的任务类别与非运行任务的最近活动使用 `text-l4`；`src/components/WorkbenchSchedules.tsx` 的时间轴文字也使用它。默认 `neutral` 的 `l4=#6e6e6e`、画布 `#111111`，对比度为 **3.70:1**；macOS `neutral-light` 的 `l4=#7e7e7e`、画布 `#ededed` 为 **3.47:1**。这些文字约 11px，低于普通小字的 4.5:1 目标。数值根据实际令牌计算，不是截图估色。

**建议**：这些文字改为至少 `l3`；`l4` 保留给不承载信息的装饰。任务名 13px，状态/时间 12px，类别最低 11px；更长文字允许增高换行。跨主题验收要读最终平台覆写后的颜色。

**原型**：辅助色在深色内容面上的对比度为 **6.59:1**，浅色为 **5.69:1**；蓝色按钮白字为 **5.39:1**。这些是指定色对的检查，不代表全页面无障碍验收已经完成。

依据：`accessibility.md › Vision`：「Strive to meet color contrast minimum standards.」；`typography.md › Ensuring legibility`。

## 按优先级完善交互与功能

|---|---|---|
| P0 / High | `WorkbenchProjectGroup.tsx` 的 `TASK_GRID` 固定七列；定时任务也是固定列。固定列先占去宽度，名称与状态只能竞争余下空间。此项是代码可见的布局风险，未声称在某尺寸实际截断。 | 按内容容器宽度改排版。宽窗对齐，较窄时把时间移到状态下面，再窄时整行上下排；任务名、关键状态与入口保持可见。HTML 顶栏提供「窄窗预览」。 |
| P1 / High | `openContinueTarget` 可能聚焦活对话、恢复旧 Run、打开项目或进入目录；项目头统一写「继续」，只有 tooltip 解释。 | 用同一个目标解析结果同时决定行为和文案：回到对话、打开项目、打开目录。原型展示前两种；目录分支仍需实现时补齐。不要为改文案另写一套导航判断。 |
| P1 / High | 审批 `deferRow` 在 5 秒之后才真正调用 `chat_channel_reply`，toast 当下已写「已允许 / 已拒绝」，会让用户误以为 Agent 已经收到。 | 待发送期间写「将在 5 秒后允许一次，仍可撤销」；成功后再写已发送，失败时恢复队列并说明下一步。原型支持等待与撤销，以及倒计时后的模拟提交；未连接真实 CLI。 |
| P1 / Medium | 行内审批主要显示标题与截断的命令/路径。更多上下文需要回对话，但「允许一次」的作用范围可以更明确。 | 可打开审批详情，完整展示 CLI 提供的请求内容、目录与回复范围，再允许一次 / 拒绝 / 回到对话。不推断命令安全性；旁路没有的字段如实标未知，不能照抄原型虚构数据。 |
| P1 / Medium | 任务详情已有目标、产物、验收标准和过程，但动作放在详情内容后面。长目标或多项标准会把下一步挤出可见区域。 | 操作放到详情标题下方的固定区域；正文仍按当前类型按需出现。保留「去验收」「回到对话」，不在工作台放直接采纳按钮。原型演示详情及原入口落点。 |
| P1 / Medium | 定时轴是绝对定位的小点，任务名只在 `title` 中；相同时间的点会落在同一位置，且点本身不是可聚焦按钮。 | 时间与任务名一同出现，支持键盘打开详情；同刻多项聚合成「N 项」并展开。暂停项指回拍板区。原型展示具名时间项，尚未实现同刻聚合。 |
| P1 / High（待辅助技术验证） | 队列用 `listbox / option` 表达，而每个 option 内有多个独立操作按钮。这种语义与复合列表选择器不一致，需要专门验证读屏与焦点。 | 采用普通 `ul / li` 承载内容与按钮；如继续用复合控件，必须实现对应的完整交互模型。保留 J/K，同时让 Tab、回车和焦点恢复独立可用。原型采用列表、原生按钮与详情焦点圈定。 |
| P2 / Medium | 页面已有读取错误与重试，但一边保留旧数据一边报错时，用户不一定知道下面的信息有多新。运行时长与「最近活动」共用一列，也主要靠 tooltip 区分。 | 有可靠快照时间时显示「状态截至 HH:mm」；部分加载失败时说明影响范围。时间直接带「本轮」「更新于」前缀。原型提供「部分加载失败」场景；正式落地需要先提供真实快照时间，不能用渲染时间代替。 |

## 视觉与信息密度的取舍

建议继续用当前默认的极简灰蓝主题与系统字体。用字重、缩进和间距区分项目头与任务，不给每类任务另铺颜色。强调色只承担选择与主要操作，黄色只给真需要人决定的事。

原型把花费收进任务详情，列表保留「任务 / 状态 / 时间」，这项密度取舍现已由用户「按你设计的执行」确认。如果希望跨任务横向看花费，可在宽窗保留现有花费列、窄窗移入详情；费用仍必须沿用已计价/未计价口径，不补估算值。

任务名称、实时工具名和失败说明比统计卡更值得占首屏。待办多时保留展开出口；普通通知默认收拢，以免「要我决定」与「告诉我一声」抢同一层注意力。无需新增智能路由、自动拆任务或主仓自动采纳。

## HTML 的范围与使用

双击 `design-workbench-refinement.html`，用本机浏览器打开。无需联网、安装依赖或运行服务，所有 CSS、SVG、示例数据与交互都在文件内。

可以体验：

1. 日常工作、待办很多、暂无待办、首次使用、部分加载失败五种场景。
2. 深浅色与 800px 窄窗预览；侧栏手动收展。
3. 项目筛选、折叠、记下目标、任务详情与原入口导航落点示意。
4. 允许一次 / 拒绝，5 秒待发送与撤销；定时任务模拟开始 / 停止。
5. 工作区 J/K 选择与回车打开，详情 Esc 关闭与 Tab 焦点圈定。

原型中的导航只展示落点，不实现完整的项目页、终端或验收页。侧栏简化了资源入口，以集中展示工作台；这不代表建议删除或合并正式产品入口。没有接入权限、会话或文件系统 API，所有变化只在当前页面内存中；切换场景会重置演示状态。

## 验证与实施建议

已运行一次性 `node --input-type=module` 脚本，通过 `vm.Script` 检查 HTML 脚本语法，并用 JSDOM 核对场景切换、展开筛选、目标文本转义、详情打开/关闭/焦点恢复、审批撤销、模拟发送、切场景取消待发送、定时开始/停止、错误重试、深浅色/窄窗开关和 DOM ID 唯一性。指定颜色对的对比度已计算。JSDOM 中 dialog 与滚动能力使用最小桩，键盘可见性检查使用模拟几何数据；它们不构成原生行为或渲染验收。

本次只新增两份 `docs/` 下的设计文档，按仓库文档改动口径没有运行 `npm test`、`npm run build` 或 `cargo test`。

**浏览器视觉验收未完成**：预览工具的安全策略拒绝本地 `file://` HTML；未通过其他方式绕过该限制。原生 Mesa 开发窗口也未能被界面工具读取。因此，真实字体、800px 换行、200% 放大、读屏、实际平台焦点与截图均待后续在可用环境验证。HTML 使用容器查询，但其实际布局尚未验证。

建议先落地可读性与窄窗适配，再处理导航和反馈文案，最后完善任务详情、定时项与边界场景。每批只改对应组件及其共享逻辑；已存在的目标归属、费用计算、原入口和 Run 恢复机制继续复用。正式产品修改后再按 AGENTS.md 同步用户指南与 CHANGELOG；本次设计提案不写入产品决策记录。


## 实施核验（用户确认后）

正式工作台已接入自适应分组、实际导航落点文案、审批原文详情与真实延迟反馈、固定详情操作、具名定时时间项及同分钟聚合、原生列表与焦点导航、通知折叠和按读取范围记录的真实快照时间。开工、CLI 回复、Run 恢复、评审与验收仍走已有入口。

新增 JSDOM 集成测试覆盖审批撤销 / 成功 / 失败 / 同对话下一问、请求原文、详情焦点圈定与返回、键盘作用域、hooks 审批边界、费用按需读取与去重、失败保留旧数据与重试、定时同刻展开及只刷新定时数据。真实 CLI 回复以模拟命令边界验证，未向用户会话发送审批。样式构建通过不等于视觉验收；界面工具仍无法绑定正确的 Mesa Dev 热更新窗口，未用旧打包窗口替代。

最终验证：使用本机 Python 3.14.6 所在目录置于 PATH 前执行 `npm test`，2445 项全部通过、无跳过；`npm run build` 通过（保留现有的大分包体积提示），`git diff --check` 通过。默认 shell 的系统 Python 过旧会使既有 EndNote 测试报 `Path.write_text(newline=...)` 参数错误；本次未改文献功能或系统 Python 配置。未改 Rust，按仓库口径未运行 cargo test。
