## 0. 起因

2026-11-06 用户请 Agent「整体看一下每个科研步骤流程，给专家建议」。结论：骨架对，缺口集中在实验与收尾两头——
科研论文 / 毕业论文默认实验是 AI 写代码跑的（模板说明写着「计算实验向」），而当前用户做电催化、电池，实验在实验室里做；
定量领域综述的核心是性能对照表，但数字散在笔记自由文字里；检索做在几个月前，投稿前没有更新；导师和合作者的 Word 批注进不了流程。
另有几处模板小项。用户追问「分节写会不会伤一致性」后定：初稿默认一段对话顺序写，稿子大时才分路，分路必须先定约束、最后统稿。

## 1. 初稿写法：默认顺序写，大稿才分路（§8-1）

- **所有初稿步**（综述初稿、论文初稿、学位论文初稿）：先写 `manuscript/style-sheet.md` 写作规范（术语与缩写的统一写法、各在哪一节首次定义、符号与单位、时态语态）；
  按大纲章节顺序一节一节写，每写完一节在 `manuscript/section-status.md` 记这节要点、新定义的术语与缩写、用到的关键数，写下一节前先读；
  **引言、结论与展望、摘要最后写**（它们给全文定调，各节写完才写得准）。
- **综述初稿声明分路**（`StepFanOutDto`，开工弹层「分几路同时跑」，默认不勾、人勾了才分）：大纲一步多交 `manuscript/sections.json`
  （正文各节：id、标题；不含引言与结论）。每路只写自己那几节到 `manuscript/sections/<序号>-<短标题>.md`，读完整大纲、写作规范、相邻节要点，
  不写引言 / 结论 / 摘要，不改写作规范（要加术语写进本路文件末尾「建议加进规范」）；收尾一路统稿：合成 `manuscript/draft.md`，写引言、结论与展望、摘要，
  补过渡、删重复，缩写全文首次定义，术语按规范统一，同一篇文献在各节引的数一致（有抽取表时对照它），图表编号与交叉引用，再照常渲染。
- 论文初稿（IMRaD，各节相互依赖、篇幅不长）与学位论文初稿（各章在前面几步已分别写好，这一步本就是统稿）不声明分路。

## 2. 投稿前更新检索（§8-2）

定稿类步骤（`step-kind.ts` 的 final：润色与定稿、润色与投稿准备、格式与定稿；期刊格式适配也算）**还没开工或刚开工**、且同一流程里检索那一步
上次保存已超过 14 天时，步骤卡「AI 干活」行多一句「检索截止 MM-DD（N 天前）：投稿前更新一次检索」+ 按钮 **更新检索…**——
打开退回补料单，退回到检索那一步，主题预填「更新检索：MM-DD 以来新发表的文献（按 screening.md 检索日志里的原检索式）」、为什么预填
「投稿前更新检索，避免漏掉最近发表的工作」，补料链照常列出精读、大纲、初稿（默认勾，实验类默认不勾）。不另造机制；按钮只是入口。

## 3. 文献数据抽取表（§8-3）

- 综述、科研论文、毕业论文模板的精读步：项目规则里有「文献数据抽取：列……」时，精读 / 速读每篇往 `notes/extraction.md` 填一行或几行
  （一个样品 / 条件一行），列按规则写的列，**末两列固定为「来源 [@键]」「页码 / 图表」**；查不到写「—」，不估。
- 规则里没写列时：精读开工先按课题提议 6–10 列（含单位与测试条件），写一条人工请求问用户（属「范围」），用户答了才填；不需要就答「不需要」。
- 综述大纲的表计划、初稿的对照表优先从抽取表取数；统稿时同一篇文献的数和抽取表对不上的列进待核实。
- 资料全貌精读那一行加「抽取表 N 行」。

## 4. 导师 / 合作者意见回流（§8-4）

- 写作类、定稿类步骤（`step-kind` writing / final）的步骤卡上有 **导入 Word 批注…**：选一个 .docx，Mesa（后端，不经 AI）抽出批注——
  批注人、时间、批注文字、被批注的原文片段——写成 `manuscript/comments/<日期>-<文件名>.md` 的意见清单表：
  `| 编号 | 批注人 | 原文 | 意见 | 类别 | 去向 | 处理 |`，类别、去向、处理留空。同名清单已存在时追加序号，不覆盖。
- 导入后接着在这一步开一轮（走开一轮的共同编排）：AI 逐条填「类别」（改文字 / 补分析 / 补文献 / 改结构 / 要讨论）与「去向」
  （本步，或「退回：步骤名」），本步能改的就改并在「处理」写改在哪；要退回的不自己改上游，「要讨论」的写进人工请求。
- 清单里有「退回：步骤名」的行时，这一步的「退回上一步补料 / 修改…」按清单预填（同大纲覆盖检查预填，一个去向一份）。
- 意见回流也可经项目助手说「把导师批注过一遍」，它只给跳到这一步的按钮（导入要人选文件）。

## 5. 实验室实验模式（§8-5）

- 科研工具多一项 **实验方式**：计算实验（默认，现状）/ 实验室实验。问在实验类步骤（交 `results/run-manifest.json` 的步骤）开工前，同「稿件载体」是开工前提。
- 选实验室实验时，实验执行一步的合同追加一节（工具合同块，可撤回）：实验由人在实验室做——
  ① 按 design.md 写 `experiments/protocol.md`（每组条件的操作步骤、样品编号规则、测试项目与仪器参数、重复次数、对照）与实验记录模板；
  ② 写 `processing/rules.md`：仪器数据的标准处理（例如 iR 补偿方式与比例、按几何面积或电化学活性面积归一化、取值点、拟合区间、参比换算），
     每条注明依据，人批准前不用于正式结果；
  ③ 写一条人工请求：请人按 protocol 做实验，把仪器导出文件按样品号放进项目 `data/raw/<样品号>/`（原始文件不改名不改内容），做完点「继续」；
  ④ 数据到了：每个原始文件登记进 `results/run-manifest.json`（样品号、条件、仪器、日期、hash），按 rules.md 用 `experiments/reproduce.py`
     从原始文件处理出结果；`results/matrix.json` 每组标 done / failed / not-run，缺数据的不补造；`results/implementation-check.md` 记数据质控
     （重复性、对照、异常曲线与处理）；`results/summary.md` 每组一行主指标与原始文件路径。**不编造、不补全任何测量值。**
- 下游结果分析不变（输入文件名一致）；回头时 `ROUND_CLAUSE.experiment` 照旧（只重跑受影响的，实验室模式下是「只重处理 / 请人补测受影响的组」）。

## 6. 各模板小项（§8-6）

| 模板 | 改什么 |
|---|---|
| 投稿材料、综述定稿 | 目标期刊要图形摘要（TOC 图）时按 schematic-forge 出一张，交 PPTX + SVG；不要时写明不需要 |
| 期刊格式适配 | 目标期刊没定时先给 2–3 个候选（范围、影响因子 / 分区、审稿周期、版面费，依据写出处），写一条人工请求让人选，不替人定 |
| 数据处理·分析报告 | 报告分「探索发现」与「确证结论」两节：只有事先在 eda-report 标「待确证」、并在留出或新数据上按事先写好的计划检验过的，才进确证结论；否则一律是探索发现 |
| 毕业论文 | 研究方法、实验、结果分析支持几项研究：design.md 按「研究 1 / 2 / 3」分节，矩阵 id 带研究前缀（S1-…），结果章每项研究一节。**不复制步骤**（落地与建议不同：复制三遍步骤会让合同、回头、资料全貌都翻倍，按研究分组在同一条链里更稳） |
| 投稿与返修 | 模板说明写明：论文在 Mesa 里写的，在原项目里「＋ 从模板追加」——返修要补分析时能直接退回结果分析 |
| LaTeX 论文 | 改名「LaTeX 排版（已有稿件）」，说明写明：新写论文用「科研论文 / 毕业论文」并把稿件载体选 LaTeX，这一套只给已有稿件排版用。模板 id 不变 |

## 7. 不做

- 不自动分路写初稿（分路只在开工弹层由人勾）；引言、结论不分出去。
- 不让 AI 自动判断意见该不该采纳——AI 只分类、改本步能改的，要讨论的交人。
- 实验室模式不让 AI 生成或补全任何测量值；不接仪器软件。
- 不为每个场景新加模板；变化进选项与合同。

## 8. 落地顺序（一项一个提交，文档同提交）

1. 初稿写法（顺序写 + 写作规范 + 综述分路 + 大纲交 sections.json）
2. 投稿前更新检索
3. 文献数据抽取表
4. 导师 / 合作者意见回流
5. 实验室实验模式
6. 各模板小项

## 9. 验收

各项落地后：内置模板每步任务书预览核对新增段落；按「动真实数据先干跑」，意见回流的导入在一份带批注的真实 docx 上跑通（只读源文件、清单落项目）；
实验室模式在一个测试项目上切换、撤回各一次，合同块前后一致；HER 项目走到初稿时用一次分路与统稿（人勾）。
