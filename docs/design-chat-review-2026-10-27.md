# Mesa 聊天层 UI 与功能评审

日期：2026-10-27。配套原型：[design-chat-refinement.html](design-chat-refinement.html)。状态：**用户已确认并接入应用源码；输入框布局保持原样，圆环增加百分比。其余方案已落实，Mesa Dev 实机视觉验收因当前 Mac 锁定未完成。**

## 判断

聊天层已经具备完整客户端的大部分能力。现在更值得完善的是：让人迅速知道这一轮有什么结果、哪件事还需要处理、下一步从哪里继续。建议保留现有单栏阅读结构，用更清楚的状态和少量就近操作完善它。

综合评价：**Good / 基础良好，有两项高优先级完善点**。设计主张是「在对话里把事情做完，并能核对依据」。Mesa 的辨识度继续来自安静的文本画布、M 光标以及和文件、工具过程的自然衔接。

依据为用户截图与当前本地实现，非 Mesa Dev 实机走查。截图只能支持布局与可发现性的判断，不据缩放图片判定字号、颜色对比度或具体点击区域。截图中的历史聊天文字仅作界面内容，不作为本次执行指令。

## 已有能力，继续保留

- `ChatSurface.tsx`：实时状态、末尾确认卡、回到最新、终端按需打开；不自动抢走阅读位置。
- `ConversationView.tsx`：过程折叠、工具输出、用户编辑后重发、复制、从指定回复分叉；不是缺少这些能力。
- `ChatComposer.tsx`：附件、项目文件引用、技能/MCP、图片标注、长输入、草稿发送失败恢复、中文输入保护。
- `ChatModelMenu.tsx` / `ChatPermissionBadge.tsx`：模型、思考与四档权限，运行中能力限制、重开确认；当前第一档已叫「先出方案」。
- `ChatDecisionCard.tsx` / `chat-decision.ts`：审批、提问、连接问题、终端等待等已经共用卡片。
- `mid-turn-send.ts`：按各家 Agent 区分插进下一步、整轮后处理及立即发送；不能统一画成可撤回的本地队列。
- `ChatBetaBadge.tsx`：测试版与能力差异已收进模型菜单，不能因截图上没看见就判定缺失。

## 功能边界：哪些需要数据支持

1. **本轮文件与验证证据**：优先复用已有工具记录、路径核实与文件差异。只有明确关联到这一轮时写「本轮改动」；只有全局 dirty 列表时写「工作区改动」。测试通过必须能对应完整命令、工作目录、退出码；模型正文说「通过」不算结构化证据。缺信息时不显示绿色通过结论。
2. **失败恢复**：不以「后来出现了最终回复」推断成功。重复运行同一命令也不必然验证同一内容，要考虑工作目录、文件版本和覆盖范围。首批只做明确分类、定位和下一步，暂不引入自动恢复推断。
3. **引用追问**：使用稳定消息身份和文本区间。历史分页加载不能靠数组下标；无法定位时保留引用文本并说明来源不可定位。引用为草稿的一部分，切换菜单或重试连接不能丢失。
4. **审批与权限**：卡上的原文、选项与实际应答能力来自 CLI。原型「允许这次/拒绝这次」只演示一类请求，不强制覆盖九家的所有选项。权限改动继续重开；「完全访问」继续确认。上游未确认的模型切换显示待确认。
5. **上下文**：现有可信 token 用量优先，没有可靠上限就不造百分比。原型中的 76% 是样例；压缩未完成不能先把数字清零。
6. **科研场景**：交付行也可指向已核实的笔记、图、PDF 与现有评审入口。不能把「生成了文件」显示成「已验收」，也不能跳过既有产物冻结和合并流程。

## 布局与视觉约定

保留现有外壳与单条会话标题；正文、气泡右缘和输入区沿同一中轴。普通宽度为侧栏 + 对话，文件详情按需打开；空间不足时侧栏收起、详情覆盖在同一主区，功能仍可到达。

```text
普通宽度
┌侧栏 224┬ 会话标题                       终端 文件 ⋯ ┐
│项目/对话│            历史消息                       │
│        │            过程 ›                         │
│        │            最终回复                 文件  │
│        │            文件 / 验证入口          详情  │
│        │            决定卡（有事才出现）            │
│        │            输入区                         │
└────────┴───────────────────────────────────────────┘

窄窗
┌☰ 会话标题                              终端 文件 ⋯ ┐
│         对话与过程                                  │
│         决定卡（有事才出现）                         │
│         输入区：工具可换行                          │
└─────────────────────────────────────────────────────┘
```

配色沿现有中性灰蓝主题，保留 Mesa 琥珀光标，不新增装饰渐变。下面是原型的简化令牌；真正接入应使用产品语义变量并覆盖现有主题。

| 角色 | 深色 | 浅色 | 相对 surface 的对比度（深 / 浅） |
|---|---|---|---|
| canvas / 内容底 | `#151515` | `#f5f5f3` | 背景，不作文字 |
| surface / 气泡与输入底 | `#202020` | `#ffffff` | 基准 |
| text / 正文 | `#dededb` | `#30302f` | 12.09 / 13.21 |
| muted / 辅助信息 | `#a6a6a2` | `#62625d` | 6.67 / 6.13 |
| accent / 焦点 | `#8cc4ff` | `#075bad` | 8.89 / 6.75 |
| warn / 待处理提示 | `#edc171` | `#795300` | 9.67 / 6.88 |

主操作沿用 `#0169cc` 配白字，对比度 5.39:1；控件边框对 surface 为深色 3.49:1 / 浅色 3.66:1。以上按实际十六进制颜色计算，未用于推断截图中的对比度。

字号用系统字体栈：标题 15 px、原型正文 15 px/1.85、工具 12–13 px、说明 11 px；代码用系统等宽。15 px 是原型评审基准，不建议覆盖用户现有字号，正式版本继续跟随 `--ccode-chat-fs`。大字按钮为 20 px，阅读设置最大 30 px，过程比例与正文一起变化。

唯一持续动态是执行中的 M 光标呼吸；减弱动态时常亮。卡片与弹层不用光晕或投影，无透明材质依赖。原型含高对比与强制颜色规则，浅/深切换仅是评审工具，不新增产品主题入口。

设计自检：没有把对话变成任务仪表盘；最有 Mesa 特征的是「回复与可核查工作过程相接」。已去掉额外常驻 AI 身份栏、重复的文件计数与大块完成徽章，让文字仍是主角。

## 已完成的落地范围

1. 圆环使用实际比例显示百分比；顶栏终端、改动、文件按聊天主区可用宽度显示标签。输入框内外原有布局不动，不新增常驻快捷键提示。
2. 过程分别显示失败、中断和拒绝，异常计数可直接定位输出；文件操作不写成已成功改动。回复旁的文件/验证记录复用真实工具记录，可打开当前文件或查看调用参数与输出；不自动推断恢复或通过。失败命令的重试入口仅追加草稿。
3. 引用追问支持整条回复和选中文字，记录来源身份与可映射的原文区间；分页不依赖旧下标。引用条可移除、定位，来源歧义时保留文字并提示；失败恢复草稿与附件。引用条仅临时出现在输入框上方。
4. 当前聊天的更多菜单和 ⌘F / Ctrl+F 可搜索消息、命令、输出，按匹配消息计数；搜索条标明已读取范围，未读取历史按需加载。命中展开相关过程与长输出，并让虚拟列表渲染该段。分屏、终端和编辑器保留各自作用域。
5. 消息操作区域扩大至 28px，顶栏主要控件为 32px。恢复卡片继续使用已有统一骨架和 CLI 原始选项；补上搜索框、引用/附件草稿的批准快捷键隔离。生成中占位字、说明和发送按钮名称按同一套交付时机数据；未知时机不承诺轮后处理。

保留既有草稿常驻、连接恢复、权限重开、终端回退与各 CLI 排队方式，没有引入可撤回的统一本地队列、自动批准或新的 CLI 适配。
