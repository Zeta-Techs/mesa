## 1. 定位

用户的话：「其实就是在不同的 Agent CLI 外面做一层聊天层，这个聊天层就像 Codex 和 Claude 客户端那样，可以切换模型、思考强度、访问权限，添加一些操作。」

所以聊天层是**一个客户端**，不是终端的附属视图。用户在这里完成一段对话的全部日常动作：选谁来做、用哪个模型、想多深、放多大权、给它材料、看它干活、回答它的问题、换模型、压缩上下文、开新对话。终端退到「出了聊天层处理不了的情况才打开」的位置。

和 ChatGPT 们的根本差别：我们底下是九个各不相同的 CLI，不是一个自家服务。由此定三条原则：

1. **一个控件对应一个已核实的 CLI 机制。** 没有核实过的不放；这家做不到的，控件在、但置灰并写原因（「Cursor 没有这一档」）。不做假按钮，不做「点了没反应」。
2. **终端是事实来源。** 当前模型、思考档、权限、是否在等确认，都以 CLI 自己画出来或写进会话文件的为准；聊天层显示 Mesa 以为的状态时必须标明（「待确认」）。
3. **同一件事只放一处。** 模型 / 思考 / 权限只在输入框里；底部状态栏只放身份、目录、git、时长与 token（不写美元花费，2026-10-23）；顶部不加头部（标题归标签条）。

## 2. 现在的样子与问题（2026-10-17 走查）

已经有的：输入框左下目录芯片与权限标记，右下「模型 · 思考」芯片，「+」插技能 / MCP，斜杠命令面板，对话流（用户气泡、助手 Markdown、思考与工具折叠、命令行），实时预览（仅 Claude），信任 / 切换确认 / 审批三种横条，卡住时露出终端。

问题按严重排：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 权限五档（按本机设置 / 只讨论 / 先问再改 / 自动改文件 / 完全访问）。「自动改文件」与「先问再改」是同一条轴上的细分，「按本机设置」又不是一档，而是说明当前状态 | 用户要读五段说明才能选；和 ChatGPT「请求批准 / 帮我批准 / 完全访问」三档的心智对不上 |
| 2 | 各家都有的「AI 自己判断哪些安全」模式没有用上：Claude `auto`、Codex `--approve-for-me`、Qwen `auto`、Cursor `--auto-review`、Kimi `--yolo`、CodeBuddy / Grok `auto` | 用户最常想要的那一档（ChatGPT 的「帮我批准」）缺席 |
| 3 | 开聊前的选择器是四栏宽弹层（Agent / 配置 / 模型 / 思考），开聊后变成另一个窄菜单 | 同一位置两种长相，用户要学两次 |
| 4 | 信任、切换确认、审批三种「等你决定」都做成对话流**上方**的横条 | 眼睛要从底部输入框跳到顶部；和 Claude / Codex 客户端「确认卡出现在对话末尾、贴着输入框」的习惯相反 |
| 5 | 「+」只能插技能 / MCP；加文件、加图片只能拖进来或粘贴，没有入口 | 用户不知道能给 AI 文件 |
| 6 | 新对话、压缩上下文、分叉、导出、看改动这类「对话操作」散在终端启动行的 ⋯、标签菜单里，聊天层里找不到 | 聊天层不是一个完整客户端 |
| 7 | 斜杠命令表的键写成 `claude`，Claude Code 的 agent id 是 `claude-code`，Claude 用户的斜杠面板只剩 `/help` | 已修（本轮） |
| 8 | 完全访问启动时 Claude Code 会先弹「Bypass Permissions mode」警告，默认高亮在 No，聊天层没有按钮 | 聊天卡在「已送出」；已修为启动后 20 秒内识别确认菜单（本轮） |
| 9 | 消息上没有操作：不能复制一条回答、不能把上一句拿回来改了重发、不能从某一条开新分支 | 客户端基本功缺失 |
| 10 | 看不到上下文用了多少，什么时候该压缩全靠 CLI 自己提示 | 长对话突然变慢 / 被自动压缩，用户不知道为什么 |

## 3. 信息架构

从上到下只有三层，和 ChatGPT / Codex 客户端一致：

```
┌ 标签条：标题（会话名） · 分屏 / 右栏按钮 ─────────────────────────┐
│                                                                    │
│  对话流（居中一栏，max 4xl）                                         │
│    用户气泡 · 助手正文 · 思考折叠 · 工具折叠 · 命令行 · 实时预览       │
│    等你决定的卡片（信任 / 切换确认 / 审批）← 贴在对话流最末尾         │
│                                                                    │
│ ┌ 输入框 ──────────────────────────────────────────────────────┐   │
│ │ 输入区（附件缩略图在上方一行）                                 │   │
│ │ [+] [目录*] [权限]                     [上下文○] [模型·思考] [发送] │
│ └──────────────────────────────────────────────────────────────┘   │
│  底部状态栏：● Claude Code · GLM-flash  ▸目录  git  1:01  75k↑ $0.01 │
└────────────────────────────────────────────────────────────────────┘
* 目录芯片只在开聊前出现
```

输入框底栏左边是「给什么、在哪、放多大权」，右边是「谁来想、想多深、发出去」。这条分界与 ChatGPT 截图一致（左「+ 完全访问」，右「模型 高 ↑」）。

## 4. 输入框

### 4.1 「+」添加

一个菜单，四项，图标 + 一行字：

| 项 | 做什么 | 实现 |
|---|---|---|
| 文件或图片 | 系统选择器选文件；图片走现有粘贴图片通道 | 选中后作为附件缩略图显示在输入区上方，发送时把路径拼进正文（与现在拖入同口径）。2026-10-23：选来的图片也读缩略图；点缩略图在输入框上方展开看图标注台（见 §4.7）；「编辑后重发」把消息里整行的图片路径还原成缩略卡（`ComposerSeed`），发出去仍是正文 + 一行一个路径。同日（用户对照 ChatGPT）：拖进聊天面板的文件也成附件卡（原先是把转义后的路径插进正文），拖着悬停时面板盖一层虚线框「松开，添加到消息里」；非图片附件统一成文件卡（左首页预览 / 类型色块，右文件名 + 类型字）：PDF 由 pdf.js 画第一页（`pdf-thumb.ts`），Word（docx）经 mammoth、表格（xlsx/xls/ods）取前几行排进一张纸，用 SVG foreignObject 包成图片地址（`doc-thumb.ts` / `docx-thumb.ts`；2026-10-23 在真 WKWebView 里核过中文、表格、内嵌图都能画），PPT / 旧版 doc / csv 画类型色块；选择器改在 Rust 侧弹（`pick_attachment_files`），拖进 / 选中的文件登记进读取白名单（`attach_grants.rs`），项目外的图片与 PDF 也出缩略图 |
| 引用项目文件 | 弹搜索框，模糊找当前目录下的文件，回车插入 `@路径` | 复用文件树索引；各家都认路径文本 |
| 技能 › | 二级菜单，同现有 | 不变 |
| MCP › | 二级菜单，同现有 | 不变 |

输入框里打 `@` 也直接弹「引用项目文件」，和 Claude / Codex 客户端一致。

### 4.2 权限：四档，照 ChatGPT 的样子

菜单标题「AI 动手前怎么问你？」（原右上「了解更多」2026-10-18 用户要求去掉）。每项：左图标、标题、一行说明，当前项右侧打勾：

| 档 | 图标 | 说明 | 本质 |
|---|---|---|---|
| 只讨论 | 眼睛 | 只看、只说，不改文件、不跑命令 | 各家只读 / 计划模式 |
| 请求批准 | 手掌 | 改文件、跑命令前都先问你 | 各家「默认 / manual」 |
| 帮我批准 | 盾牌 + 勾 | 日常操作自动放行，有风险才问你 | 各家 AI 判断模式（classifier / auto-review） |
| 完全访问 | 盾牌 + 叹号，**只图标用琥珀色**（2026-10-21：整行染黄太刺，文字保持 l1 / l3） | 改文件、跑命令都不再问你 | bypass / yolo |

和现在的差别：

- **去掉「自动改文件」**：它只是「请求批准」的变体（Claude acceptEdits），用户分不清它和「帮我批准」。
- **去掉「按本机设置」这一项**：没手动选过时，打勾的是**本机设置对应的那一档**，标题后跟一个小灰字「本机设置」。例：本机 Claude 设了 bypassPermissions → 「完全访问 · 本机设置」打勾、徽标橙色。用户点任何一档 = 这次用参数覆盖。本机设置认不出对应哪档时，徽标写「默认权限」，四档都不打勾。
- **完全访问**：二次确认不变（已有）；Claude Code 启动时自己还会弹一次英文警告，聊天层把它显示成确认卡，按钮照原文（「No, exit / Yes, I accept」），不替用户选。
- 这家没有的档：置灰，说明换成「Cursor 没有这一档」。
- 运行中换档：确认框写「会停下 AI，再带着新权限接回这段对话」（已实现）；生成中只显示不可点。

徽标文字 = 当前档名；完全访问整颗橙色；只讨论用眼睛图标；其余灰色。

### 4.3 模型 · 思考：开聊前后同一个菜单

一个单栏菜单，三段，开聊前后长相相同，只是可改的东西不同：

```
┌───────────────────────────────┐
│ Claude Code · GLM-flash     › │  ← 开聊前可点，进二级菜单选 Agent / 配置；开聊后只显示
├───────────────────────────────┤
│ 模型                          │
│ ✓ glm-5.3-flash   200K · 思考 │  ← 每行右侧一行灰字：上下文窗口 · 思考 · 看图（来自模型能力库）
│   glm-5.2         128K · 思考 │
│   其他模型…（输入回车）        │
├───────────────────────────────┤
│ 思考强度                      │
│ [ low | medium | high | max ] │  ← 分段控件一行排开，当前档实心
├───────────────────────────────┤
│ 灰字说明（只在需要时出现）     │  ← 如「Claude Code 会把这次的选择存成它新对话的默认」
└───────────────────────────────┘
```

- 开聊前选的是启动参数；开聊后点 = 写切换命令进终端，CLI 要确认时对话末尾出确认卡；未读回前芯片斜体 +「待确认」（已实现）。
  2026-10-18 修订：切换命令会写回 CLI 全局配置的家（Claude、Codex、Grok 的模型，Claude、Codex、Qwen、Kimi 的思考档）改为停下再带新参数
  接回原对话，不写配置（`switch-strategy.ts`）；菜单底部写明是哪种换法，生成中不让换。
- 思考强度用分段控件而不是列表：档位是一条刻度，横排一眼看出「在哪一格」，也省高度（Codex 客户端同做法）。
  2026-10-17 改成滑块（Grok 八档时分段每格只剩一个字母）；2026-10-18 审美一轮：模型行与权限菜单同一套（名字下一行能力灰字、
  行尾勾、不铺底），档 ≤6 时每个刻度下写档名，底部说明压到一两行。
- 这家中途不能换模型 / 思考的：那一段只读，写「这家中途不能换，新开一段对话时在这里选」。
- AI 停了还能接着聊：菜单标题改「接着聊用」，选的是下次启动参数（已实现）。

### 4.4 上下文用量

模型芯片左边一个 14px 圆环，表示上一轮输入占模型上下文窗口的比例；悬停写「已用 63%（12.6 万 / 20 万）」。超过 80% 圆环变橙。数据：上一条助手消息的 input + cache 用量（会话文件里有）÷ 模型能力库的 context。读不到窗口大小就不显示圆环。

**点开是上下文浮层（2026-10-20，用户要 Claude 客户端那样的面板，按推荐做）**：标题行已用 / 窗口；横条按分类上色——对话 / MCP 工具 / 内置工具 / 系统提示四大类各一色、小类同灰、剩余是底色，顺序固定不按大小排（同日用户看过三段灰的版本后改要每类一色；配色见 `context-breakdown.ts` SERIES，改色先用 dataviz 校验器重验），≥80% 只让标题数字变橙，竖线标自动压缩点；列表逐类列 token 与占比；底部「离自动压缩还有 X」+「压缩上下文」（斜杠面板 Mesa 组同一个动作，这家有压缩命令且在运行时才给）。分类来自 CLI 自己的 `/context`，Mesa 用标签同一套启动参数在后台跑一次（`context_breakdown.rs`）：Claude Code `-p "/context" --resume <id> --no-session-persistence`（关 hooks）、Qwen Code `-p "/context" --resume <id>`，2026-10-20 实测拿 2.8MB 真实对话副本跑，对话文件一字节未变、不调用模型。CodeBuddy 有 `/context` 但无头模式把它当普通提问发给模型；其余家没有这类命令——浮层只有已用 / 剩余。点开才读、同一轮缓存；数字标「估算」。

### 4.5 发送、排队、停止

- 发送钮右下角，生成中变停止钮（已有）。
- 生成中仍可打字回车：消息进入**排队**（CLI 本身会缓冲），对话流末尾显示排队气泡，气泡下一行灰字「排队中 · 这一轮结束后处理」；生成中输入框占位字也写明会排队。
  - 2026-10-18 落地口径：Mesa 不另设队列——发出即写进终端，由 CLI 自己排队，所以**没有撤回钮**（「还没写进终端才能撤」的情形不存在）；要撤回去终端里删。排队气泡一律接在对话末尾（`placePendingUsers`），不随新回复插到前面。
  - 2026-10-22 与终端联动（用户：「排队以及立即发送这一块需要和终端联动」）：各家收到这句后的处理不同，按逐家实测写成表（`mid-turn-send.ts`，
    依据 matrix §14「生成中再发一句」）。气泡下一行照实写：Claude / Codex / CodeBuddy / Qwen / OpenCode「下一步时交给它」（做完手头这一步就看到，
    插进这一轮），Gemini / Kimi / Grok「排队中 · 这一轮结束后处理」。能让它马上处理的家，最后一条排着的气泡旁给一个钮：
    Claude / Codex / CodeBuddy / Gemini「立即发送」= Esc（打断手头这一步并马上发），Grok「立即发送」= 再按一次回车（不打断），
    Kimi「插进这一轮」= Ctrl+S；Qwen / OpenCode / Cursor 不给。
    Claude 插进这一轮的话记在会话文件的 `attachment/queued_command`，解析补上后聊天层与回放里才看得到（原先这句会消失）。
    停止钮（Esc）在前四家也会让排着的那句马上发出，停止块悬停说明写明（`stopTitle`）。输入框发送区停止块旁那组字同口径（`queueSendHint`）。
- 输入框为空时按 ↑：取回上一条自己发的话进入编辑（与终端历史一致）。

### 4.6 从终端送进来的文字（2026-10-18，与终端会话对接）

终端选中文字的「引用 / 问 AI」（终端那边做）统一走 `TerminalView` 的 `onConversationInsert(tabId, text, {send})`，父级按这个标签**此刻**在哪一层分派：

- 聊天层：`send=false` 填进聊天输入框（接在已有草稿后面）；`send=true` 直接按聊天发送走（乐观气泡、排队规则都一样）。
- 终端层：`send=false` 用 bracketed paste 写进 TUI 输入行（多行不会被当成回车）；`send=true` 走标签的 `sendMessage`。

### 4.7 看图与标注（2026-10-23）

用户：「点图片只能放大，并不能看着编辑消息」，要 ChatGPT 那种点图标注。定下：

- **不挡输入框**：点附件缩略图，`ChatImageStage` 在输入框上方展开、盖住对话区（`absolute bottom-full`，高度 = 输入框上沿到聊天面板顶，每次渲染量 + ResizeObserver），输入框照常能写；再点同一张 / × / Esc 收起。不用 Modal。开聊前的居中空态下输入框上方只剩一小块，标注台开着时 `ChatSurface` 改用开聊后的布局（输入框沉底、起手提示收起，`onImageStageChange`），收起再回居中（同日用户：图太小了）。
- **工具五样**：意见框（带编号）、画笔、箭头、打码（实心中灰块，不做可还原的马赛克）、裁剪（只留最后一个）；撤销 / 清空不动输入框里的字。不选工具 = 只看。
- **意见写在消息里**：画好意见框，输入框末尾另起一行写圈码 ①，光标停在后面接着写——不另设评论框。一条消息几张图连着编号，撤销掉的号不回收（`nextMarkNumber` + 计数器，发送后归零）。
- **原图不动，发送时才出图**：标注只存原图像素坐标（附件的 `markup`），发送时 `exportMarkup` 按同一套几何（`image-markup.ts`，预览 SVG 与导出 canvas 共用）画进新图，落盘到粘贴区，发出去的是新图路径；格式跟原图（jpg 仍 jpg，其余 png）。后端与九家 CLI 不用改：收到的还是一行图片路径，看不看得懂取决于模型能否看图（已有黄色提示）。
- ~~**不做**：移除背景、擦除~~（2026-10-25 改：出图模型已接上，见下一条与 architecture §10 同日条目）。
- **接着改对话里的图（2026-10-25）**：聊天层点对话中的图 = 放进输入框并直接展开标注台（`ChatImageEditContext`，只读视图仍是预览）。改图口径：提示「发出去由 AI 用出图模型在原图上改」、占位字「描述修改内容」、工具条后「移除背景 / 调整画幅」两个常用说法（写进输入框、不直接发）；图写成「原图：路径」一行，标过的另加「标注图：路径」（不写成单独一行的路径：Claude Code 会把它升级成图片附件，看不了图的模型就报错；九家实测见 matrix §11 末条）。没标过的改图不触发「看不了图」提示，标过的提示换成「标注它看不到」。真擦除（按蒙版重画）不做。
- 已发出的图在对话里点：聊天层里进标注台接着改（上一条）；会话浏览等只读视图有工作目录开右栏文件预览，随手聊弹 `ChatImageViewer` 看大图。

## 5. 对话流

| 元素 | 规则 |
|---|---|
| 用户气泡 | 右对齐、大圆角；悬停在气泡下面靠右出「复制」「编辑后重发」（= 文本放回输入框，不自动发；2026-10-25 起浮着不占高度）。超过约 12 行收起渐隐 +「展开全部」；新问题前留大空（2026-10-21） |
| 助手正文 | 左侧全宽 Markdown，不截断（公式、表格横滚壳与数字列、代码高亮、`[@key]` 引用胶囊、核实过的文件路径就地可点，2026-10-21，见 §9）；悬停在段末出「复制」「从这里分叉」（复用现有分叉：新标签带简报开新对话；2026-10-18 起简报只截到这条回复为止——`build_handoff_brief` 的 `until_text` 按正文认这条，不按下标，因为聊天层只载入了尾部几页；认不出就报错，不悄悄给全文） |
| 思考 | 默认收起一行「思考过程」，点开看全文 |
| 工具 | 连续工具合并成一行「执行记录 · 3 次（Read、Bash）」，点开逐条；改文件的那条带「看改动」直达右栏 diff |
| 命令行 | `/model`、`!ls` 等：一行灰字「命令 + 结果」（已实现） |
| 实时预览 | 生成中，终端已出、会话文件未落盘的段落以浅一级字色接在末尾，追上后让位（2026-10-18 起 Claude / Codex / Qwen / Gemini / Grok / Kimi 六家；CodeBuddy、OpenCode 屏上读不出，仍给「看实时输出」） |
| 等你决定的卡片 | **贴在对话流最末尾**（不是顶部横条）：标题一句、说明灰字、选项按钮、右侧「打开终端」。四种来源同一张卡，同一时刻只出一张，优先级：工具审批 > 启动时的目录信任 > 连接出问题（2026-10-18，额度 / 限流 / 钥匙 / 服务 / 模型，`src/chat-decision.ts`；同家其他连接各一个按钮「换到 X，接着这段对话」最多三条，没有时「去添加连接」，另有「先不换」）> 切换 / 启动警告的确认菜单 |
| 错误与系统提示 | 居中一行灰字：AI 退出、重开换权限、压缩完成等 |

等你决定的卡片出现时，输入框占位字改成「先在上面选一项，或者直接回复」，发送钮仍可用（有的 CLI 允许在确认时打字）。

## 6. 对话操作

两个入口，内容一致：

1. **斜杠面板分组**：打 `/` 弹出，上半组「Mesa」——新对话、压缩上下文、分叉到新标签、导出 Markdown、查看改动、打开终端；下半组「Claude Code 命令」——这家 CLI 的已核实命令（`src/slash-commands.ts`）。Mesa 组由 Mesa 执行，CLI 组原样写进终端。
2. **标签条 ⋯**：同一份 Mesa 操作，给不习惯斜杠的人。2026-10-18 落地在聊天层活动标签的标签名右侧（挨着 ✦），终端层不显示——终端层的操作在启动行 ⋯。

「压缩上下文」只在这家有命令时出现（Claude / Codex `/compact`，Gemini / Qwen `/compress` 待核实）；「新对话」= 当前目录新开标签，不清旧对话。

## 9. 视觉规格

- 输入框：圆角 `rounded-xl`，底 `bg-raised`，1px `border-field`；底栏高 40px，芯片高 24px、字号 micro、灰调 `text-l3`，悬停 `bg-hover`。
- 菜单：`ccode-float-surface`，宽 18–20rem，行高 28–44px（带说明的两行项 44px），分段控件高 28px；分组之间 1px `border-hairline`。
- 颜色只表达一件事：橙（warn）= 风险（完全访问、上下文将满）；蓝只给状态点；其余全部灰阶。例外：上下文浮层的分类横条按分类上色（2026-10-20 用户要）。
- 图标统一 lucide 1.8 线宽、12–14px：眼睛 / 手掌 / ShieldCheck / ShieldAlert / Paperclip / AtSign / Sparkles / Plug / SquareTerminal。
- 动效：菜单 120ms 淡入；实时预览不做打字机动画（终端本来就是逐行到）。
- 正文排版（2026-10-21，对照 Claude / Codex 客户端）：聊天字号阶梯（回答 1 / 过程 0.94 / 过程里的代码 0.86，全随「聊天字号」）、栏宽 = 字号 × 52
  （回答一行约 52 字）、新问题前 1.75rem、做完的一轮里中途说明降一级、中文排版（自动中西间距、段末不留孤字、句读不落行首）。
  规格与类名见 `docs/conventions/design-system.md`「聊天正文排版」。例外色：代码高亮与引用胶囊（bib 里没有的键描琥珀圈）。

## 10. 分期

**第一期：把三个芯片做成客户端的样子**（约 2 天）
- 权限四档 + 「本机设置」标记 + 「了解更多」，接入各家「帮我批准」参数（矩阵 △ 项先按帮助说明接）。
- 模型 · 思考合成一个单栏菜单（Agent / 配置二级、模型带能力灰字、思考分段控件），开聊前后同形。
- 三种「等你决定」横条合成一张末尾确认卡。
- 已顺手修：斜杠表 `claude-code` 键、完全访问启动警告、菜单按键提示行。

**第二期：操作与消息**（约 2 天；2026-10-18 已实现）
- 「+」菜单四项 + `@` 引用项目文件。
- 斜杠面板「Mesa」组 + 标签条 ⋯。
- 消息悬停操作（复制 / 编辑后重发 / 从这里分叉），排队气泡与撤回，↑ 取回上一句。
- 上下文用量圆环。

**第三期：九家逐个打通**（按使用频率：Codex → Qwen → Kimi → Gemini → 其余；2026-10-18 已做，结论见 §7）
- 每家用假 API 抓屏：确认菜单形态、实时预览、模型读回、帮我批准的真实行为；把矩阵的 △ 改成 ✓ 或 ✗。
- 落地：审批菜单在聊天层按原文给按钮（这一轮没结束前一直扫屏，`tui-menu.ts` 认七家形态）；实时预览按每家画面布局读
  （`live-reply.ts`）；Gemini / Codex 模型读回、Qwen 底栏思考档读回；Codex「帮我批准」启动参数修正；Kimi 接口连接不再
  给运行中换模型。样本进 `tests/tui-menu.test.ts`、`tests/live-reply.test.ts`、`tests/reasoning-effort.test.ts`。

验收：每期结束用户在 Mesa Dev 窗口按核对清单点一遍；每家的抓屏样本进测试。

## 11. 不做的

- 不在聊天层里复刻 CLI 的全部斜杠命令；只放已核实、对聊天有意义的。
- 不做「重新生成这一条」：九家没有统一的撤回一轮机制，分叉替代。
- 不在进程里偷切权限（Claude 的 shift+tab 循环读不准当前档）；换权限一律重开接回。
- 不替用户回答任何确认菜单（信任、完全访问警告、切换确认）。
