文件树挪进右栏：文件和改动各开各的窗格

你指出的关键点：Claude 里「改动」和「文件」是两个分开的窗格——对话头上各有一个按钮（± 和文件夹），右栏同一时刻只显示其中一个，各有各的头；不是一条「文件 | 改动」标签条。 我们的对话头已经有终端按钮和「± 改动」按钮（TerminalPage.tsx 对话头里的 FileDiff 钮，开关右栏的 git 页），所以最顺的做法是：再加一个「文件」按钮，右栏那条「文件 | 改动」标签条撤掉。 树是文件窗格头里最左的固定标签，文件是它右边的斜体预览标签。示意只画结构，尺寸、动效、图标你来定。

前两版我更正过的一点沿用：previewFiles 只是同夹兄弟文件（↑↓ 切换用），右栏同一时刻只有一个预览，所以一期只做「树 + 一个预览标签」，多文件标签放二期。

现有改动页的功能（逐 hunk 验收、提交等）全部原样，不改。只是窗格头不再是「文件 | 改动」两个标签，而是写「改动」+ 汇总。这一块我不会动内容。
这么拆的理由
· 两者的使用时机不同：「文件」是浏览和打开，「改动」是对话干完活后验收，不会同时盯着。
· 对话头已经是「看终端 / 看改动」这套开关，加一个「看文件」最自然，用户不用学新位置。
· 各窗格自带头，改动页以后加「基准 ▾」之类的选项不用和文件页抢同一条标签。
· 代价：想同时看文件和改动做不到（Claude 同样如此）；要并排用「专注内容」或分屏。

五、预览标签的规则（一期 / 二期）

一期（推荐先做）二期（要再拍板）
标签数量树 + 最多一个预览标签。和现在「同一时刻一个预览」的状态模型一致，改动面小。预览标签可「固定」（双击或编辑后自动固定），固定的多开，斜体的仍只一个。需把 preview 单状态改成列表，每个标签自带未保存状态。
单击树里的文件替换预览标签并切过去。同左；已固定打开过的，直接切到那个标签。
关预览标签 ×回到树。未保存时照旧提示。关到相邻标签；没有就回树。

六、细节怎么处理

项目处理
对话头按钮在「看终端」「± 改动」之后加「▤ 文件」（图标待定）。原来左边「显示文件树」「收起文件树」「窗口不够宽先让位」整套不要了。
右栏标签条撤掉「文件 | 改动」。RIGHT_TABS / rightTab 仍用来记当前是哪个窗格，只是不再画成标签。
树的根仍是这段对话的文件夹，与「改动」跟随的根一致。
搜索框直接输入过滤文件名 / 后缀（现有行为）；? 开头搜文件内容依赖后端有没有内容搜索，没有就这期不做，占位符只写现有的。
树的排序与图标点开头目录在前、普通目录、再文件；按类型配小图标；展开文件夹左侧缩进竖线。视觉增强，可一起做也可单拆。
卡片样式Claude 的右栏是浮起的圆角卡片；我们是贴边分栏 + 线条语言，建议这次不改，只改结构。
宽度三块变两块：对话 ≥ 360px，右栏默认 460px、最窄 360px。没有「文件树 12–22rem」这一档，窗口窄时只压右栏。
从对话点文件路径 / 工作台跳转打开右栏文件窗格并出预览标签（与现有 openPreview 入口一致）。
记忆右栏最后停在哪个窗格、文件窗格最后停在树还是预览；旧的树「开着 / 宽度」偏好弃用。
