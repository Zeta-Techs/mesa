## 0. 一句话

AI 越强，卡住科研进度的越不是「AI 干得好不好」，而是三件事：**机器**（活跑在笔记本上，合盖就停）、**人的注意力**（产出多一百倍，人审不过来、也批不过来），
**对外的门**（下全文、读来信、用外部服务要用到人的身份）。Mesa 的定位不变——AI 干活，Mesa 管活，人拍板——变的是「管」的方式：
**从逐条批准，改成事前授权、事后核验；执行可以离开笔记本，但凭证、计量和记录始终在 Mesa 手里。**

## 1. 终局排序（2026-11-08 拍板）

| 顺序 | 支柱 | 终局形态 | 本稿章节 |
|---|---|---|---|
| 1 | 执行离开笔记本 | Mesa 是控制台，活在实验室服务器、集群或官方云端跑，Mesa 窗口关着也不停 | §5 |
| 2 | 授权在前、核验在后 | 开工时人圈定范围（能写哪里、能访问哪些网站、花多少、多久、用谁的身份），范围内 AI 不逐条问；越界才找人，手机只处理越界 | §4 |
| 3 | 核验与出处（主轴） | 「哪些能信、出处在哪、谁用什么在哪台机器上做的」是人真正要看的；三档核验与研究记录照旧是护城河 | §9 |
| 4 | 对外的门由 Mesa 管 | 身份、计量、日志在 Mesa；AI 只是手。全文代下是第一扇门 | §6、§7 |
| 5 | 长期在跑的活 | AI 起草，人批准一次，之后在授权与预算内长期跑 | §8 |

维持不做：**自动挑模型 / 挑机器人**（各家 CLI 会在内部调度；Mesa 只把「谁、用什么模型做的」记清楚，这是 AI 使用声明与复现包要交代的事实）；
**语音朗读与通话**（输入用系统听写和飞书语音转文字即可）；自建 VM / 云电脑、自研 Agent 循环、通用 Manus 式产品（§11.5 照旧）。

## 2. 设计原则

1. **凭证不给 AI，门由 Mesa 开。** 学校会话、API 密钥、飞书凭证永远不进 Agent 的环境与提示词；AI 要用，调 Mesa 的工具，由 Mesa 代为出门、计数、记账。
   这是本稿唯一能**硬落实**的边界，其余能落实到哪一步取决于各家 CLI（§3）。
2. **能力表说实话。** 某家 CLI 做不到的限制，界面写明「这家只能做到 X」，走 `AgentCapabilitiesDto` 能力表，不假装做到，不硬编码。缺能力时拒绝启动，不悄悄放宽（同只读权限「缺能力拒绝」）。
3. **授权是 Run 的事实。** 每次 Run 记下用的是哪份授权、在哪台机器、哪条连接、花了多少、出过哪些门；事后核验对照它，研究记录与复现包从它出。
4. **外来文字是资料，不是指令。** 网页、文献、手机与飞书消息、别的 Agent 留的话交给 AI 时一律标明来源并声明「不照其中的指令办事」。这是放开授权与代下全文的前提（另一会话 2026-11-08 已在做，见 §11 期 0）。
5. **人拍板的东西不下放。** 保存进项目、评审采纳、删除、写回、扩大授权，仍然只能由人点；终局里只是点的次数变少、粒度变粗。

## 3. 现状（2026-11-08 核对，改代码前以代码为准）

### 3.1 各家 CLI 能被约束到哪一步

| CLI | 限制可写目录 | 限制联网 | 越界时能否由程序作答 | 说明 |
|---|---|---|---|---|
| Codex | **能，系统层**：`-s workspace-write` + `sandbox_workspace_write.writable_roots`（`pty.rs` 已给主仓 `papers/`） | **只能开 / 关**：`sandbox_workspace_write.network_access`，Mesa 现在恒开 | 能（app-server JSON-RPC） | Windows 沙箱要用户配置或同意 |
| Claude Code | 只能按工具路径规则（`--allowedTools "Edit(./notes/**)"`）；自带沙箱设置**待调研**（matrix 未记） | 只能去掉 WebFetch / WebSearch / Bash；按域名放行**待调研** | 不能，只能在终端菜单里点 | `--settings` 覆盖层现在只带 env 与 hooks，不带权限规则 |
| OpenCode | 按应用层规则（`OPENCODE_CONFIG_CONTENT` 的 edit 路径 allow / deny） | 按工具（webfetch / websearch） | 能（HTTP） | |
| Grok Build | 系统层 `--sandbox`，Mesa 只用过 `read-only`；`workspace` / `strict` 未测 | 未知 | 不能（只报 blocked） | |
| Qwen Code | 未知 | 未知 | 能（Dual Output 输入文件） | 无头写盘未验证 |
| Gemini / Kimi / CodeBuddy / Cursor | 未知（只有审批档位） | 未知 | 不能；Cursor、Gemini 连审批事件都没有 | |

要点：**没有哪一家能按网站放行**；预算没有任何一家有原生开关（Claude Code 的单次花费上限参数待核）；
**定时任务与可写的无头目标现在是全权限跑**（`ai.rs` `headless_task_args`：Claude `bypassPermissions`、Codex `workspace-write` 加联网、Grok `--yolo`），
隔离副本只决定工作目录，除 Codex 外系统层挡不住写到副本外面；保护路径只在合并 / 写回时检查。

另一会话 2026-11-08 排查外来文字时交来的两处缺口，同属授权范围、并进期 3 处理：
① 一次性调用（`ai.rs` `ai_prompt_impl` 一族）只有 Claude、Codex 带了限制，OpenCode、Kimi 等几家没有任何沙箱 / 权限参数，能不能写文件、跑命令未核实；
② 跨厂商复核只在提示词里写「只读」，实际开的是可写会话——提示词说的权限与启动参数给的不一致，违反原则 2「能力表说实话」。

### 3.2 执行层与后端

- `runtime.rs` 只有 `LocalCli / Headless / Custom` 三种，**没有 Runtime 接口**，三种是三条写死的路；agent-workbench.md §6.1 规格里的 `AgentRuntime` 尚未落地。
- 后端已管：定时任务与事件规则（`scheduler.rs` 每分钟一跳）、无头运行、飞书长连接收发、Run 记录与租约、会话解析与用量。
- **只在前端窗口里跑**：派活进展（每分钟）、推新人工请求和卡住的活到手机、飞书消息路由与卡片动作、项目内传话投递、分片合并、空闲自停、十分钟无输出判定、
  「卡在哪」判定（读 xterm 画面）、交互式开跑（`setPendingTerminal` → 终端页 → `pty_spawn`）；部分状态在 localStorage。
- 会话、用量、隔离副本、评审冻结、hooks、聊天旁路全部假定 CLI 跑在本机磁盘上。

### 3.3 全文获取

- 自动阶梯 `fetch_fulltext_bytes`（`lit_watch.rs`：开放直链 → Unpaywall / OpenAlex 合法副本 → 机构通道）**仍在后端，但界面已不调用**；
  现行入口全是人逐篇点：在系统浏览器打开（`inst_browser_open`）由下载目录接住，或浏览器扩展的「存到 Mesa」（`extension/` + native messaging → `mesa_helper` 入库）。
- **Mesa 里没有任何频率限制**：无按出版商计数、间隔、每日上限、熔断、请求日志；只有超时、60MB 上限、6 跳重定向。技能脚本 `lit_records.py` 有 429 / 5xx 退避与「连续 3 篇 403 全停」。
- Wiley、Elsevier 对非浏览器客户端一律 403（按 TLS 指纹判），Wiley / ACS 的 epdf 是图片阅读器，Nature / Springer 对 urllib 给验证页——**真浏览器才下得动**，扩展路线正好是真浏览器。
- 无头与定时运行**拿不到**机构会话（只有阶梯里一处读它）。

## 4. 支柱二：授权范围

### 4.1 对象

一份**授权**挂在 Task 上、随每次 Run 落进 Run 事实：

| 项 | 取值 | 说明 |
|---|---|---|
| 能写哪里 | 隔离副本（默认）/ 加上项目里指定的目录（如 `papers/`、`data/raw` 只读） | 项目根直写仍不允许，派生产物照旧经评审带回 |
| 联网 | 关 / 只走 Mesa 的门 / 学术清单 / 开 | 「只走 Mesa 的门」= Agent 自己不联网，下全文、查题录调 Mesa 工具 |
| 身份 | 哪条连接；能不能用学校会话（只经 Mesa 的门） | 密钥照旧拉起瞬间注入；学校会话永远不进 Agent |
| 预算 | 这次最多花多少（按官方价，同用量页口径） | 到了就停，记一条「到预算停下」 |
| 时限 | 最长跑多久 | 现有：定时 5–180 分、无头目标 90 分 |
| 机器 | 本机 / 某台 SSH 机器 | §5 落地后才有 |
| 越界怎么办 | 停下问人 / 记一笔继续（只限不写不花钱的） | 默认停下问人 |

授权有几份**常用底稿**（读文献、整理数据、写稿、代下全文、定时巡检），人开工时在弹层里看到并可改；任务包只能**申请**授权项，装包或开工时由人批准，
不能自己放宽（与任务包「改不动隔离 / 评审 / 核验 / 密钥」同口径）。项目助手起草派活单时附上建议的授权，人点「派出去」即批准这一份。

### 4.2 三层落实

1. **CLI 原生能做的照做**：Codex 用沙箱的可写根与联网开关；Claude Code 把权限规则写进 `--settings` 覆盖层（allow / deny、工具白名单），其自带沙箱能否按域名放行先调研；
   OpenCode 用 permission 配置；Grok 先实测 `--sandbox workspace`。做不到的项，开工弹层按能力表写「这家只能做到……」，人可以换一家或接受。
2. **门在 Mesa**：全文、题录查询、出图（已有 `MESA_IMAGE_TOOL` 先例）一律经 `mesa_helper` 子命令，凭证在 helper 里现取、不进 Agent env；
   每次出门记日志、计数、按授权放行。**按网站放行在 CLI 层做不到，所以真正要紧的门不靠网络过滤，靠「凭证只在 Mesa 手里」。**
3. **收尾对照**：评审冻结已有开工基线与收尾快照，加一条「写到授权范围外」→ 核验拦下；花费超出、出过清单外的门 → 记进 Run 事实，评审页列出。

**花费在跑的过程中盯**：无头运行按会话文件里的用量累计，到预算 `kill_process_tree`；交互运行到预算先推「等你的事」，不强杀（人可能正在看）。

### 4.3 替掉现在的全权限

定时任务与可写无头目标改为**按授权生成启动参数**：默认底稿「写隔离副本 + 只走 Mesa 的门 + 每周预算」；Codex 起关闭沙箱联网，Claude 起以权限规则代替 `bypassPermissions`。
做不到的家（只有全权限档的）在定时任务里标「这家只能全权限跑」，由人决定还用不用。这一步要先做外来文字的资料化（原则 4），否则放开授权等于放大注入面。

### 4.4 越界与手机

越界请求进「等你的事」，类型「要扩大授权」，写清扩什么、为什么、这次还是以后。手机上可以点「只扩这一次」，
**只限能由程序作答的 CLI（Codex、OpenCode、Qwen）**；其余家只能回电脑在终端里点。「以后都允许」只在桌面改授权底稿。
逐条确认命令仍不在手机上做（终局里它应当越来越少出现，不值得为它做小屏 UI）。

## 5. 支柱一：执行离开笔记本

### 5.1 期 A：SSH 远程执行

Mesa 留在笔记本，CLI 在实验室服务器上跑，数据不出单位，复用课题组现成的 SSH 账号与密钥。

- 先把 agent-workbench.md §6.1 的 `AgentRuntime` 接口落成代码（start / stop / resume 不支持时给原因），三种现有 Runtime 改走接口，再加 `RuntimeKind::Ssh`。
- 启动：PTY 里跑 `ssh -t`；**密钥经 stdin 交给远端的一次性包装脚本再进子进程 env，不出现在命令行**（ps 可见）；远端 CLI 由用户自装，Mesa 先检查版本。
- 隔离与评审：隔离副本建在远端（git worktree），开工基线与收尾快照由远端的 `mesa_helper` 算好拉回；采纳时把所审副本拉回本机项目根。
- 会话与用量：按 Run 把远端会话文件拉回只读镜像（sftp / rsync），喂给现有解析与用量；`.ccode/help-wanted.md`、`outbox.jsonl` 同样拉回。聊天旁路远端起不来时退回读屏（已有回落）。
- 网络门：远端调 `mesa_helper paper` 时经 SSH 反向通道回到本机 Mesa 的门，学校会话不出笔记本。
- 要改的已定规矩：无（Backlog 已有此项；「会话目录只读」对远端镜像同样成立）。

### 5.2 期 B：常驻后端

把 Mesa 拆成**常驻核心**（可跑在实验室工作站上）+ 桌面窗口 + 飞书，窗口和飞书都只是接上去的客户端。

- 前端里的那批循环（§3.2）挪进后端；读屏判定换成后端的终端仿真（vt 解析）；交互式开跑要有不经窗口的后端入口；PTY 输出改成可多端接入、可断开；localStorage 状态进 `app.db`。
- **不开公网端口**：核心只监听本机（或 unix socket），远程接入只走 SSH 隧道；飞书照旧主动连出。Tailscale 一类只是用户自己的网络，Mesa 不依赖也不内置。
- 要改的已定规矩：§11.5「daemon 化」、调度台「Mesa 必须在电脑上开着」、Backlog「后台常驻须重新拍板」。动手前单独出一份 §10 决策草案。

### 5.3 期 C：官方云端 Runtime

Claude Code 云端会话、Codex cloud 等有稳定官方接口才加 Adapter（§11.6 照旧），产物照走评审冻结。

## 6. 支柱四之一：全文代下（2026-11-08 拍板）

> **2026-11-09 收窄，以本条为准**：HER 检索步实测，学校通道直取与浏览器扩展后台取都走不通——Wiley / RSC 拒脚本请求（403），Elsevier 封 IP（CPE00001），46 篇只有 ACS 下成。用户拍板「根本不可行」：代下只留 6.2 的 ①（开放获取），找不到的交给人点「官网」自己下；6.2 的 ②③、AI 指候选链接，以及 6.3 按学校身份计的间隔、每日上限、熔断、整队暂停都已撤掉。6.1 的范围检查与「不存密码、不自动登录、不解验证码」不变。下文保留为当时的设计记录；再放开须重新拍板，并先在真实项目上干跑。

### 6.1 拍板

用户原话：「只要不连累学校IP 可以用AI computer use下或者怎么方便怎么设计」。据此**取代** 2026-09-16 机构访问通道的「只由人逐篇触发、无头不携带会话、不做批量」：
AI（含无头与定时运行）可以请求代下全文，**硬约束是不连累学校的 IP 与账号**，由 Mesa 计量和拦截，不靠 AI 自觉。以下不变：
不存学校账号密码、不做无人值守自动登录（MFA 过不去）、学校会话不进 Agent env 与 shell、**遇到验证码交还给人，AI 不解验证码**。

### 6.2 形态：Mesa 的下载队列，AI 只是提出请求

```
Agent ──mesa_helper paper fetch <DOI>──▶ Mesa 下载队列（全局一条、单线程、按出版商限速）
                                          │
                                          ├─ ① 开放直链 / Unpaywall / OpenAlex 合法副本（不用学校身份，不计入学校配额）
                                          ├─ ② 机构通道直取（现有 fetch_via_channel；Wiley / Elsevier 这类按 TLS 指纹拦的直接跳过）
                                          └─ ③ 真浏览器：Mesa 叫浏览器扩展在后台标签打开落地页、在页内取 PDF（现有「存到 Mesa」逻辑）
                                                 └─ 页面上找不到 PDF → 把页面截图与链接清单交给 AI 指一个候选（只在这个标签里点，computer use 只限于此）
                                                 └─ 验证码 / 登录页 / 「异常访问」页 → 熔断该出版商，交还给人
```

- **为什么走浏览器扩展而不是接管屏幕**：扩展跑在人自己的浏览器里，用的就是人登录过的学校会话和真浏览器指纹，Wiley / Elsevier 也下得动；
  不抢鼠标，不碰其他标签；扩展、native messaging、`helper_ingest` 入库都已存在。接管整块屏幕的 computer use 不用：会和人抢操作，也会看到人屏幕上的其他东西。
- AI 只提交 DOI，只能下**项目清单里有的**（`papers/included.json`、`to-fetch.md`、雷达已采纳的条目），清单外的 DOI 进「等你的事」由人点放行。
- 入库照旧：PDF 校验 `%PDF-`、同字节去重、写 `papers/` 并登记（原始资料直写项目根，口径 C 不变）；Agent 拿到的是落盘路径，不是字节流。

### 6.3 不连累学校的硬规矩（Mesa 执行）

初值偏保守，按人读文献的节奏定，实测后再调；**人可以调低，调高有上限**。

| 规矩 | 初值 |
|---|---|
| 全局只有一条下载队列，单线程，多个 Run 的请求排在一起 | — |
| 同一出版商两次请求间隔 | 随机 15–45 秒 |
| 同一出版商每天上限（经学校身份） | 30 篇 |

### 6.4 其他门

## 7. 支柱四之二：对外入口（外面的 AI 查 Mesa）

吸收另一会话对 T3 Code / OpenMausBot 的借鉴项：开一个**有边界的 MCP**，让人在 Claude 桌面版、终端里的 CLI 或别的 AI 里问「综述到哪了」「记一个目标」。

- 能做：读项目状态、读等你的事、起草目标与派活单（落成草稿，照旧要人在 Mesa 里点开始）。不能做：批准、采纳、保存进项目、删除、改授权、碰密钥与设置。
- 只监听本机；首次接入出配对码由人批准，分两档「只读 / 可起草」。
- 要改的已定规矩：Mesa 第一次对外开入口，单独拍板。排在常驻后端之后做（接在核心上，不接在窗口上）。

## 8. 支柱五：长期在跑的活

- 项目助手起草定时任务后，单子上点一下即**建成、默认暂停**，旁边给「启用 / 改一改 / 撤销」；启用卡写清：做什么、多久一次、用哪条连接、**用哪份授权、每周预算**、在隔离副本里跑。
  取代现在「跳到定时任务页、新建表单、AI 写巡检技能、确认」的多步；仍然是人点，项目助手自己不建、不启用。
- 定时结果「同一条记录、每次新开会话」（借 T3 Code）：记录连贯，上下文不越滚越大。
- 事件规则照旧：只由人写、新建默认只记录。
- 开工弹层写「这条连接上次同类步骤花了约 $x（按官方价）」：陈述历史，不预测；没记录就不写。终局里它并进授权的「预算」一项。

## 9. 主轴：核验与出处

每根支柱都往 Run 事实里写：授权（哪份、越过几次界、谁批的）、机器、连接与模型、花费、出过的门（哪些 DOI 经哪一级取得）。
研究过程报告、AI 使用声明、复现包从这里出。核验三档（通过 / 拦下 / 待你判断）不变，新增两条机械检查：写到授权范围外、出过清单外的门。

## 10. 不做

- 自动挑模型 / 挑机器人、模型研判（「谁用什么做的」要说得清）。

- 接管整块屏幕的 computer use；替人填表、提交、付款、改账号；AI 解验证码。
- 自建 VM / 云电脑、自研 Agent 循环、通用 Manus 式产品、500 个应用连接。
- 公网监听端口、自建中转服务器。
- 手机上逐条确认命令、采纳、写回、删除。

## 12. 风险

- **授权给人「安全了」的错觉**：多数 CLI 只能做到一部分。对策：能力表逐项写实，开工弹层只列这家真能做到的项；凭证类的门不依赖 CLI。
- **代下全文仍可能触发出版商风控**：对策是保守初值、按出版商熔断、请求日志可查；第一次实测选一个人工也会去下的小清单（≤10 篇），在用户真实项目上跑一遍再放开（「动真实数据先干跑」）。
- **远端会话镜像与评审冻结拉回的一致性**：远端算哈希、本机只认拉回的所审副本，与「合并只带回所审副本」同口径。
- **常驻后端工作量大**：前端那批循环要整体挪；期 6 之前不为它在前端加新的长循环，新循环一律写在后端。
