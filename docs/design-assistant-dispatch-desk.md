# Mesa 设计稿：项目助手调度台、动作分级、飞书通道与总助手

> 状态：**已拍板、一并落地**（2026-11-06，用户「所有按照设计需求安排，直接做」）。
> 起因：用户问「项目助手是不是相当于子 bot、能不能统筹项目下正在进行的会话」「能否在手机上做一个主 bot 派发指令、会话返回的问题在 bot 里统筹回复」「是不是需要服务器」。
> 前置：`docs/design-assistant-intake.md`（接活、派活单、派活回音、记忆）、`docs/design-project-coordination.md`（看一眼、传话）、`docs/design-phone-drop.md`（手机采集口）。

## 0. 一句话

三层：**总助手**（只有一个，判断你说的是哪个项目、汇总所有项目等你的事）→ **项目助手**（每个项目一个，这个项目的调度台）→ **工作者**（步骤会话、目标运行，真正干活）。
项目助手不是常开的会话：它的「身份」是 Mesa 保管的状态（问答记录、项目知识、正在跟的派活、等你的事），每来一条消息——桌面面板或手机——都在后台调一次 AI。
手机经**飞书机器人长连接**接入：Mesa 主动连出去，不自建服务器、不要公网地址；Mesa 必须在电脑上开着。

## 1. 拍板（2026-11-06）

1. **桌面调度台**：项目助手顶上列出这个项目「等你的事」——人工请求、AI 在对话里问你的话、等你确认的命令；你就地回，Mesa **原路、原话**转达（人工请求写回作答并交给那一步、对话里的问题经留话或接回对话送达），**不经 AI 改写**。确认命令只带路去对话里确认。
2. **动作分级**：项目助手的动作分三档——不用你点（回答、总结、收进列表）/ 你点一下就生效（答人工请求、留话、派出派活单、记规矩、答它的追问）/ 只在桌面（确认执行命令、评审采纳、写回项目、删除、跳页）。分级表是唯一真源，桌面与手机共用。
3. **手机定位改写**（取代 10-20「手机只是采集口、拍板留在桌面」的一部分）：经飞书通道，手机上可以做「你点一下就生效」那一档；「只在桌面」那一档在手机上只提示「请在电脑上处理」。
   手机网页「从手机添加」仍是单向局域网采集口，不变。
4. **数据经飞书**：用户接受会话摘要、问题、派活单经飞书服务器传到手机。密钥、文件正文不发；发出的文字先脱敏。
5. **飞书机器人由用户自建**（企业自建应用，App ID / App Secret），Secret 存 0600 `keys.json`；**配对永远要人点开始**（设置里点「绑定」出 6 位码，在飞书里发给机器人），只听绑定的那一个人，其他人的消息丢掉。
6. **总助手只路由与汇总**：不在项目之间搬数据（跨项目不直连照旧）；判断项目靠你点名（「课题A：…」）、上一次说的项目、或给你项目按钮选，不靠 AI 猜。

## 2. 调度台：等你的事

| 来源 | 判定（全机械） | 你怎么回 | Mesa 怎么转达 |
|---|---|---|---|
| 人工请求 | `list_help_requests` 里这个项目未答的 | 点选项或写一句 | `help_request_answer` 写回；那一步的 AI 开着 → `mail_send` 送「按决定继续」；关着 → 接回那段对话自动开跑、标已送（同人工请求弹层） |
| AI 在对话里问你 | 某一步最近那段对话 AI 的最后一段话像在问（问号、「要不要 / 是否 / 请确认 / 选哪」），且 AI 没在干活 | 写一句 | 开着 → 留话；关着 → 接回对话带上这句开跑。送的是「【你在项目助手里的回复，Mesa 转达】原话」 |
| 等你确认的命令 | 终端里这个项目的标签 attention = confirm | 只在桌面：点「去对话里确认」 | 不代答 |

派活回音照旧写在问答里。

## 3. 飞书通道

- 后端 `feishu.rs`：长连接收消息与卡片回调（只收私聊、只收绑定的人、按 message_id 去重），REST 发文字与卡片；状态 `off / connecting / online / error`。
- 前端 `im-bridge.ts`：收到一句话 → 总助手路由（`im-route.ts`）→ 项目助手问一次（与桌面同一条 `askProjectAssistant`，记进同一份问答记录）→ 把回答里的块渲染成卡片（`im-cards.ts`）：`:::问` 选项按钮、`:::派活` 「派出去」、`:::记下`「记进项目知识」、等你的事逐条按钮。
- 卡片按钮 → 按分级表执行；「只在桌面」的回「请在电脑上处理」。
- 推送：派活回音、新出现的等你的事，推到手机（同一条只推一次）。
- 手机上常用说法：「课题A：…」点名项目；「等我的」看所有项目等你的事；「切到 课题B」改默认项目。

## 3.1 信任文件夹（2026-11-06 用户拍板「两项都做」）

真机实测发现：从手机派出的目标第一次进 Mesa 建的隔离副本，Claude Code 停在「是否信任这个文件夹」，调度台与手机都看不到，活一直卡着。定：
① 停在信任菜单算「等你的事」，调度台列出、可点「信任并继续 / 不信任」；② 手机上推卡片，**只限经项目助手派出去的活**带信任按钮（仍是人点），
其余与等确认的命令只提醒回电脑。不做自动信任（终端页「信任文件夹由人在信任卡上点」不变）。

## 4. 不做

- 不做常开的总控会话（项目助手仍是每问一次）；不做自建中转服务器；不在手机上确认命令、采纳、写回、删除。
- 不做 AI 自己去回答会话的问题（「Mesa 不替人回答」照旧），AI 只把问题讲成人话、按需起草回复，由你发。
- 不做群聊机器人；不做多人共用一个机器人。

## 5. 落地记录与未验（2026-11-06）

- 后端 `feishu.rs`：同步 `tungstenite`（rustls + 系统根证书）跑在自己的线程，pbbp2 帧手写编解码（与 Go SDK `Marshal` 字节一致的测试）；ping、分片重组、ack 照官方 Go SDK `ws/` 客户端；
  不可重试的错误（凭证错、403、连接数超限）停在 `error`，其余按服务端给的间隔重连、状态留 `connecting` 并写原因。换 App ID 清绑定、删旧 Secret。配对码错 5 次作废。
- 卡片点击按官方 SDK 走 `type=event` 帧，立刻回 toast「收到」；`feishu-card-action` 的 `messageId` 是这次点击的 event_id，`openMessageId` 是卡片消息 id。
- 已验：假凭证打 open.feishu.cn 得到预期错误码（不可重试）；WebSocket TLS 握手与收发；前后端各自单测（Rust 13 个、前端路由 / 卡片 / 调度台）。
- **真机实测（2026-11-06，用户自建「Mesa交互机器人」，公司租户、管理员审核发布）**：长连接连上（飞书后台保存长连接设置通过）、配对绑定、私聊文字收发、
  「项目」列表、说不清项目时的项目按钮卡片、**卡片按钮回调**（点项目名后交给那个项目）、项目助手回答卡片（含「在电脑上还可以：…」）全部正常。
- **未验**：手机上「派出去」、「等我的」与「回第 N 步」转达、派活回音与新人工请求推送、分片消息；调度台在 Mesa Dev 窗口里点一遍。
- 局限：同一个飞书应用在两台电脑上同时连，飞书会把事件分给不同连接，每台只收到一部分——一个机器人只接一台电脑。
