# Mesa 设计草案：科研做图——交出去的是能改的图

> 状态：**草案，待拍板**（2026-11-05）。§11 列出要用户定的几项；拍板后细则写进 `docs/conventions/pipeline.md`「科研做图」、
> 各技能 SKILL.md，并在 architecture §10 记一条。

## 0. 一句话

科研里的图分好几种，各自适合不同的做法。Mesa 不在应用里做画图编辑器，只管四件事：**每种图交给谁画、交成什么格式、
机器能查的先查掉、人在熟悉的软件里接着改**。交给人的永远是能改的源文件（PPTX / SVG）加上生成它的过程，不是一张改不动的 PNG。

## 1. 起因

用户转来一段同行聊天（2026-11-05），有三个信号：

1. **「给它个大纲就能做得不错」**：同行用一个 skill 从大纲做出带大量中文小字的机理 / 设计策略图（图形摘要式的版式图）。
   要的是「大纲 → 排好版的图」，不是数据图。
2. **「把生成的图转化成可编辑的 PPT」**：AI 画得不完美不要紧，要紧的是改得动——挪个框、改个字。
3. **「现在不用 Origin 也行，Python 画完到 Adobe 里拼图后处理」**：数据图已经普遍走 Python；缺的是拼版和后期这一步。

Mesa 现状（2026-11-05 盘点）：

| 图的种类 | 现在由谁做 | 缺口 |
|---|---|---|
| 数据图 | `figure-forge`（立论点、期刊规格、`fig_check` 重建核验）、`data-eda`；Windows 可选 `origin-plot` | 基本够。SVG 文字可能被转成路径，到 Illustrator / PPT 里改不了；画完没有「看一眼成图」的自检 |
| 示意图（机理、装置、流程、技术路线、图形摘要） | `image-gen`（出图模型，规定默认不画字）；`review-figures`「自绘示意图」（matplotlib）；`blender-research`（三维） | **最大空白**：文字多的版式图没人能做好；交出去的都是位图 |
| 组图（多块拼成一张投稿图） | `review-figures/assemble_panels.py`，只拼从文献裁的 PNG | 自己的数据图、示意图、照片拼不到一起；结果不能编辑 |
| 交给人改 | 无 | 没有 PPTX 出口；人改过以后 AI 再改会不会冲掉人的改动，没有规矩 |

## 2. 参考了什么

2026-11-05 在 GitHub 上看了科研做图方向 star 较高的项目（只读 README / SKILL.md / 源码，没装也没跑），按思路分四类：

| 思路 | 代表 | 学什么 | 不学什么 |
|---|---|---|---|
| **先出整图，再拆成可编辑** | `ningzimu/image-to-editable-ppt-skill`（3.2k，即聊天里那个）、`ResearAI/AutoFigure-Edit`（4.4k，ICLR 2026） | 文字位置与字号「测量驱动」、同级文字字号分组统一；图标先出在一张纯色底素材板上再抠；占位框把 AI 写的骨架和切出的图标对齐 | 依赖第三方 OCR 服务 / SAM3 / RMBG 本地大模型；一页 10 分钟、10 页能用完 Pro 额度；字的正确性靠识别，识别错了就错 |
| **出图模型出成品 + 模型评审** | `K-Dense-AI/scientific-agent-skills` 的 `scientific-schematics`（库 56k）、`dwzhu-pku/PaperBanana`（7.6k，ICML 2026） | PaperBanana 先找同类参考图再规划、风格指南从优秀图归纳、评审回路；出「效果参考图」帮人定风格 | 图里的字靠出图模型写（中文尤其不可靠）；按模型打分过门槛（8.5 分）——与 Mesa「核验不打总分」冲突 |
| **代码画矢量** | `lgwrightlab/schematic-figure`（169，2026-10 新，Nature 风格） | 先写一句话要点、规格卡、事实记录再动手；每个元素标来源；检查脚本（gate）只列「必须修 / 逐条说明」不打分；上屏文字逐字对事实记录；冷读。**作者自测：分数主要来自规划阶段（去掉掉 6.8 分），双稿、自评、gate 几乎不加分但能消错** | 依赖 Node 22 + 无头 Chromium，普通科研用户装不齐；用盲评模型打 0–100 分 |
| **数据图** | `Haojae/scipilot-figure-skill`（2.8k）、K-Dense `scientific-visualization` | 画前按 18 条误用清单拦（小样本均值柱、双 Y 轴、截断轴…）；画后程序自检（缺字、出界、刻度标签相交）+ 灰度预览；SVG 保留可编辑文字 | ——（与 `figure-forge` 方向一致，只补缺） |

各项目的机制细节见 §12「参考机制摘录」。许可证都是 MIT / Apache-2.0；按 AGENTS.md 借鉴原则，学机制不抄代码。

**结论**：文字和排版交给大模型「写出来」，出图模型只画不带字的局部——这是唯一能同时做到「字一定对、能改、能重跑」的路。
「先出整图再拆」留作补充模式（§7），只服务「我就喜欢这张 AI 图，帮我拆开」。

## 3. 总原则（不变量）

1. **交付 = 源文件 + 重建过程**。每张图要么有生成脚本（数据图），要么有图纸（示意图、组图，§4.2），都登记进
   `figures/manifest.json`，`fig_check` 能重跑出同一张图。
2. **文字永远是真文字**。不让出图模型写字；SVG 不转曲、PDF 嵌字体（matplotlib `svg.fonttype: none`、`pdf.fonttype: 42`），
   PPTX 里是文本框。期刊明确要求转曲的，在投稿副本里转，源文件不转。
3. **出图模型只画不带字的局部**：图标、插画元素、背景质感；透明底；经 `MESA_IMAGE_TOOL`（密钥不进 Agent 环境）。
   每个这样的元素在图纸里记下模型和描述，交付时生成 AI 使用披露句。
4. **先立意、列事实，再动手**。一句话要点、要点清单、不能暗示什么、事实记录（元素顺序、方向、数量、因果，带出处）。
   事实记录里没有的东西不画；没有出处的标「不确定」，要么问，要么故意画得模糊（数量写 N 或省略号）。
   画**这篇工作的具体实例**，不画教科书通用版；只画手上有的数字，没有数据就定性表示或不画；示意性的曲线结构要对、
   精度不能高过实际，图注写明是示意（借 schematic-figure P23 / P28 / P29）。
5. **核验三档，不打总分**。机器能确定的（文字重叠、出界、字号低于下限、缺字方框、文件能重建）判通过或拦下；
   好不好看、科学上对不对，最多「待你判断」。不设模型评分门槛。
6. **人改在自己熟悉的软件里**（PowerPoint / WPS / Keynote / Illustrator / Inkscape）。Mesa 不做画图、SVG 编辑或裁图界面
   （沿用 2026-09-20「不做 Mesa 内裁图界面」口径）。
7. **人改过的文件是新的源**。人一旦改过 PPTX / SVG，AI 之后只在这份文件上做局部修改，不从图纸重新生成覆盖它（§6.3），
   与精读「在原笔记上续写」同口径。
8. **不画冒充实验数据的图**（显微照片、电泳条带、光谱、仪器截图），沿用 `image-gen` 边界；照片类面板在组图里只许整体缩放、裁切，
   不改像素。

## 4. 示意图：大纲 → 图纸 → 可编辑图（新技能，核心）

新增内置技能 **`schematic-forge`**（名字待定，与 `figure-forge` 同族；§11-1）。管：机理图、装置 / 实验流程示意、技术路线图、
概念图、图形摘要（TOC 图）、组会用的大图。不管：数据图（`figure-forge`）、照片级三维（`blender-research`）、
文献图拼板（`review-figures`）。

### 4.1 流程

借 `schematic-figure` 的分步和 PaperBanana 的「先找参考」，按 Mesa 口径收窄：

| 步 | 做什么 | 落在哪 |
|---|---|---|
| 0 定档 | 用途（期刊示意图 / 图形摘要 / 组会 / 技术路线）、成品尺寸（89 / 183 mm、16:9、期刊 TOC 规格）、语言、深度（草稿 / 标准）、风格参照（用户给的图、项目里已有的图） | 第一句回复就写出「我按什么定的」，不先问 |
| 1 立意 | 一句话要点、要点（用户原话优先）、不能暗示什么、范围 | `figures/<图名>/brief.md` |
| 2 事实 | 每个要画的东西：是什么、顺序、方向、数量、谁作用于谁、出处（笔记 / 论文 / 用户） | `figures/<图名>/facts.md` |
| 3 构思 | 草稿档 1 个、标准档 2–3 个布局方案，各画一张成品尺寸缩略图并排给人看；人挑一个（**AI 提议、人拍板一次**）。可选：人要时用出图模型出 1–2 张「效果参考图」定风格，明确标「只看风格，字不算数」 | `figures/<图名>/concepts/` |
| 4 图纸 | 按选中的方案写图纸（§4.2） | `figures/<图名>/figure.json` |
| 5 素材 | 每个图标位按顺序取：内置图元 → 项目里已有素材 → 出图模型（同一风格的图标出在一张纯色底素材板上再切，透明底） | `figures/<图名>/assets/`（每张附 `.prompt.txt`） |
| 6 渲染 | 随包脚本把图纸渲成 PPTX + SVG + PNG（PDF 进 `output/figures/`） | §4.3 |
| 7 检查 | 随包检查脚本（§4.4），拦下的改到过 | `.ccode/checks/schematic-<图名>.jsonl` |
| 8 冷读 | 看成品尺寸的 PNG，只凭图写「这张图在说什么」，对照 brief 的一句话；再按 facts 逐条对数量、方向、顺序。看不了图的模型如实说没做，这两项交人 | 结果写进核验项（最多「待你判断」） |
| 9 交付 | 图注草稿（写 schematic）、AI 使用披露句、`figures/manifest.json` 登记、报告用了什么、哪里拿不准 | 回复里写出 PNG 完整路径（聊天直接出图） |

深度只分两档：**草稿**（1 个构思、检查脚本通过即交）、**标准**（2–3 个构思人挑、冷读 + 事实逐条核对）。
不做「两稿互评 + 独立评审 agent」的完整档：schematic-figure 作者自测这些几乎不提高质量、只是消错，消错交给检查脚本和人；
Mesa 的拆分也要人批准（并行三层），默认不开。力气花在 1–4 步的规划上。

**规格卡**（`brief.md` 末尾，借 schematic-figure spec card）：要点一句话、尺寸、主角（哪个元素最显眼）、面板（各自职责与占比）、
元素（标签原文、外观、**来源**：画 / 由数据算 / 取自项目文件 / 查实物参考 / 出图模型，附理由——由数据决定形状的元素必须算出来或取真实数据）、
关系（从、到、类型、画法）、约定（配色含义、线型）、不能出现什么。

**标签写法**：期刊示意图的标签是 2–4 个词的名词短语，紧贴所指的东西，解释进图注；一个实体一种颜色贯穿全图，饱和色只给主角；
一个面板一个想法，有明确的入口面板；三维只给几何上有意义的主角。图形摘要、组会大图按用途放宽字数，但同级文字字号统一。

**执行纪律**（借 image-to-editable-ppt）：图纸是唯一的构建源，三份输出只从图纸来；检查不过时只修出问题的那一处，
不为一个无关错误重画已通过的素材；重试前必须改了输入或条件；出图模型的任务按顺序一张张来，同一条件失败过的不原样重发。

### 4.2 图纸（figure.json）

图纸是**和格式无关的版面描述**，三种输出都从它来。大模型擅长写结构化描述，「听得懂人话」就体现在这一步。草图：

```json
{
  "canvas": {"width_mm": 183, "height_mm": 110, "purpose": "graphical-abstract", "lang": "zh"},
  "theme": {"font_cjk": "思源黑体", "font_latin": "Arial", "base_pt": 7,
            "palette": {"primary": "#1F4E79", "accent": "#C55A11", "muted": "#7F7F7F"}},
  "grid": {"cols": 4, "gutter_mm": 3},
  "elements": [
    {"id": "title", "type": "text", "box": [0, 0, 183, 8], "text": "Ni/ZnO 基反应吸附脱硫（RADS）吸附剂设计策略", "pt": 10, "weight": "bold"},
    {"id": "s1", "type": "panel", "box": [0, 10, 44, 60], "fill": "primary-10", "title": "策略一：载体改性"},
    {"id": "s1-icon", "type": "icon", "box": [8, 20, 28, 20], "asset": "assets/zno-support.png",
     "source": {"kind": "image-model", "model": "gpt-image-1.5", "prompt_file": "assets/zno-support.prompt.txt"}},
    {"id": "s1-text", "type": "text", "box": [2, 42, 40, 16], "text": "引入 Al₂O₃ 提高分散度…", "pt": 6.5},
    {"id": "a1", "type": "arrow", "from": "s1", "to": "core", "style": "solid"}
  ],
  "facts_ref": "facts.md"
}
```

要点：

- **坐标用毫米**，按成品尺寸写，不靠缩放凑；字号用 pt。
- **文字只出现在 `text` / `panel.title` / 标注里**，不进图标。
- 每个元素可带 `source`（内置图元 / 项目素材 / 出图模型 / 用户提供），渲染时汇总成披露句与素材清单。
- 箭头、连线按元素 id 连（不写死坐标），挪框时线跟着走。
- 组图（§5.3）也用这份格式：多一种 `figure` 元素，引用外部 SVG / PDF / PNG。

### 4.3 渲染器

随包脚本 `render_figure.py`（Python）读图纸，同时出三份：

| 输出 | 用途 | 做法 |
|---|---|---|
| `<图名>.pptx` | 人在 PPT / WPS / Keynote 里改（国内科研最普遍的改图工具） | python-pptx：文本框关自动缩放、换行由渲染器按字体量好后显式写入（PowerPoint 和本机字体测量不一致时，靠显式断行保证不同软件里一样）；图标是图片，框是原生形状，箭头是原生连接线（连到形状的连接点，挪框线跟着走）；连续的线必须是一条路径，表格是原生表格。python-pptx 不支持的（自定义曲线路径、渐变细节）直接写 OOXML 片段——image-to-editable-ppt 整个都是手写 OOXML，可行性已有先例 |
| `<图名>.svg` | 投稿、Illustrator / Inkscape 里改 | 文字是 `<text>`，指定字体族；图标内嵌 |
| `<图名>.png` | 预览、聊天里看、冷读 | SVG 光栅化（§4.3.1） |
| `output/figures/<图名>.pdf` | 投稿副本（`*.pdf` 不进 git） | 由 SVG 转 |

#### 4.3.1 SVG 怎么变成 PNG / PDF

候选（§11-3）：

- **建议：随包 `mesa_helper svg-render`**，内置 Rust 的 resvg：三平台一致、不要用户装任何东西、读系统字体。
- 退路：本机有 LibreOffice 时用它（`office_view.rs` 已会找）；或 Python cairosvg（Windows 上 cairo 难装，不作主路）。
- 不用无头 Chromium（`schematic-figure` 的路线），普通用户装不齐。

#### 4.3.2 字体

- 中文：思源黑体 / 苹方 / 微软雅黑，按本机有的选，写进图纸 `theme`；英文期刊图：Arial / Helvetica。
- PPTX 换到没有该字体的电脑会被替换：交付时写明用了什么字体；中文默认选三平台都容易有的（思源黑体随 Mesa 文档说明给下载指引）。
- 量字宽用与渲染同一份字体文件（Pillow `ImageFont`），保证检查脚本和渲染器看到的是同一个排版。

### 4.4 检查脚本（gate）

随包 `schematic_check.py`，复用 `mesa_checks.py` 三档写法，结果进评审页核验清单：

| 检查 | 判法 |
|---|---|
| 任意两段文字外框相交 | 拦下（`review-figures` 2026-10-23 已有同类检查，这里按图纸几何算） |
| 文字超出所在框 / 画布 / 溢到别的面板 | 拦下 |
| 成品尺寸下字号低于下限（期刊 5 pt、图形摘要 6 pt、组会 14 pt）；上下标过小 | 拦下 |
| 渲染出现缺字方框 / 字体回落 | 拦下 |
| 规格卡里声明的关系没画、箭头方向与声明相反；箭头两端没连到元素、元素 id 重复 | 拦下 |
| 位图元素在成品尺寸下不足 300 ppi | 拦下 |
| **图上每段文字都能在 brief.md / facts.md 里原文找到**（不在里面的就是没出处的字） | 找不到的拦下 |
| 图标位缺素材、素材不是透明底 | 拦下 / 待你判断 |
| 不是期刊栏宽；字体超过一种；面板编号不是 a、b、c；线宽过细或过粗；文字压在繁杂背景上（像素采样）；单块空白过大；引线穿过别的元素或文字；标签像句子（≥ 6 词、带冒号） | 待你判断（逐条改，或写明为什么保留） |
| 颜色只靠红绿区分、灰度下两类分不开 | 待你判断（附灰度预览） |
| 出图模型元素清单（模型、描述） | 写进核验项，供披露 |
| 冷读是否与一句话要点一致、事实逐条对（数量、方向、顺序、连接、极性） | 永远「待你判断」——检查全过不等于图对（schematic-figure：「Green does not mean good」） |
| 图纸 → 三份输出能重建 | `fig_check` 重跑；字节不同交人目视（同现有口径） |

### 4.5 图元

图标先找**内置图元**（矢量、可改色），再找出图模型。一期只做少量通用件：箭头样式、框、编号圆点、括号、
烧杯 / 反应器 / 电池 / 电极 / 细胞 / 分子球棍等十来个最常用的；按领域扩充放三期（§10），也接受用户把自己的图元库放进项目
`figures/library/`。

## 5. 数据图与组图

### 5.1 `figure-forge` 补三处

1. **可编辑文字默认开**：模板风格里固定 `svg.fonttype: none`、`pdf.fonttype: 42`，主交付 SVG 能在 Illustrator / PPT 里改字。
2. **画前拦误用**：借 scipilot 的 18 条清单，挑与 `figure-forge` 现有规则不重复的写进技能（小样本画均值柱→改箱线加散点、
   双 Y 轴造相关、柱状图截断 Y 轴、分类变量用折线连、连续色阶没有色标、rainbow / jet 色图、饼图与装饰性 3D、
   显著性星号滥用、图例用程序内部变量名）。scipilot 碰到就停下问用户「是否坚持」；Mesa 按「少占注意力」改为：
   **默认按替代画法画，交付时写明换了什么、为什么**，用户明说要原样才照画并在图登记里留一句记录。
3. **画后看一眼**：新增随包 `fig_lint.py`——按成品尺寸渲染一次，同时听 warnings 和 logging 两路抓字体缺字；用渲染器取每段文字外框，
   查标题 / 标签出界、刻度标签相交、字号下限、子图字母是否对齐成线；另存一张灰度预览（Pillow 转灰度）交人看；
   查导出格式（拒 JPEG）与字体是否嵌入。结果进 `.ccode/checks/fig-lint.jsonl`。

Origin（`origin-plot`）维持现状，不再加投入；聊天里同行说的「Origin 有点落伍」与我们的判断一致。

### 5.2 PPTX 出口

数据图在组会、答辩里常要进 PPT：`figure-forge` 交付时可选再出一份单图 PPTX（图是 SVG 嵌入 + PNG 后备，标题和图注是文本框）。
不把数据图拆成 PPT 原生图表——那会丢掉脚本这个唯一可信来源。

### 5.3 组图（拼版）

把自己的数据图、示意图、照片拼成一张 (a)(b)(c) 投稿组图，替代「到 Adobe 里拼」：

- 用同一份图纸格式：每块是一个 `figure` 元素（引用 SVG / PDF / PNG），面板字母、统一字号、栏宽都在图纸里。
- 同一个渲染器出 SVG / PDF / PPTX / PNG；SVG 里矢量块保持矢量。
- 检查：成品栏宽下每块里最小字号（读子图 SVG 的 `<text>` 乘缩放比）不低于下限；面板字母字号字体一致、对齐成线；
  照片块只整体缩放裁切（记录裁切框）；同一实体在各块同色（提示，待你判断）。
- `review-figures/assemble_panels.py` 的「按栏宽卡可读性」思路并进来；文献拼板本身不改，以后再考虑迁到同一渲染器。

## 6. Mesa 里能看见什么

界面只加最少的东西，主要是让已有入口认得这些文件。

### 6.1 项目「科研工具」设置

现有字段「结构 / 装置示意：不需要 / Blender」改为 **「示意图：图纸（PPT / SVG）/ Blender（三维）/ 不需要」**，默认图纸。
选图纸时，挂示意图步（现在是 `exp-design`、`methodology`）自动挂 `schematic-forge`，与 Origin / Blender 同一套挂载
（`research-tools.ts`）。「数值图：Python / Origin」不变。（§11-4）

### 6.2 流程模板

- 科研论文「实验设计」、毕业论文「方法」：挂示意图技能（技术路线图、实验流程图）。
- 科研论文结果分析后：不新增步；`figure-forge` 交付里多一份组图图纸（有多块时）。
- **图形摘要**：做成内置可选步骤（投稿材料步前），也可当任务包加入；读稿件摘要和主结论，出 TOC 图（期刊规格在定档时问清）。
- 开题报告（`proposal-writer`）：技术路线图走示意图技能。

### 6.3 人改过之后

- 渲染器每次在 `figures/manifest.json` 记三份输出的哈希。
- 人在 PPT 里改了（哈希变了）：之后让 AI 改这张图，AI 只用 python-pptx 在这份 PPTX 上做局部修改（改字、挪框、换图标），
  **不从图纸重新生成**；图纸标记为「已被人改过的 PPTX 取代」。人要「推倒重来」时明说，才回到图纸。
- 评审页对已被人改过的图，不再拿图纸重建核对（`fig_check` 跳过并注明「以人改版为准」）。

### 6.4 预览与点图接着改

- 文件页：SVG、PNG 已能预览；PPTX 现在只有逐页大纲——有同名 PNG 且比 PPTX 新时显示它，比 PPTX 旧时提示「预览是生成时的，
  你改过以后的样子请在 PPT 里看」；装了 LibreOffice 的照旧可转 PDF 看。
- 「用 PowerPoint / Keynote / WPS 打开」走系统默认程序。
- 聊天里点图标注、接着改：这张图在 manifest 里有图纸或人改过的 PPTX 时，附件行写「图纸：路径」/「可编辑文件：路径」，
  提示语改为「AI 按图纸改」，不走出图模型在原图上改（`chat-image.ts attachmentLines`）。

### 6.5 依赖

- python-pptx 加进依赖检查与一键安装（`dep_check.rs` 现有 pymupdf / pillow 同一套）。
- Pillow 已有；SVG 渲染随包在 `mesa_helper` 里，不要用户装。

## 7. 已有图转可编辑（补充模式，三期）

用户手上有一张 AI 生成的图、旧图或草图，想「拆开能改」：作为示意图技能的**复刻模式**——

- Agent 看图读出文字内容，写图纸（布局、颜色）；**文字位置和字号由本地脚本量**，不靠模型估（借 image-to-editable-ppt：
  分块二值化切出文字行、按墨迹高度换算字号，中日韩字取 0.95 em，同一级文字聚成一组统一字号）。
- 图标：让出图模型的改图功能把原图里的图标原样拆到一张纯色底素材板上（颜色避开主体，不美化、不加字），
  去底后按人工指定的区域切；区域重叠、贴边、有前景没被覆盖就直接报错，不猜。纯色、渐变背景用原生形状重建，不调模型。
- 渲染后与原图叠图对比，只修对不上的那一处；图标位可用 AutoFigure 的编号占位（`<g id="AF01">`）回填，保证骨架与切出的图标对齐。
- **只给能看图的模型**；看不了图的模型直接说做不了。
- 不接第三方 OCR 服务、不装 SAM / RMBG 本地大模型（密钥外发、装不齐）；以后连接页若接了 OCR 类模型再议。
- 版权：复刻别人已发表的图只作风格参考或附出处，不当原创交付；与 `review-figures` 转载许可同口径。

## 8. 不做

- Mesa 内画图 / SVG 编辑器 / 裁图界面（AutoFigure-Edit 带的 svg-edit 不学）。
- 模型打分门槛（K-Dense 的 8.5 / 10）；任何「质量分」。
- 让出图模型画整张带字的成品当交付（可以当构思阶段的「效果参考图」）。
- 第三方 OCR、SAM3、RMBG、无头 Chromium 这类重依赖。
- 自动选模型、自动套风格；不自动推荐图形摘要步。
- 冒充实验数据的图；对照片做非整体的像素修改。

## 12. 参考机制摘录

2026-11-05 经 `gh api` 读源码所得，只记对 Mesa 有用的机制与出处，供实现时回查。

### 12.1 `lgwrightlab/schematic-figure`

- 11 步（`reference/process.md`）：brief → 规格卡（2–3 方案留一）→ 每个元素定来源（画 / 算 / 取 / 查 / 渲染）→ 查实物参考图（只看不嵌）→
  文字（标签 2–4 词，解释进 `caption.md`）→ 缩略图排版 → 逐面板画、每块渲染看图改 → gate → 忠实度核对 + 自评 → 冷读 → `--final` 交付。
- gate（`foundation/tools/check.mjs`）：FAIL 为字号低于下限、文字相交、出页、超高、位图 ppi 不够、声明的关系没画或方向反；
  WARN 为非栏宽、中位字号过小、多字体、上下标过小、字密度高、标题成句、标签像图注、面板编号、线宽、文字压繁杂背景（像素采样）、
  大块空白、文字溢出面板、引线穿越、没有主角。`--final` 要求每个上屏字符串都能在 `facts.md` 原文找到。
- 规格卡（`templates/spec-card.md`）：Takeaway、Size、Hero、Panels、Components（标签原文 / 外观 / 来源及理由）、Relations、Conventions、Negative constraints。
- 原则（`reference/principles.md`）：P12 一面板一想法；P15/P16 一实体一色、饱和色给主角；P18/P31 直接标注、名词短语；
  P22 比较同轴；P23 示意数据结构对、精度不过实；P25 三维只给几何主角；P28 画本文实例不画教科书版；P29 只画手上有的数字。
- 作者基准：去掉规划掉 6.8 分；双稿、critic、gate 对盲评几乎无影响但消错。

### 12.2 `ningzimu/image-to-editable-ppt-skill`

- 父 agent 只编排，每页一个 worker；状态只经 `editppt` CLI 推进，manifest 是唯一构建源。
- 每页顺序（`references/page-decision-tree.md`）：盘点 → 背景 → 前景素材 → 原生元素（文字 / 表格 / 形状 / 公式）→ 自检。
- 文字（`runtime/text_hints.py`、`page_text_metrics.py`）：本地分块二值化 + XY-cut 切行、量墨迹高；字号 = 墨迹高 / em 比例
  （中日韩 0.95，拉丁 0.5–0.95）；同级聚成 `size_group` 统一字号；标 `font_size_source: measured` 后构建器不再打折。PaddleOCR 可选。
- 素材板：改图模型把图标拆到纯色抠图键底的稀疏素材板；`remove_chroma_key.py` 软 alpha + 去溢色；`split_alpha_components.py`
  按指定区域切，重叠 / 贴边 / 漏覆盖直接报错；无降级路径。纯色、渐变背景原生重建，不调模型。
- pptx 不用 python-pptx / PptxGenJS，zipfile 手写 OOXML；连续线必须单一路径，表格必须原生。
- 记录前校验（`validate_pptx.py`）：manifest 能独立重建该页；禁止「整页截图 + 叠文字」；圆角半径有源；拿真实 slide XML
  比线条数量与几何、表格结构、必需文字。失败只修出问题的产物，重试必须改条件。

### 12.3 `ResearAI/AutoFigure-Edit`

- 流程（`autofigure2.py`）：生图模型出整图 → SAM3 框图标 → RMBG 去底 → 多模态模型写占位版 SVG → 回填图标。
- 占位 label 模式：标注图上每个图标盖灰框写 `<AF>01`，要求 SVG 输出 `<g id="AF01">`，回填按 id 换成 `<image>`；
  找不到按缩放坐标、再按 ±10 px 灰框兜底。模板提示：viewBox 等于原图尺寸、只输出 SVG；lxml 校验失败把报错交回模型修；
  optimizer 拿原图 / 标注图 / 当前渲染 / SVG 代码按「位置、样式 × 图标、文字、箭头、线条」八点比对。文字是 `<text>`。

### 12.4 `Haojae/scipilot-figure-skill`

- `visual_qa.audit_layout`：渲染一次，warnings + logging 两路抓「missing from font」（FAIL）；`get_window_extent` 查标题 / 标签出界、
  相邻刻度标签相交（WARN）；只量不改。
- `references/viz_pitfalls.md` 18 条：均值柱、双 Y 轴、饼图与 3D、截断 Y 轴、连续色阶无色标、离散点连线、颜色过多、
  图例缺失或用内部名、误差类型未交代、chartjunk、分辨率格式、一图多论点、红绿 / 色盲、rainbow / jet、显著性符号滥用、
  缺字、文字裁切与图例遮挡、子图编号不齐。
- `export_figure`：pdf / svg / eps / png / tiff，拒 JPEG；强制成品尺寸；`pdf.fonttype=42`、`svg.fonttype="none"`；灰度预览 PIL `convert("L")`。

### 12.5 `dwzhu-pku/PaperBanana`

- Critic（`agents/critic_agent.py`）：内容维度（忠于方法与图注、不臆造、文字核对、图里不放图注）与呈现维度（清晰、冗余图例）；
  写「No changes needed.」即停。
- Stylist：风格指南由脚本让模型分批读约 50 张 NeurIPS 2025 论文图归纳成「按领域的多种可接受选项」；改写只动美学不动语义。
  对应本稿三期「课题组风格档」：从用户项目已有的图归纳，而不是套 AI 领域的风格。
