## 0. 一句话

科研里有些判断不该只听一家：这个方法站不站得住、这段结论有没有说过头、这条审稿意见该接受还是反驳。
研讨让你把一个问题连同材料交给二到四家 AI，**第一轮各答各的、互相看不见**，再亮出彼此的答案让它们补充或反驳一轮，
最后由你决定记下什么、要不要派活。研讨只看不动：不改文件、不跑命令，要动手就交给已有的派活单。

## 1. 参考：ClawChat 怎么做，Mesa 取什么

ClawChat 把 Claude Code、Codex、Gemini、Grok、Cursor 以及借 Claude Code 跑的 DeepSeek / GLM / 任意 OpenAI 兼容平台拉进一个群，
共用一个项目文件夹。调度核心在 `lib/hub.js`（谁接话、接力、轮数上限、停止）。

| ClawChat | 做法 | Mesa 取舍 |
|---|---|---|
| 群 + `@` 点名、`@所有人` | 输入 `@` 弹成员菜单；只有被 @ 的才被叫醒 | **取**。研讨里追问用 `@某家` / `@所有人` |
| AI 互相 @ 接力 | 人不说话时连续接力到上限就停，等人发话（默认 25 轮，`store.js maxAutoTurns`） | **取，上限压低**：默认 2 次，可调 0–6。研讨是为了让人判断，不是让几家自己聊到天亮 |
| `[PASS]` | 跟自己无关或没有新东西就只回 `[PASS]`，群里不显示 | **取**。交叉轮和接力里没补充的不占版面，记录里留「没补充」 |
| 动手权限三档（项目内放手干 / 完全放开 / 只读讨论） | 每个群单独设 | **只取只读**。改文件走目标 / 步骤的隔离副本和评审，研讨不开第二条写路 |
| 私聊（`<私聊老板>`、AI 之间 `<私聊 X>`） | 用标签把话只发给某一位 | **不取**。要人回答的事走人工请求（`.ccode/help-wanted.md`），AI 之间不需要背着人说话 |
| 分身 | 本体忙时复制会话开只读分身回话 | 研讨不需要（每轮都是新的无头调用，没有「忙着的本体」）；作为独立小改动见 §10.2 |
| 换新会话时请另一位 AI 交代 | 三选一：AI 交代 / 带最近 40 条 / 我自己交代 | Mesa 已有「换 Agent」接力简报，不重复 |
| 联合群（经 Tailscale 和同事的 AI 同群、Touch ID 确认传文件） | 跨机器、跨主人 | **不取**。违反「跨项目不直连」，安全面太大 |
| 气泡配色、消息朗读 | | 不取（朗读已否） |

ClawChat 没有、Mesa 要加的：**第一轮互相看不见**（防后答的跟着先答的走）、**依据必须能定位到文件**、**结论由人记**。

## 2. 和已有功能的分工

| 已有 | 管什么 | 研讨和它的关系 |
|---|---|---|
| 跟 AI 商量一下（步骤卡、聊想法、问 AI） | 和**一家** AI 聊课题内容，能接着在原对话里干活 | 研讨是「商量」的多家版。一家能聊清楚的照旧用商量 |
| 项目助手 | 问项目和 Mesa 的运转：进度、报错、规划；起草派活单 / 补料单 | 不重叠。项目助手判断你在问一个需要几家意见的内容问题时，给按钮「找几家研讨」（预填问题）；研讨要动手时，把研讨记录交给项目助手起草派活单 |
| 跨厂商复核（评审页「请另一家复核」） | 一家逐条核对稿件里的引用是否被原文支持，结论进核验记录 | 不合并。复核是**有固定对象的核验**，结果进 `.ccode/checks/`；研讨是**开放问题的讨论**，不产核验结论 |
| 留话（`mesa_helper tell`） | 同项目两段工作之间传话 | 不重叠。研讨成员不是在干活的工作，不收也不发留话 |
| 拆成几路做 | 出拆分方案、人批准一次开齐 | 不重叠。研讨不拆活 |
| 换 Agent / 接力 | 一段对话换一家接着做 | 不重叠 |

**为什么不做 ClawChat 式自由群**：11-03 的协调对话已经因为「为了协调另开一段对话没必要」并回工作台（`design-project-coordination.md` §11）；
项目助手是问进度的唯一入口；群里的 AI 能写文件、互相派活，就绕过了隔离副本、评审和「AI 提议、人批准一次」。
剩下真正需要「一屋子 AI」的，只有要几家各自判断的内容问题，这就是研讨。

## 3. 规矩（写死在提示词，Mesa 兜底）

1. **只看不动**：成员只能读项目里的文件，不改文件、不跑命令、不联网、不调 MCP。能读项目的那几家走进程级只读（§5.2），其余几家只看 Mesa 附上的材料。
2. **先各答各的**：第一轮所有成员同时作答，提示词里没有别家的答案；Mesa 等这一轮全部回来（或单家超时 / 被停）才一起亮出来。
3. **再交叉一轮**：亮答案后自动进交叉轮。每家拿到其他几家第一轮的回答，只写补充、反驳或改判；没有就回 `[PASS]`。交叉轮数默认 1，发起研讨时可选 0–2。
4. **接力有上限**：之后 AI 回答里 `@` 别家会叫醒对方，但你不说话时最多连续 2 次（可调 0–6），到了就停，写一句「先停一下，等你发话」。你说一句话计数清零。
5. **回答格式固定尾段**：每条回答末尾三行——`结论：`一句话；`依据：`项目内相对路径加位置（行号、页码或章节），可多条；`没把握的：`可空。
   Mesa 只做两件事：把各家「结论」并排成对照条；把「依据」里的路径查一遍，不存在的标「找不到这处」。**Mesa 不判谁对、不投票、不出共识、不打分。**
6. **差别看模型族，不看 CLI**：研讨要的是几种互相独立的判断，判断的差别来自模型——训练数据和偏好不同，盲区才不同。
   同一家的几档模型（Claude 的 Opus / Sonnet / Haiku，GPT 的大小两档）盲区相近，三位一起答接近一票；同一个模型换个 CLI 外壳更是同一票。
   反过来，同一个 CLI 外壳接不同家的模型（Claude Code 分别接 Claude、GLM、DeepSeek、Kimi）是**几家**，而且读材料的工具一样，差别更干净地落在判断上。
   所以「同一家」一律按模型族判（`cross-review.ts modelFamily`，与跨厂商复核同口径）：两位成员同族时，发起研讨和成员胶囊上都标「同一家模型，意见可能雷同」，不拦——
   有时你就是想看大小模型答得差多少，只是那不算研讨。
7. **不替人拍板**：结论只由你记（§4.4）；不替你回答人工请求、决策项，不建议换模型（「Mesa 不替人自动回答」「不做模型路由」照旧）。
8. **只认这个项目**：材料只能是这个项目里的文件；记录不出项目，别的项目看不到。

## 4. 一次研讨怎么走

### 4.1 发起研讨

入口（原写「不在步骤卡上加按钮」，**2026-11-11 用户拍板改掉**：要人拍板的步骤正是研讨最有用的地方，且只占「继续讨论 · TASK.md」同一行一个文字链接、不抢右缘主动作）：

- **步骤卡**：role 为 you / both 的步骤，「继续讨论 · TASK.md · 请几家研讨」同一行（`StepFlow` 的 `discussInline` 槽）；role 为 ai 的不出。
  问题预填「照现在的 TASK.md 做下去，哪些方向或判断站不住、最该先定哪一件」，材料 = 这一步的 TASK.md + expectedArtifacts 里已存在的（`consult_existing_files` 筛，按弹层上限截）；
  步骤开着工作副本时读工作副本（同评审页 `readRoot` 口径），记录写项目根。同日「＋ 话题」收掉，见 step-panel.md R5。

- **对话页**：列表栏头 **研讨**（对话页栏头原本没有「新对话」下拉，落地时改放这里）。
- **对话回放头部 ⋯ 菜单**：「请几家研讨这个问题」——当前对话里你最后一句话作问题、这段对话作材料。
- **项目助手**：回答里的动作标记 `研讨`（白名单加一项），预填问题和它点到的文件。
- **评审页**（一期已做，§11-4）：科研写正文的步骤，「基础检查」那一行「请 X 复核」旁加 **请几家研讨**，问题预填「这一步交的东西里哪些论断站不住」，材料 = 这一步要交的文件；
  成员读这一步的**工作副本**（`readRoot`，产物还没带回项目根），记录照样写项目根。评审页没有 ⋯ 菜单，按同一行的文字按钮口径放。

弹层一屏填完：

| 栏 | 内容 | 默认 |
|---|---|---|
| 问题 | 一句到一段话 | 入口预填 |
| 材料 | 项目里的文件（可写行号范围 `12-40` 或章节 `§2.4`）；贴图二期 | 入口预填；最多 8 份；摘录单份 1.6 万字、合计 4.8 万字封顶 |
| 成员 | 二到四位，每位 = 连接 × 模型（与复核下拉同一份 `reviewerOptions`），卡片上写模型族、经哪个 CLI、「能看项目」或「只看材料」 | 见下方「默认挑法」；记住上次选的 |
| 交叉 | 0 / 1 / 2 轮 | 1 |
| 预估 | 成员数 × (1 + 交叉轮数) 次调用（一期只写次数，按历史估钱二期） | 只显示，不拦 |

**默认挑法**（没有上次的选择时）：

1. 第一位是「问 AI / 聊想法」那条连接与模型。
2. 之后每一位**先保证模型族和已选的都不同**；同族的不进默认。
3. 同一个模型族有几条连接可选时，**优先 CLI 外壳能看项目的**（§5.2：Claude Code、Codex 外壳），其次一等 Agent，再其次最近用过的。
4. 凑不满三个不同模型族就少选，不拿同族的补；只挑得出一族时弹层写「只配了一家模型，研讨意义不大」，仍允许你手动加。

这样默认组合多半是「Claude Code 外壳 + 三家不同的模型」，几位都能看项目。不按问题内容挑模型（「不做模型路由」照旧），只按上面的固定次序。

主按钮「开始研讨」。

### 4.2 第一轮：各答各的

- 所有成员同时开跑，每家一张卡片**并排**（窗口够宽三列，否则两列，再窄纵向），卡头写成员名（模型族）、模型、经哪个 CLI、「能看项目 / 只看材料」。
- 进行中显示「正在看 `methods.md`」这一类过程摘要（来自流式事件，只给读了哪个文件，不给内容）；每张卡有「停止」。
- 有人先答完时，**它的卡片只显示「已答完 · 等其他几家」，内容先不展开**（防止你先读了一家就带着它的看法读别家）。全部回来后一起展开。
  这条是待拍板项（§11-2）：也可以先答完先看。
- 单家 240 秒没答完按超时处理（同 `INSPECT_TIMEOUT`），卡片写「超时，没答」，不挡其他家；出错的写一句白话原因加「重试这一家」。

### 4.3 亮答案、交叉、追问

- 第一轮卡片下面出现**结论对照条**：一行一家，左边成员名，右边它的「结论」原话；「依据」里找不到的路径标黄。Mesa 只排版、不加评语。
- 交叉轮的回答按普通聊天流排在下面，每条开头写「回应 GPT」「回应 Claude」这类，由成员自己 @ 出来；`[PASS]` 的不显示，在对照条那一家后面加小字「交叉：没补充」。
- 你随时可以在下面的输入框说话：`@GPT 你说的样本量不足依据在哪` 只叫那一家；不 @ 就是 `@所有人`。输入 `@` 弹成员菜单。
- 停止：单家停在它的卡片 / 消息上；输入框右边「全部停止」。

### 4.4 收尾：只由你记

每条回答悬停出现三个动作，研讨顶栏有「收尾」菜单：

- **记进项目知识**：打开项目助手同一张 `RememberCard`，预填这条回答的「结论」，你改写后点「记进项目知识」才写进「已定 / 不做」。一次只记一条，不批量采纳。
- **起草派活单**：把这次研讨的问题、对照条和你选中的那几条回答交给项目助手（作为本次重点），由它起草派活单；派不派你在项目助手里点。研讨自己不出派活单。
- **复制**：Markdown 原文。

研讨结束不需要「关闭」：没有进行中的调用时它就是一份记录，可以接着追问。

## 5. 每家怎么跑

### 5.1 一轮一次无头调用，不续 CLI 会话

- 每位成员每次被叫到 = 一次一次性无头调用；**记忆就是 Mesa 拼的研讨记录**，不续 CLI 自己的会话。
  理由：①只读无头已经验证过的路径都是一次性的（Claude Code `--no-session-persistence`、Codex `--ephemeral`）；②一次性内部调用不落盘（AGENTS.md）；
  ③第一轮「互相看不见」要求提示词完全由 Mesa 控制，续 CLI 会话做不到。
- 代价是每轮都要重读材料、重付上下文。缓解：提示词里先放研讨开场（规矩 + 问题 + 材料摘录），记录超过长度上限时，先把最早的交叉轮全文换成各家「结论」一句。
- 每家每次调用照无头调用记账（`record_ephemeral_usage`），归在用量页「内部活动」之外——研讨是你主动开的，算正常用量，按成员所用连接记。（待拍板 §11-5）

### 5.2 能看项目 / 只看材料

档位**按成员那条连接的 CLI 外壳定，与接的是哪个模型无关**：只读靠的是 CLI 的进程级参数（Claude Code 的工具白名单、Codex 的只读沙箱），
对任何模型都一样生效。所以 Claude Code 接 GLM、DeepSeek、Kimi 模型的 API 连接，一样能看项目。

| 档 | 哪些连接 | 怎么跑 |
|---|---|---|
| 能看项目 | CLI 外壳是 Claude Code、Codex 的连接，不论模型（一期）；Kimi CLI 外壳在一期内实测后加 | `ai_inspect_readonly`：工作目录 = 项目根，进程级只读（Claude Code `--tools Read Grep Glob --strict-mcp-config`，Codex `-s read-only`），提示词里点名材料路径，让它自己读，也可以顺着依据去翻别的文件 |
| 只看材料 | 外壳是其余几家 CLI 的连接 | `ai_prompt` 在临时目录跑（不碰项目）；Mesa 把材料摘录贴进提示词，有总长度上限；提示词写明「你看不到项目文件，只能依据下面的摘录，依据写摘录里的路径和位置」 |

- 成员卡片和发起研讨弹层都写明是哪一档；「只看材料」的成员提的依据如果超出摘录范围，Mesa 照样查路径存不存在，并标「它没看到这份文件」。
- 贴图：看图看的是**模型**（`model_registry` 的 vision，`model_supports_vision_for`），认不出的按看不了。能看图的模型、外壳又能看项目时走 `image_prompt_note` 同一套（Codex `--image`、Claude Code 点名路径 Read）；其余情况卡片上写「图没给它看」。
- 同一个外壳接别家模型要留意两件事：①有的模型调用工具弱，不会自己去翻文件，只凭提示词里那点东西回答——依据核对（§3 第 5 条）能暴露，挡不住；提示词里把材料路径点名、要求先读再答。②思考档位的线协议各家不同（如 GLM 的 effort），一律沿用连接页已有的注入规则，研讨不另设。

### 5.3 调度

- 第一轮并发（最多 4 家）；交叉轮并发（彼此看的都是第一轮，互不依赖）；之后按 `@` 的先后串行，同一条消息 @ 了几家就并发。
- 接力计数按研讨记，你发一句话清零；到上限写系统提示一句，不再叫醒。
- 停止走 `kill_process_tree`，被停的那次记「你停了」，下次叫到它时提示词里写「上次被你停了」。
- Mesa 关着时研讨不跑（长循环不进前端：调度写在后端，`consult.rs`，见 AGENTS.md「终局方向」）。

### 5.4 成员名与 @

- 成员显示名 = **模型族名**（Claude、GPT、Gemini、GLM、DeepSeek、Kimi…，与 `vendor-icon` 同一份），不用 CLI 名——三位都经 Claude Code 时按 CLI 起名分不开。
  同族两位时加短模型名区分（Claude·Opus、Claude·Sonnet）；认不出模型族的用连接名。经哪个 CLI 写在胶囊小字里，不进名字。
- 成员标记跟模型族走：用 `vendor-icon` 的厂商图标（认不出的首字占位，与连接页同口径），不用 CLI 的 `AGENT_BRAND` 色；不为研讨另起一份颜色表。
- `@` 只认本研讨的成员名和「所有人 / 大家」；回答里 @ 了不在研讨里的名字当普通文字。

## 6. 界面（见 `docs/design-group-consult-mockup.html`）

## 8. 不做什么

- 不写文件、不跑命令、不联网；不开「项目内放手干」「完全放开」档。
- 不做 AI 私聊、分身、跨项目、联合群。
- 不投票、不出「共识」、不打分、不自动采纳任何结论。
- 不自动发起研讨（事件规则、定时任务都不能开），不自动把结论写进任务书或项目知识。
- 不按问题自动挑成员或模型（只记住你上次的选择）。
- 不替代商量、复核、项目助手。

## 10. 同批可做的三处小改动（同样借自 ClawChat，和研讨无依赖）

1. **留话接力上限**：`project_mail.rs` 现在只限单条 2000 字，两段工作互相 `tell` 没有次数上限。照研讨同一条规则：人不在工作台操作时，同一对工作之间连续自动送达超过 N 条（默认 4）就停送，
   工作台「同项目留话」那一行写「它们来回了 4 次，等你看一眼」，你点「接着送」才恢复。
2. **问正在干活的那段一句**：任务面板里一段工作正在跑时加「问它一句（不打断）」：用原生分叉（`pty.rs fork_session_id`）在临时目录以只读无头起一份它当前会话的副本回答你，答完丢掉；不进它的会话、不打断本体。
   一期只做 Claude Code / Codex。
3. **Codex 会话里图片太重的提醒**：ClawChat 实测 Codex 会把看过的每张图原样存进会话、每轮重发，8MB 起变慢、超过 17MB 几分钟没反应。
   Mesa 的做图步骤正好会让 Codex 反复看图，但 `ContextRing` 不算图片体积。在上下文用量圈上加：会话里图片累计 8MB 变橙、13MB 变红，点开说明并给「换新会话接着做」（走已有接力简报）。阈值待在 Mesa 里实测。

## 11. 拍板结果（2026-11-11，用户「研讨吧……其他按你推荐」）

1. **名字**：定为 **研讨**（用户：「会诊」偏医疗，不像科研）。已进说明书 §14.1；不说「会诊」「群聊」「群组」。
2. **第一轮先答完的能不能先看**：照推荐，**全部回来再一起展开**；要等最慢的那家（能看项目 240 秒、只看材料 120 秒上限，可单家停）。
3. **交叉轮默认 1 轮、接力上限默认 2 次**：照推荐。
4. **评审页要不要放入口、要不要和多家评审结合**：用户交我决定。定为一期就放（评审页那一行的文字按钮「请几家研讨」），与「请 X 复核」并存不合并：
   复核是一家逐条核对引用、结论进核验清单（`.ccode/checks/`）、在终端标签里跑、会写一个文件；研讨是开放问题、几家只读各判、记什么由人定。合并会让复核的结论口径（四种判定、待你判断）和研讨的自由讨论混在一处。
5. **研讨花费算不算内部活动**：照推荐不算。
6. **成员上限 4 家**：照推荐。
7. **§10 三处小改动**：这一期没做，留着另排。

## 13. 验收清单（落地时逐条过）

- 记进项目知识只经人点，写进的是你改写后的那句；起草派活单落到项目助手、派不派由人点。

## 15. 一期收尾（2026-11-11）

- **被打断的成员**：每位开答先往记录写一行占位（status=running），答完同 id 覆盖；读出时占位对应的调用不在了（Mesa 中途关了）就标「被打断了」，卡片上给 **重试这一家**。没跑完的交叉不自动补。
- **真跑**（`consult.rs consult_real_run`，`#[ignore]`，环境变量开；调度改成经事件回调 `Sink`，测试不用起窗口）：临时项目在主目录下，成员读「工作副本」目录（`read_root`），记录写项目根。
  - Claude Code + GLM、Codex + GLM 各直调一次：都读完三份材料，尾段三行拆对，依据全部核对为在；问题里诱导建 `hack.txt`，两家都没建（文件不存在）。
  - 两个 Claude Code 外壳接不同家模型（GLM、DeepSeek）走完整调度：第一轮并发 → 交叉 1 轮（互相 @、指出对方没看到的点）→ 人 @所有人追问 → 互相 @ 接力 1 次 → 到上限写「先停一下，等你发话」→ 停单家记「你停了」。
  - 真跑查出并修了三处：①Claude Code 2.1.3xx 的 stream-json 在 result 之后多一行 task_summary，只看最后一行会把每次只读调用都判成失败（项目助手只读查看同样受影响，`ai.rs parse_oneshot_output`）；
    ②开场写「不运行命令」，Codex 就一份材料都不读（它靠 shell 命令读文件），改成只禁改动类命令；③依据写成「（路径）」时括号被算进路径。
  - 没跑通的两条都是环境：Claude Code 官方账号登录过期；Codex 官方账号没写模型时沿用 `~/.codex/config.toml` 里的 `deepseek-v4-flash-0731`，ChatGPT 账号不认（项目助手只读查看同样会撞，另记待查）。
    Codex 在调度子线程里跑不了是测试替身（真实配置替身是线程局部）造成的，正式应用读磁盘不受影响；Codex 直调已通。
- **Kimi Code 外壳只读实测**（2.5.2）：`-p` 与 `--plan` 不能同用（「Cannot combine --prompt with --plan」）；`-p` 默认不问就建文件、跑命令。没有只读的一次性调用，维持「只看材料」。
