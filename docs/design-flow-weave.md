# Mesa 设计稿：流程贯通——从哪一步都能回头，回头一次跟到底

> 状态：**已拍板**（2026-11-06，用户「按这个方向做」）。按 §8 逐项落地，落地与设计不同处在对应节补写。
> 规则摘进 pipeline.md「综述回路」节，决策记录见 architecture §10 同日条。
> 前作：`docs/design-review-loop.md`（2026-11-05，退回补料、跟进上游、轮次留痕）。本稿在它上面把回路从「几条要人逐步去点的回头线」做成贯通的。

## 0. 一句话

论文是反复打磨的：经常要回去补文献、补精读、改大纲。前面几步不是一次过的关卡，而是围着几份会一直改的资料
（文献库、笔记、大纲、稿件）轮流干活。步骤保留——它定的是「这类活由哪个 AI、按什么规矩做、做完谁评审」——
但人不该被钉在线上：从哪一步都能回头，回头时 AI 拿到的是项目最新内容，回头一次能顺着下游跟到底，全局一页看得清。

## 1. 起因与原话

一位用户试用英文综述后的反馈（2026-11-06 转述）：「每一步直接没办法互相循环交互」「第三步发现要改，需要反馈给第二步去对应的调整，
甚至反馈给第一步」「第一步的对话能自动去找二三步新生成的笔记和大纲来对应找文献吗」「能通过和它聊天去告诉它，让它参考第二步或者第三步
最新的结论或者大纲对应的去做一些事情吗」。用户：「也不用他的说法当作宗旨，主要是进行正确合适的完善」「有一个可以掌握全局的感觉，
而不是被步骤钉死。论文是一个不断打磨的过程，我之前想简单了，经常要回去补充文献、精读笔记、修改大纲」。

## 2. 现状（已核对代码）

| 情况 | 现在 |
|---|---|
| 回头的入口 | 只有已保存步骤上的「退回上一步补料…」会先把项目最新内容并进上一步（`TaskCardsSection syncForRound`）。「继续」「新开一轮」、项目助手派活给第 N 步（`assistant-dispatch.ts sendToWorkspace` 只接回上次对话）、在原对话里直接说，都不并入——那一步的 AI 手里还是它上次的文件 |
| 回头之后 | 下游每一步要人去点「跟进上游的新增」，各自确认规模、评审、保存 |
| 半路发现问题 | 退回入口只在已保存时出现：发起步要先把半成品保存进项目 |
| 「待跟进」判定 | `stale_upstream_for`：上游保存时间晚于本步「最后保存 / 跟进」时间。本步没并入就保存，保存时间就把待跟进盖掉（这正是只许保存后退回的原因） |
| 全局 | 各份资料基于上游哪一版、落后什么，只散在步进器的「待跟进」小字与回路提示一行里 |

## 3. 任何入口先并入项目最新内容（§8-1）

开任何一轮之前——「继续」「新开一轮」、退回补料、跟进、项目助手派活接回那一步——都先看这一步的工作副本有没有落后于项目：

1. 算「要并进来的」：工作副本到项目最新之间改过的文件（`workspace_incoming`，`git diff --name-only HEAD...基准`），
   滤掉过程文件（`.ccode/`、积累台账，同 `followupFiles`）。为空就不并。
2. 不为空：AI 正在干活或等确认时不并（并入会改它手下的文件），提示等它停下；工作副本有没提交的文件先点名问「一起提交，继续」
   （同 `commitLeftovers`）；然后 `workspace_sync_base`。冲突时停下，指去那一步「去处理冲突」。
3. 并入后记一行 `step-rounds.jsonl`（kind=`sync`，不算一轮），开场指令末尾附「项目里新并进来的内容：文件清单（最多 30 个）；跟本步有关的照着用」。
4. 项目助手派活时那一步的 AI 开着：停在提示符上的，同样先并入再留话（留话里附清单）；正在干活的不并，留话里写明
   「你的工作副本还没并入项目最新内容，这一轮做完停下，我会在 Mesa 里点『继续』并进来」。

**「待跟进」改按「最后一次并入」判**（`stale_upstream_for`）：本步的进度时间 = 工作副本建立时间与各次并入（sync / 补料轮 / 跟进轮 / 新开一轮 / 跟进确认无事 ack）里最晚的那个；
**本步自己保存不算并入**。上游保存时间晚于它 → 待跟进。这样本步没并入就保存，照样提示跟进；而任何入口并入过，提示自然消掉。

## 4. 说一句话就能回头（§8-2）

项目助手多一种卡片：补料单。你在项目助手里说「按新大纲第 3 节补文献，顺着那两篇综述找」，它起草：

```
:::补料
退回到：第 1 步
从：第 3 步
要补：§3.2 失活机理：近三年原位表征工作
为什么：这节能写进正文的只有 2 篇
线索：顺着 [@Wang2023]、[@Li2024] 两篇综述的参考文献找（可省）
规模：10（可省）
:::
```

卡片列出各栏和「补完后接着跟进」的下游（§6），**人点「退回去补」才发**——走的就是步骤卡上退回补料的同一条路（并入、补料单、开轮、记轮次、链）。
项目助手仍不写文件、不替人拍板：它只起草，退回目标与内容人在卡片上看清再点。退回大纲、初稿这类不找文献的步骤，卡片与指令都叫「修改」（同步骤卡）。
普通派活交给第 N 步照旧，只是接回前按 §3 并入。

## 5. 做到一半也能回头（§8-4）

退回入口从「只在已保存时」放宽到**这一步开过工就有**（进行中、待评审、已保存都可以）。发起步自己不动：它的 AI 可以接着干别的，也可以先停下。
上游补完、保存进项目后，按 §3 的新判定，发起步亮「待跟进」——进行中的步骤在「AI 干活」行写「上游「X」补完了，点「继续」会先把新内容并进来」，
已保存的照旧给「跟进上游的新增」。原先「只许保存后退回」的理由（保存会盖掉待跟进）由 §3 的判定改法消掉。

## 6. 回头一次，一条链跟到底（§8-5）

补料单上列出这次会牵动的下游：退回目标之后、开过工的步骤，默认全勾，人可去掉（「补完后接着跟进：☑ 精读 ☑ 大纲 ☐ 初稿」）。存进补料单的 `chain`。

- 目标步保存进项目后，链上下一步**自动开「跟进上游的新增」**：不再弹规模确认（发补料单时已确认过一次），规模 0 记 ack、直接往下走。
- 每一步照旧去评审、保存；保存后链再往下一步。**不跳过评审，不自动保存。**
- 链断了（那一步 AI 正在干活或等确认、有没保存的产出、冲突、开不了对话）：不硬开，那一步留「待跟进」，回路提示指过去；人处理完点跟进，链从这一步接着走。
- 只在 Mesa 开着、看见那次保存时自动往下走；Mesa 关着期间保存的（或别的窗口保存的），回路提示写「链上下一步：去『X』跟进」，不在打开项目时突然开终端。
- 同一步不重复开：`rework_chain_claim` 在补料单里原子地记「这一步已在链上开过」，两处同时看到保存也只开一次。

拍板记录：推翻 2026-11-05「跟进逐步点、一次批准一路跟进不做」（design-review-loop.md §13-2）。

## 7. 全局一页：资料全貌（§8-3）

项目页流程线上方一块（流程有两步以上开过工才出，空节点不出现），一行一份资料：

| 资料 | 现状（Mesa 从文件机械数） | 跟上游对齐没有 | 动作 |
|---|---|---|---|
| 文献库（检索那步） | 纳入 M 篇（综述 a / 研究 b）· 有全文 K | — | 去这一步 |
| 笔记（精读那步） | 精读 x · 只速读 y · 没读 z | 落后于「文献检索」11-06 那次保存 | 跟进 |
| 大纲 | 定框架 k/6 · 薄节 n | 已对齐 | 去这一步 |
| 稿件（初稿 / 定稿） | 有 / 没有 | 基于上一版大纲 | 跟进 |

再加正在进行的回头：「补料单：综述大纲 → 文献检索（11-06 发出）· 在补 / 已补完，链上下一步：精读」，可「停掉这条链」（只停自动往下，补料单与已开的轮不动）。
行与列都按步骤与技能槽认（引擎不认综述），模板不同时有几行写几行；数字只从文件数，不靠 AI 自述（同 design-review-loop §12）。

> **落地与设计不同（2026-11-06）**：「动作」列只留点步骤名跳过去，不在全貌里另放「跟进」按钮——跟进、退回都在步骤卡上（step-panel「主路径唯一」）。
> 有没跟上的或在途的回头时默认展开，都对齐时折成一行（`overviewSummary`）。

## 8. 落地顺序（一项一个提交，文档同提交）

1. §3 任何入口先并入 + 「待跟进」改按最后一次并入判
2. §4 项目助手补料单
3. §5 做到一半也能回头
4. §6 一条链跟到底
5. §7 资料全貌

（拍板时说的顺序是 1 → 2 → 资料全貌 → 4 → 5；资料全貌要显示在途的回头与链，放到最后做最省返工。）

## 9. 不做

- **不把前三步合成一个工作区**：AI 能实时看到彼此，但丢了每步评审、每步换不同 AI、精读分路。
- 不让步骤之间靠「互相留言」传话：留言服务同时开着的几件活；顺序步骤靠文件和回头入口。
- 不让 AI 自己决定回头；不自动保存；不在 Mesa 关着时自动开活。
- 不依赖各家 CLI 自带的跨对话记忆；记忆统一在项目知识。

## 10. 验收

按「动真实数据先干跑」：在 HER 项目上走一遍——检索、精读第一轮保存 → 大纲做到一半从项目助手说一句发补料单（勾上精读、大纲跟进）→
检索补料轮保存 → 精读自动跟进、只读新篇 → 保存 → 大纲自动跟进、只改相关节 → 资料全貌各行对齐。核对：已有笔记字节不变；
「待跟进」在没并入就保存时仍亮；链断一处能从那一步接着走。
