# Mesa 设计稿：综述前三步的回路——检索、精读、定框架来回走

> 状态：**已拍板**（2026-11-05，用户「按推荐拍板」，§13 六项全部按推荐定）；按 §15 分三期落地，落地与设计不同处在对应节补写。
> 以后要守的规则摘进 pipeline.md「综述回路」节，决策记录见 architecture §10 同日条。
> 起因：一位用户试用综述流程（课题「甲醛储氢」）后的反馈，原话摘录见 §1。
> 现状部分（§2）已对照代码核对；「已核对」指读了代码和模板，**没有在界面上点验**。

## 0. 一句话

综述前三步（检索 → 精读 → 大纲）本来就是来回走的：读了综述才知道哪里能写，定了框架才知道还缺哪类文献。
Mesa 现在把它们排成一条直线，回头只能靠人自己记着去哪一步、对 AI 说什么。本稿要做的是：

- 下游能**带着理由退回上游补料**；
- 上游补完后，下游**只跟进新增的部分**；
- 每一轮都**留痕、能对比**；
- 定框架改成 **AI 拿证据、人做判断的一问一答**。

不新造流程引擎，不自动连跑整条链：每一次回头仍由人点一次才发生。

## 2. 现状（已核对）

**已有，可以直接用的：**

| 机制 | 在哪 | 对本稿的意义 |
|---|---|---|
| 每步一个工作区，按 `steps[].workspace_name` 认；保存进项目后工作区仍是 active + `merged_at`，再有新提交就回到「待评审」 | `ProjectGroup.tsx deriveStepStatus` | 回头补料 = 在同一工作区开新一轮，不用新建步骤 |
| 「继续」接回上次对话；「新开一轮」另开对话。**只在步骤进行中出现**：步骤保存进项目后，步骤卡上不再有这两个按钮（`step-node-actions.ts` done 状态不给动作），只能从侧栏打开那一步原来的对话接着说 | pipeline.md「继续」条 | 补料轮、跟进轮复用「新开一轮」的开对话路径，只换开场指令；入口要新加在已保存的步骤上 |
| 上游漂移：上游步骤晚于本步最后推进时间又保存过，`WorkspaceDto.staleUpstream` 回填上游步骤名 | `workspaces.rs stale_upstream_for`；评审页顶部「上游「X」有更新，产物可能过期」 | 「待跟进」的判定现成，只是现在只在评审页提醒一句 |
| 工作区并入项目最新内容（冲突留在工作区） | `workspaces.rs workspace_sync_base`（目前只在评审页解冲突时用） | 下游跟进前先把上游新产物并进来 |
| 检索步把已纳入清单、积累、导入统一去重当进料口 | pipeline.md「流程期间继续加入积累」条；lit-search 技能 | 补检天然是追加，不会推翻已有筛选 |
| 精读按 `notes/index.json` 与 `included.json` 的 id 对齐；未读的记 pending | 精读步完成标准 `same-ids` | 新增篇自动成为「还没读的」，增量精读不用另造清单 |
| 大纲步：空白清单 → 范式卡片 →「先报候选再融合」（经 help-wanted 问一次）→ 用图计划 + 证据综合表 | `pipeline-presets.ts` 综述大纲；review-framework 技能 | 可写点、提问式定框架都在这一步上扩 |
| 初稿步：对照表用 markdown 真表；按大纲用图计划从 PDF 裁子图、拼板 | 综述初稿 brief 第 3 条；review-figures 技能 | 表格拼图已有（§11） |
| 人工请求：固定字段写 `.ccode/help-wanted.md`，收件箱卡片点选即答、经原对话送达；同时未答不超过 3 条；「范围」属于七类必问 | design-attention-dispatch.md §4 | 提问式定框架的载体 |
| 保存进项目 = 一次 git 提交；验收记录逐次留 | review-freeze.md；项目设置「验收记录」 | 每一轮的文件其实都在 |
| 侧栏对话菜单「关掉这段对话」：停下 Agent、收起，记录还在，再点开就接回；只在 AI 开着时出现。「删除」在 AI 开着时禁用 | `ProjectTree.tsx` 菜单 | 停止能力有，入口名字和位置不对 |

**缺的：**

1. 没有「退回上游补料」：上游已保存时步骤卡上没有任何再做的按钮，要回头，人得从侧栏找到那一步原来的对话，自己写 prompt 说补什么。
2. 上游补完，下游只有评审页一句提醒；没有「跟进」按钮，也没有只读新增的开场指令。下游工作区不会自动并入上游新产物。
3. 每一轮的文件在 git 里，但流程线上看不到「这一步做过几轮、各轮起因、各轮改了什么」。
4. 精读对综述和研究论文用同一套八段笔记；`included.json` 不区分文献类型。
5. 没有「可写点」产物：大纲步的空白清单来自笔记的「局限」，范式卡片拆的是结构，都没有对照「各篇综述覆盖到哪、截止到哪年」。
6. 定框架只经 help-wanted 问一次（骨架 + 卖点），不是逐问推进。
7. 步骤卡上没有「停下这一步」；做完一步后没有集中的「接下来」。

## 3. 总体设计：回路怎么走

```
            ┌──────────── 退回补料（带补料单）────────────┐
            ▼                                              │
  ① 检索与筛选 ──保存──▶ ② 精读与笔记 ──保存──▶ ③ 大纲（定框架）
            │                 ▲                            ▲
            └─保存后，②③标「待跟进」─┘                       │
                              └─②保存后，③标「待跟进」─────┘
```

三条规则：

1. **回头只有一种动作：退回补料**（§4）。它不改步骤顺序、不新建步骤，只让上游在原工作区开一轮「补料轮」。
2. **跟进是人点的，不自动连跑**（§5）。上游保存后，下游亮「待跟进」，人点「跟进上游的新增」才开一轮。
   「一次批准、一路跟进到大纲」一期不做（§13-2）。
3. **增量，不重做**。每一步的补料轮 / 跟进轮都在已有产物上追加或修改，旧产物保留；整步推倒重来仍是「新开一轮」，但不是回路的默认动作。

**和初稿、定稿的关系**：回路只覆盖前三步。大纲在初稿开工之后又改了，初稿照样亮「待跟进」，但初稿跟进是改稿，不在本稿细化，沿用现有评审退回。

## 4. 退回补料

### 4.1 从哪发起

| 入口 | 什么时候出现 | 预填什么 |
|---|---|---|
| 大纲步的覆盖检查结果（§9.3） | 有章节「可写正文的文献不够」 | AI 已起草的补料单，一节一条 |
| 评审页（大纲、精读两步）顶部 | 一直在，次要按钮「退回上一步补料…」 | 空单，人填 |
| 步骤卡「接下来」区（§10.2） | 本步待评审或已保存 | 同评审页 |

项目助手判断你想回头补文献时，只给跳到上述入口的按钮，不自己起草退回单（项目助手只解释不动手的口径不变）。

### 4.2 补料单

补料单是一张固定字段的表单，不是自由 prompt。人可以改，**点「退回去补」才生效**（「AI 提议、人批准一次」）。

| 字段 | 必填 | 说明 |
|---|---|---|
| 退回到哪一步 | 是 | 默认上一步；从大纲可选「检索」或「精读」 |
| 要补的主题 / 章节 | 是 | 一条一行，例：「§3.2 催化剂失活机理：近三年原位表征工作」 |
| 为什么 | 是 | 一句话，例：「这节可写正文的只有 2 篇，且都早于 2021」 |
| 线索 | 否 | 关键词、已知的几篇（DOI / 标题）、要排除的方向 |
| 规模 | 否 | 大致篇数上限；不填按检索步原纳入规模的 20% 提示 |

落盘：`.ccode/rework/<时间戳>-<上游工作区名>.json`（不进 git，与 help-wanted 同口径），记发起步、目标步、各字段、发起时间、状态（待发 / 已发 / 已完成 / 撤回）。

### 4.3 上游怎么开这一轮

点「退回去补」后：

1. 目标步工作区若已归档，先走现有「恢复」；仍在就先 `workspace_sync_base` 并入项目最新内容（人在 Mesa 里改过的纳入判定、补投的 PDF 都要带上）。并入冲突时停下，交人在评审页解，不开新一轮。
2. 在原工作区另开一段对话（走「新开一轮」的同一条路径；已保存步骤原本没有这个入口，由补料单发起），开场指令换成补料轮专用的一句（新常量，与 `CONTINUE_STEP_PROMPT` 并列）：
   读 `TASK.md` 与 `.ccode/rework/<id>.json`，**只补单上列的主题**；已纳入的不重筛、不改判定；新纳入的在 `included.json` 追加并标 `round`；
   在 `screening.md` 末尾追加「## 补料轮 N」一节（补了什么、检索式、候选 / 纳入数、未下载原因）。
3. 步骤状态回到「进行中」；补料单状态改「已发」。上游保存进项目后改「已完成」，并触发 §5 的下游待跟进。

**检索步任务书本身不改**：补料单是这一轮的附加输入，不进 TASK.md 草稿，免得下一次正常开步还带着它。

## 5. 下游跟进上游的新增

### 5.1 「待跟进」

判定沿用 `stale_upstream_for`，不新加状态位：本步最后推进之后，任一上游步骤又保存过，就是待跟进；本步再保存一次自然恢复。改的是**显示**：

- 步进器节点上加一个小标「待跟进」（警告色，与现有三处提醒同文案来源）；
- 步骤卡「接下来」区给主按钮「跟进上游的新增」（§10.2）；
- 仍然**只提醒不阻断**：人可以不跟进，直接往下走。

### 5.2 「跟进上游的新增」做什么

1. `workspace_sync_base` 把上游新产物并进本步工作区（冲突同 §4.3 处理）。
2. Mesa **机械算出增量**，写进开场指令，不让 AI 自己去猜哪些是新的：

| 本步 | 增量怎么算 | 开场指令要点 |
|---|---|---|
| 精读 | `included.json` 里有、`notes/index.json` 里没有或仍 pending 的 id | 只读这 N 篇；已有笔记不动；收尾更新 `handoff.md` 与 index |
| 大纲 | 本步上次保存后新增 / 改过的 `notes/*.md`、新增的 `angles.md` 条目，加上触发这次回路的补料单 | 在原 `outline.md` 上改；只动补料单涉及的章节和受影响的综合表行；文末追加「## 本轮改了什么」 |

3. 开一轮之前在确认弹层里写出规模：「新增 12 篇，预计精读 12 篇」，人确认才开。规模 0 时不开，提示「上游这次没有新增文献，只改了 X」。

### 5.3 为什么不整步重做

我们之前回答用户「第二步第三步也需要重新做」。实际不需要：精读按 id 对齐，大纲在原稿上改，都能只处理新增的部分。整步重做既花钱，又会把人在上一轮里改过、确认过的内容冲掉。

## 6. 每一轮留痕

**事实**：大纲、笔记、`papers/*.md`、`included.json` 都受 git 跟踪，每次保存进项目是一次提交，验收记录也逐次保留，所以过程文件实际都在。全文 PDF 不进 git，但它们只会增加，不会被改写。
缺的是**看得见**。

步骤卡加一个折叠区「这一步的几轮」，只读：

| 列 | 来源 |
|---|---|
| 第几轮、日期 | 本步工作区每次保存进项目的提交（验收记录） |
| 起因 | 首轮 / 补料轮（链到补料单）/ 跟进轮 / 人工新开一轮 |
| 改了哪些文件 | 该次提交的文件列表 |
| 操作 | 「看这一轮的 outline.md」（只读打开该提交的版本）、「和上一轮比」（复用现有差异视图） |

起因来自 `.ccode/rework/` 与开轮时记下的轮次类型（开轮时写一行到 `.ccode/step-rounds.jsonl`，不进 git）。

一期**不做「回到这一轮」**（回滚会和下游已用的产物打架）；人要旧版本可以从「看这一轮」里复制。一期只看不回滚已拍板（§13-5）。

### 二期落地与设计不同（2026-11-05）

- **入口只在步骤卡**：§4.1 表里的评审页顶部入口没做——评审页是看稿、写意见、保存的地方，补料是看完结果之后的决定，放在已保存 / 待评审步骤的「AI 干活」行上已经够近；覆盖检查入口随三期。
- **补料单没有「撤回」**：发出即在上游开一轮，要撤就在那一步点「停下」、评审里退回；单子本身留作记录。状态不落盘，「已完成」按上游此后有没有再保存推算（「这一步的几轮」里那一轮起因写「补料轮（X 退回）」）。
- **两道拦**：开补料轮 / 跟进轮前，目标步骤的 AI 正在干活或等确认、或有没保存的产出，都先请人处理，不叠一轮；只是开着、停在提示符上的对话不拦，新一轮就地换掉它。
- **补料单原文写进开场指令**，不只给文件路径：上游工作区里看不到项目根 `.ccode/` 下没进 git 的文件。
- **精读跟进的回退**：纳入清单里没有缺笔记的篇、但上游改了别的文件时，按改动文件跟进；否则「待跟进」要等下一次保存才消。
- **「这一步做过 N 轮」**只在两轮以上、或保存后又开了一轮时出现；只有一轮时没有可比的。
- **入口不认模板**：任何有上游步骤的步骤都有「退回上一步补料…」（引擎不认识综述，`role` / 模板名不进判断）。

## 7. 综述和研究论文分开读

### 7.1 标类型

- `papers/included.json` 每条加 `kind`：`review`（综述）/ `research`（研究论文）/ `other`。
  检索步按标题、刊名、摘要判断（Crossref 的 `type` 两者都是 journal-article，不能靠它）；判不准的标 `research` 并在 screening 里列出。
- 人在筛选评审里可以改类型（与改纳入判定同一处）。
- `notes/index.json` 同步记 `kind`。
- **双端镜像检查**：`kind` 不进任何 RIS / bib 字段。改 `lit_records.py` 时跑 `tests/lit-records.test.ts`，确认 RIS 输出不变。

### 7.2 两种笔记

| | 研究论文（不变） | 综述（新） |
|---|---|---|
| 结构 | 现有八段 | 综述卡六段：① 覆盖了哪些主题，各主题的结论 ② 文献截止到哪年（按其参考文献最新年份），发表于哪年 ③ 结构骨架（章节顺序，一句话说明每章作用）④ 作者点出的空白与展望 ⑤ 和本课题的重合度（高 / 中 / 低 + 重合在哪几节）⑥ 可引用点 |
| 写在 | `notes/<序号-短标题>.md` | 同目录，文件头标 `> 类型：综述` |
| 喂给谁 | 大纲证据综合、初稿 | 可写点清单（§8）、大纲范式卡片 |

综述卡的 ③ 就是现在大纲步「范式卡片」的原料，大纲步改为直接取用，不再回原文拆一遍。

### 7.3 精读的顺序

精读步内部**先读综述，再读研究论文**：综述读完先交可写点清单（§8），再读本轮要读的研究论文。

**第一轮：综述精读 + 研究论文全部速读**（§13-3，2026-11-05 先按方案 A 拍板、同日用户改）：

- ~~方案 A：精读第一轮只读综述 + 检索时标为核心的研究论文，其余研究论文等框架定了按章节读~~（同日否决）。用户追问两点：「核心」怎么定——检索时 AI 只看了标题摘要，一篇没读、大纲没定，等于凭摘要猜；不把所有论文读一下总结，怎么有大局观——综述只覆盖到它截止那年，最该看清的恰是之后的新工作，A 第一轮偏偏不读它们。
- **现行**：综述精读（综述卡）；研究论文**全部速读**进一张 `notes/skim.md`（一篇一行：研究问题、方法、主要结论、主题、新在哪、有无全文，主要看摘要，有全文再扫引言结论）。速读表就是整批文献的大局，可写点清单「之后的新工作」从它写。**不再标「核心」**：要写进正文的篇由大纲覆盖检查按章节「补读」点名，退回精读去精读；只速读过的篇在大纲里一律算「仅线索」。
- 速读放一张表而不是一篇一份：沉浸阅读区和「已读」判定按单篇笔记文件认，速读写成单篇会被当成精读过。
- ~~方案 B：维持全量精读~~（否决：框架没定就全量精读，花费大，且精读的篇未必是大纲要的）。
- 代价：仍要改精读步「有全文的全部精读」（2026-09-24）在综述模板上的完成标准，改为「综述写成综述卡、研究论文都进速读表」。

### 三期落地与设计不同（2026-11-05）

- **综述卡不另起六段标题**：沉浸阅读区、抽查、「已读」判定都按八段标题认笔记，另起标题会让综述笔记被当成没写。改为沿用八段标题、按综述读法填，主要结果后加「覆盖范围与时效」「结构骨架」两节，状态行开头写「综述」；截至年份同时写进 `notes/index.json` 的 `cutoffYear`，供 `angles-facts` 用。
- ~~「核心」由检索步的 AI 先标~~：同日随 §13-3 改写撤掉，`core` 键、文献清单的「＋核心」一并删除。
- **精读第一轮的分路**照旧按全部纳入的篇分；各路的速读行写本路的 `notes/skim-<路号>.md`，收尾一路合成 `notes/skim.md`（各路只写自己的文件）。为「只分综述与核心」加的分路筛选「并 / 或」写法随之撤回。
- **精读跟进只处理索引里还没有的篇**（上游新加的）：按任务书精读或补速读行；只速读过的不顺带精读，由大纲覆盖检查「补读」退回精读点名。
- **六问不另做界面**：走已有人工请求卡片（一次一问）；进度靠「定框架记录」表在「AI 干活」行显示「定框架 k/6 问」。
- **补料单预填**按「覆盖检查」表：建议写「补检：」的进退回检索那份、「补读：」的进退回精读那份；人改过字就不再覆盖。
- **模板更新提示不限综述**：哪套内置模板有更新都提示，按项目的研究工具换算后再比，免得每个项目都被误报。
- **初稿、定稿不变**：「表计划」已在一期加进大纲；初稿照旧按大纲写。

## 8. 可写点清单

新产物 `notes/angles.md`（受 git 跟踪，精读步交），一条一个候选角度：

```
## 角度 3：原位表征揭示的失活路径
- 一句话：……
- 已有综述覆盖：[@键A]（截至 2020，第 4 节两段带过）、[@键B]（截至 2022，未涉及）
- 之后的新工作：2021 年后 9 篇 [@键C; @键D; …]，其中纳入且有全文 6 篇
- 和已有综述的重合度：中——最像 [@键B] 第 3 节，但它只讲热力学
- 撑起来还缺：动力学方向的研究论文，目前 1 篇
- 风险：新工作多为同一课题组
```

规则：

- **AI 只给证据，不判「能不能写」**。用户原话：「并不是别人写了就不能再写」。重合度高的照样列出，标明最像哪篇，取舍交给人。
- 「截至哪年」「之后新工作几篇」由脚本从 `included.json` 的年份和综述卡 ② 算出，不靠 AI 数（新加 `lit_records.py angles-facts` 子命令，输出一张时效对照表，AI 在此基础上写）。
- 不要求「必须有创新」。不往指令里塞「不能和已有综述重合」，这句话只会逼 AI 编造差异。
- 大纲步的空白清单（review-framework 第一步）改为以 `angles.md` 为起点，再补笔记「局限」里的 gap，不再从零提炼。

## 9. 一问一答定框架

### 9.1 形式

大纲步开工后，AI 不直接写 `outline.md`，先按固定顺序**一次问一个问题**，走现有人工请求通道（`.ccode/help-wanted.md` → 收件箱卡片 → 点选或写「其他」→ 经原对话送回）。每问都带：建议选项（标推荐）、各选项的后果一行、依据（链到 `angles.md` 的条目或笔记），以及「按推荐」一键。

| 顺序 | 问什么 | 选项从哪来 |
|---|---|---|
| 1 | 核心问题确认（检索步已定的那句，还对吗） | `screening.md`「核心问题与边界」 |
| 2 | 选哪几个角度（多选，可自填） | `angles.md` |
| 3 | 读者是谁、读完带走哪一句（卖点） | AI 按 2 的选择给 2–3 句候选 |
| 4 | 以哪篇综述的结构为骨架，或不照搬 | 综述卡 ③ |
| 5 | 章节草图（AI 出一版，人逐节保留 / 合并 / 删 / 改名） | AI 按 1–4 起草 |
| 6 | 覆盖检查后，哪些节退回补料（§9.3） | 覆盖表 |

每答一问，AI 把结论追加到 `outline.md` 顶部「## 定框架记录」（问题、人的选择、日期），之后的轮次和下游都按它来，不再重问。人中途改主意，在记录里改那一行，下一轮按新的来。

这六问都属于七类必问里的「范围」，符合人工请求规则；同时未答不超过 3 条的上限自然满足（一次一问）。

### 9.2 和「跟 AI 商量一下」的分工

- 一问一答是**主路径**：不会写 prompt 的人也能点完。
- 想展开聊的，卡片上有「展开聊」，进同一段对话自由说；聊出的结论仍由 AI 写回「定框架记录」。

### 9.3 覆盖检查与按节补料

章节草图定下后，AI 按节出覆盖表（写进 `outline.md`「## 覆盖检查」）：

| 节 | 可写正文的键 | 仅线索 | 最新一篇年份 | 判断 |
|---|---|---|---|---|
| 3.2 | 2 | 3 | 2020 | 薄：建议补检 |

「可写正文 / 仅线索」沿用大纲步现有的分档口径。判断为「薄」的节，AI 起草补料单（§4.2），作为第 6 问交人勾选；人勾了才发。

补料、跟进完成后，大纲进入**二级逻辑**：每节写小节顺序和每小节「要回答什么、用哪几篇、用什么图表」，这就是用户说的「梳理二级逻辑，让它每一块该咋写」。现有的用图计划、证据综合表在这一阶段写。

大纲步完成标准增加两条：「定框架记录」六问都有答案；覆盖检查里没有未处理的「薄」节（人选择不补也算处理，记一句理由）。

## 10. 停下、下一步、少写 prompt

### 10.1 停下这一步

- **步骤卡**：进行中的步骤，在「去终端看看」旁加「停下」。语义与侧栏「关掉这段对话」相同：停下 Agent、收起对话，工作区和已写的文件都在，步骤仍算进行中；再点「继续」接回原对话。正在出字时先确认一次。
- **侧栏菜单**：流程步骤的对话，菜单首项改为「停下这一步」（其余对话仍叫「关掉这段对话」）；「删除」保持在最后、AI 开着时禁用，并在禁用提示里写「要停下请用『停下这一步』」。
- 说明书「步骤」章节补一小节「怎么停下正在做的步骤」，并在 §14.1 补「停下」。

### 10.2 做完一步之后：「接下来」

步骤卡底部加「接下来」区，**按状态只出一个主按钮**（守 step-panel「主路径唯一」）：

| 本步状态 | 主按钮 | 次要 |
|---|---|---|
| 待评审 | 去评审 | 再让 AI 改改（继续） |
| 已保存、下一步没开 | 开始下一步「X」 | 退回上一步补料… |
| 已保存、待跟进 | 跟进上游的新增（N 篇） | 先不跟进 |
| 进行中、AI 停在提示符 | 去终端看看 | 停下 |

每个按钮下面一句话说它会发生什么，例如：「AI 会只读新增的 12 篇，已有笔记不动」。

> **一期落地与设计不同（2026-11-05）**：没有另立「接下来」区。核对发现保存进项目后步骤卡已自动换成下一步（主按钮「开始」），
> AI 跑完时「去评审」已就绪，「去终端看看 / 继续」也在原行——另立一区会让同一个按钮出现两次（step-panel R3、R6）。
> 改为：评审节点就绪时的提示只补按钮没说的去向（「满意就保存进项目，流程线随即跳到下一步；不满意在评审里写上意见、退回修改」，
> `review-save-copy.ts reviewHintReady`），说明书 §4.3 补「一步做完之后怎么走」。表中「退回上一步补料」「跟进上游的新增」两行随二期做，
> 挂在已保存步骤的「AI 干活」行上，不另立区。「停下」挂在「AI 干活」行「去终端看看 / 继续」之后（`StepFlow.tsx`，`run-overview.ts stepStopTab`）。

### 10.3 少写 prompt

本稿的新动作都用表单或选项发起，不需要人写 prompt：补料单（§4.2）、跟进确认（§5.2）、定框架六问（§9.1）。
说明书补一节「AI 不按你想的来时怎么拉回来」：在哪里看它定了什么（「我自己定了什么」一节、定框架记录），怎么改那一行让下一轮按新的来，什么时候用「新开一轮」。

## 11. 表格与拼图（已有，补可见性）

初稿步已经会：按大纲每节的用图计划从全文 PDF 裁子图、拼板（`review-figures`），对照表用 markdown 真表；裁不到时改成「见 [@键] Fig.n」。用户不知道这个功能，是因为它只写在任务书里。

改动：

- 大纲步保存后，步骤卡显示「初稿会出 N 张拼图、M 处引用原图」（从 `outline.md` 用图计划机械数）。**落地**：大纲写出后（进行中即显示）「用图计划：初稿要拼 N 张图 · 直接引原图 M 处 · 对照表 K 张」（`notes-progress.ts figurePlan`）；`outline.md` 不在台账白名单（白名单同时管写回），走只读预览通道读。
- 大纲每节加一行「表计划」（对照表要比哪几项、取哪几篇），与用图计划并列；初稿步据此出表。**落地**：格式「表 N（比什么）= 列：… ；行：[@键]…」，写在综述大纲 brief 第 5 条与 review-framework 技能；初稿 brief 第 3 条按表计划出表、查不到出处的格写「—」不估。
- 说明书初稿一节写明会自动出表和拼图、在哪看（`figures/`、`figures/README.md`）、不满意怎么退回。

## 12. 让人看得到 AI 漏了什么

用户担心 AI 选择性下载、精读偷懒。数字由 Mesa 从文件机械算，显示在步骤卡上，不靠 AI 自述：

| 步骤 | 显示 | 来源 |
|---|---|---|
| 检索 | 候选 N → 纳入 M（综述 a / 研究 b）；有全文 K；缺全文 M−K | `included.json`、`to-fetch.md` |
| 精读 | 已精读 X；仅摘要 Y；题录 Z；还没读 W | `notes/index.json` |
| 大纲 | 覆盖检查「薄」节数；定框架六问已答几问 | `outline.md` |

AI 报告里的数字和机械数对不上时，步骤卡标「数字对不上」并给出两边的值。这一项归入核验结果的「待你判断」，不自动通过、不挡流程。

> **一期落地与设计不同（2026-11-05）**：
> - 检索步显示「纳入 M 篇 · 待确认 P · 已有全文 K · 缺全文 M−K」（`notes-progress.ts searchProgress`，按 `included.json` 的 pdf 字段认全文）。
>   「候选 N」不显示：候选池只在 `screening.md` 里以 AI 写的文字出现，没有可机械数的台账。综述 / 研究分开数等三期 `kind` 字段落地后加。
> - 精读步沿用已有的 `NotesProgressLine`（已写笔记 / 全文 / 仅摘要 / 卡住），本期不改。
> - 大纲步本期显示用图计划与表计划（§11）；「薄」节数、六问已答几问随三期做。
> - **「数字对不上」暂不做**：`included.md` 开头的篇数由 `lit_records.py write` 从 json 生成，人在 Mesa 里改判定后评审页也会按 json 改写那一句，
>   AI 手写数字的地方只剩 `screening.md` 的散文；从散文里抽数字比对误报会比真问题多。以后若有确实被 AI 报错数的实例再议。

## 13. 拍板结果（2026-11-05，全部按推荐）

1. **整体方向**：回路 = 退回补料 + 跟进上游 + 轮次留痕；不造新引擎、不自动连跑，每次回头由人点一次才发生。
2. **跟进逐步点**：一期不做「一次批准、一路跟进到大纲」，上游保存后下游各自点「跟进上游的新增」；用熟了再议。
3. **综述模板的精读第一轮：综述精读 + 研究论文全部速读**（§7.3；同日先定「只读综述 + 核心篇」，用户追问核心怎么定、没有大局观后改）。要写进正文的研究论文由大纲覆盖检查点名精读；
   2026-09-24「有全文的全部精读」在**综述模板上**由此改写，论文、学位论文模板不动。
4. **大纲步改为一问一答六问**（§9.1），取代「先报候选再融合」的单问。
5. **轮次一期只看不回滚**：「这一步的几轮」只读，可看可比，不提供回到旧一轮。
6. **存量项目经 `pipeline-upgrade.ts` 提示升级**，人点了才改项目档案里的步骤简报；新建项目直接用新模板。

## 16. 验收

按「动真实数据先干跑」规则，二、三期交给用户前，用一个真实综述项目（优先该用户的甲醛储氢项目副本）完整走一遍：

1. 检索 → 精读第一轮 → 大纲六问 → 覆盖检查出「薄」节 → 发补料单 → 检索补料轮保存 → 精读跟进只读新增篇 → 大纲跟进只改相关章节。
2. 核对：已有笔记字节不变；`included.json` 只追加；`outline.md`「定框架记录」未被覆盖；「这一步的几轮」三步都能看到每轮并对比。
3. 中途在终端里点「停下」，再「继续」，确认接回原对话、文件没丢。
4. 机械计数与 AI 报告逐项一致，人为改一个数字能看到「数字对不上」。

## 17. 给这位用户的回复口径

- 回头补文献：今天可以手动做——在侧栏找到「文献检索与筛选」那一步原来的对话，点开告诉 AI 补哪个主题、只追加不重筛；它保存后到评审里存进项目，再分别打开精读、大纲两步的对话，让它们只处理新增的部分。之后会做成步骤卡上的按钮（本稿二期）。
- 过程文件都保留：每次保存进项目都留一版，旧笔记不会被覆盖。
- 表格和拼图：初稿一步会按大纲的用图计划自动裁图拼板、出对照表。
- 停下：侧栏对话右键「关掉这段对话」就是停下，不要点删除；之后会在步骤卡上加「停下」按钮（本稿一期）。
