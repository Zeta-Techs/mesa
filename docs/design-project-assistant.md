# Mesa 设计稿：项目助手——项目里有不明白、出了错，问它

> 状态：**已拍板、两期一起落地**（2026-11-04，用户「两期一起做」）；落地与设计不同处见 §11。
> 起因：用户说「科研流程步骤太多，能否在工作台做一个总控 AI，有不明白或者哪里出错的可以问这个 AI」，
> 担心和已有的协调对话、进度显示做混；随后补充「不知道哪里出错，更可能是 Mesa 的问题，用户无从知晓，只能问项目助手」。
>
> 已拍板：名字叫**项目助手**；连接走「Agent 分工」里新加的**专属绑定**；问答**记录要存**；一期二期一起做；抽屉位置按推荐。

## 0. 一句话

项目助手是这个项目里**唯一的「问」入口**：问进度、查报错、问规划、要修复建议，都在它这里问。
Mesa 把这个项目的现状、**连同 Mesa 自己在这个项目上出过的错**整理成一份项目快照交给 AI，AI 解释原因、判断是课题的事还是 Mesa 的事、给出下一步；
要动手时给出跳到已有入口的按钮，你点了才发生。它不是常开的终端，不派活，不替你拍板。

## 1. 归到项目助手的，和不归的

**「问」的入口归一**：以后在项目里想知道什么，只有一个地方问。

| 你想问的 | 项目助手怎么答 |
|---|---|
| 问进度：到哪了、还剩什么、花了多少 | 引用工作台同一份数据回答，不另算 |
| 查报错：这一步为什么失败、为什么卡住 | 看运行记录、退出码、最后的事件、核验、**Mesa 自己的出错记录**，先判断是谁的问题（§3） |
| 问规划：下一步做什么、要不要拆开做、流程要不要加一步 | 给建议；要拆开做就带着草稿跳到「拆成几路做…」，要改流程就跳到流程编辑器 |
| 修复建议：怎么办 | 能在 Mesa 里点几下解决的，给按钮；Mesa 的毛病，给绕过办法 + 「报告给开发者」 |
| 看不懂某个按钮 / 某个状态 / 某个词 | 按说明书和当前界面状态解释 |

**不搬家的**：显示和操作照旧留在原地，项目助手只是带你过去。

- 任务面板、步进器、收件箱、等你拍板队列：仍是看数字、点操作的地方。
- 人工请求、决策项、评审采纳：仍由你在原卡片上定，项目助手只解释选项。
- 「跟 AI 商量一下」（步骤卡）：仍是**聊课题内容**的地方，比如这段方法怎么写、这批数据怎么清；项目助手**聊的是项目和 Mesa 的运转**。两者分工写在入口提示里，项目助手判断你在问内容时给按钮「去跟 AI 商量」。
- 「拆成几路做…」：仍是出拆分方案、批准开工的地方，项目助手能把需求预填进去。

## 2. 和已有功能的关系

| 已有 | 本稿之后 |
|---|---|
| 协调对话（11-03 已删） | 不恢复。区别：项目助手不开终端，不自己探，不派活，不传话；主要回答「为什么」和「怎么办」，这两样记录里没有现成答案 |

| 跟 AI 商量一下 / 问 AI / 快速开聊 | 不变，各自开工作对话；项目助手只在需要时带路过去 |

## 3. 关键：让「Mesa 的问题」看得见

用户最常卡住的不是课题本身，是 Mesa 某个操作没成功，比如保存进项目报错、工作区开不出来、连接注入失败、评审冻结失败。
今天这些错的去向：

- 红色提示条（`toast`）**不进任何记录**，几秒后就消失。
- 后端诊断日志（`logbuf`）只在内存里存最近 500 条，**不分项目**，重启就丢。
- 前端崩溃和未处理的报错会进诊断日志，但同样不分项目。

所以项目助手要答得出，先得有**按项目的 Mesa 出错记录**：

- **记什么**：
  - 发生在某个项目上的错误提示条，记下文案、出处（哪个页面哪个操作）、原始报错。
  - 该项目相关的后端命令失败。
  - 未处理的前端报错（能归到项目的）。
  - 同项目时段内的诊断日志警告和错误。
- **怎么记**：写在配置目录 `project-assistant/<项目路径哈希>/mesa-errors.jsonl`（不进项目，理由见 §11）；出 Rust 前脱敏；每条带时间和 Mesa 版本；只留 30 天、最多 500 条。
- **怎么归属项目**：调用点显式传项目根，不靠猜；归不到项目的只进全局诊断日志。
- 这份记录本身也是开发者排查的材料：「报告给开发者」时可以勾选附上。

项目助手答查报错类问题时，第一句先分清是谁的问题：

1. **课题 / AI 干活的问题**：AI 跑出错、核验拦下、评审退回。给原因和下一步。
2. **环境的问题**：缺 Git、缺 Python、CLI 没装、连接失效、网络。给安装或设置入口。
3. **Mesa 的问题**：Mesa 自己的操作失败或状态不一致。给能绕过的办法（如果有），加「报告给开发者」按钮。反馈表会预填问题描述、项目助手的判断、相关出错记录和诊断日志，你看过再发。

## 4. 两段做

### 一期：出错摆到明处 + Mesa 出错记录（不用 AI）

AI 只能解释记录里有的东西，所以先补记录和显示：

- **按项目的 Mesa 出错记录**（§3）。
- **步进器 / 步骤卡加「出错了」**：这一步最近一次运行失败、之后没有成功的，显示「出错了」+ 一句白话原因（`exit-code.ts` 译退出码 + `close_reason`）。
- **任务面板「过程」写清原因**：每次出错退出写退出码白话与最后几条运行事件，不再只有「出错退出」四个字。
- **工作台项目头加一行「卡点」**：
  - 汇总这个项目卡住的事，最多三条，点哪条跳哪：出错的步骤、Mesa 出错、核验拦下、评审退回未处理、人工请求未答、工作副本开着没保存。
  - 有卡点时用项目头上的「项目助手」问（行末原有的「问项目助手」2026-11-04 收掉，见 §11 入口规矩）。

### 二期：项目助手

**连接：Agent 分工里的专属绑定**

- 「Agent 分工」新加一行**项目助手**，槽位名 `assistant`，加进 `valid_agent_binding_slot` 白名单。
- 只列支持无头调用的连接和模型。
- 没绑时依次退回：项目默认连接 → 设置里的 AI 功能连接。面板上写明当前用的是哪个，以及是不是退回来的。
- 解析塔口径照 agent-binding.md，不另起一套。

**入口**

- 工作台每个项目分组头上的「项目助手」。
- 卡点行、步骤「出错了」、任务面板出错的运行旁的「问问为什么」：把那件事预填成问题，并标为本次重点。
- 不放全局入口，项目助手永远只认一个项目。

**打开看见什么**

- 工作台右侧抽屉，与任务面板同一位置、同一套样式。
- 上面是这个项目的问答记录，下面是输入框，顶上写当前连接。
- 几个常用问题点选即问：「现在到哪了」「哪里出问题了」「我下一步做什么」。

**一次问答怎么走**

1. 后端 `project_assistant_snapshot(project_root, focus?)` 拼好项目快照（§5）。
2. 加上固定规矩（§6）、最近 6 轮问答、你的问题，走 `ai_prompt` 无头调用一次。在临时目录跑，不碰项目。
3. 回答里的动作标记由前端按白名单渲染成按钮。
4. 这一轮写进记录（§7）。

**花费**：每次问答照无头调用记账，记在 Mesa 内部活动里（§11）。

## 5. 项目快照：喂给 AI 的东西

全部来自已有命令，后端一次拼好，过 `redact_sensitive_text` 再出，有长度上限（超了先砍最旧的运行事件和日志）：

| 块 | 来源 |
|---|---|
| 项目与流程 | `read_project_config`：模板、步骤顺序、每步要交什么、怎样算做完、已定的决策项 |
| 每步状态 | `list_workspaces` + 步进器同口径的状态（含一期新加的「出错了」） |
| 最近运行 | `run_list`：每步 / 每个目标最近 3 次的状态、退出码、关闭原因、耗时；出错的那次附 `peek_events` 最后若干条 |
| Mesa 出错记录 | `mesa_errors_read` 最近 30 条 |
| 等你的事 | `list_help_requests`、收件箱未处理条目 |
| 评审与核验 | `research_checks_read` 的拦下 / 待你判断；`.ccode/review-notes.md` 退回意见（需新增只读命令） |
| 环境 | Git / Python / 该项目用到的 CLI 是否装好、版本、是否在金丝雀验过的版本内；连接体检结果 |
| 改动 | 进行中工作的 `peek_changes` 摘要（只给文件名和加减行数） |
| 项目知识 | `project_memory_read` 的「已定 / 不做」 |
| 怎么用 Mesa | 说明书相关章节的摘要（按问到的页面挑，不整份塞） |
| 重点 | `focus` 指向的那件事：完整的运行事件、相关出错记录 |

不放进去：文献 / 数据 / 稿件正文、密钥、别的项目的任何东西。

## 6. 项目助手的规矩（写死在提示词，前端兜底）

- **只答这个项目**。快照里没有的不猜，答「记录里看不到」，并说去哪能看到。
- **先分清是谁的问题**（§3 三类），再说原因，最后说怎么办。
- **只建议，不拍板**：人工请求、决策项、评审采纳一律只解释选项，不替你选（「Mesa 不替人自动回答」照旧）。
- **不动手**：不派活、不改文件、不传话。要动手时输出动作标记，前端只认白名单：
  - 打开某一步、去终端、去评审、回答某条人工请求、打开任务面板。
  - 给它留话：只把草稿填进「给它留话」框，发不发你点。
  - 拆成几路做：预填需求。
  - 打开流程编辑器、打开 Agent 分工 / 连接页、去设置安装依赖。
  - 去跟 AI 商量：带着问题开商量对话。
  - 报告给开发者：预填反馈表。
- **说人话**：先一句结论，再说依据（第几步、哪次运行、哪条记录），最后最多三个按钮。

## 7. 记录

- 存在配置目录同一处的 `assistant.jsonl`，按项目分开，不进项目（§11）。
- 每轮记：时间、问题、回答、用的连接和模型、花费、当时快照的摘要指纹。不存整份快照。
- 面板显示全部记录，可清空；喂给 AI 时只带最近 6 轮。
- 「报告给开发者」时可以勾选附上相关几轮。

## 8. 不做什么

- 不做常开的总控对话，不让它自己 peek、开工、传话。
- 不做跨项目助手。
- 不主动弹出、不推送；出错的提醒交给一期的显示和收件箱，项目助手只在你问时答。
- 不替代任务面板、步进器、收件箱、商量对话。
- 不自动修 Mesa 的毛病，也不自动发反馈。

## 9. 拍板与核对结果

- `assistant` 槽：开工弹层、步骤解析塔、商量类都不读它（agent-binding.md 指派表）。

## 11. 落地记录（2026-11-04）

与上文设计不同处（以这里为准）：

- **两份记录放配置目录**（`project-assistant/<项目路径哈希>/mesa-errors.jsonl`、`assistant.jsonl`，`project_assistant.rs`），不放项目 `.ccode/`：
  `.ccode/` 每多一个文件都要同步 `.gitignore` 模板、合并判定（`review_contract.rs` 账本白名单）与保存排除表，存量项目的 `.gitignore` 还不会自动补。代价：记录不跟项目换机器。
- **出错记录不逐处改调用点**：Tauri 注入的 `__TAURI_INTERNALS__.invoke` 是不可改写属性，改为 Vite 精确别名把应用里的 `@tauri-apps/api/core` 指到
  `src/tauri-core-shim.ts`，`invoke` 失败先通知 `mesa-error-capture.ts` 再原样抛出。归属看参数里的路径落在哪个项目根或其工作副本；终端收发、插件命令、取消不记；
  红色提示 3 秒内补到同一条。只有界面提示、没有后台失败的，归不到项目，不记。前端未处理异常仍只进全局诊断日志。
- **「出错了」只盖「进行中」**：待评审、有冲突、已完成各有更要紧的下一步，不盖掉；AI 正在干活或等确认时也不写。「应用上次异常退出」收尾的运行不算这一步出错，快照里标成 Mesa 的问题。
- **花费**：项目助手走 `ai_prompt` 同一条无头通道，用量记 Mesa 内部活动，不归到项目；问答记录不记每轮花费。
- **按钮**：「拆成几路做」只把需求复制到剪贴板并提示去项目分组粘贴（SplitPlanRow 没有外部预填口，不为它另开）；「给它留话」把草稿填进任务面板「给它留话」框
  （`TaskPanelPeek` 的 `draft`），那一步没开着的 AI 时提示送不到；「报告给开发者」借聊天层「和终端对不上」那条事件打开反馈表（`MismatchReport` 加 `attachLabel` / `attachHint`）。
- **快照**里出错那次运行给的是运行事件（`run_events` 最后几条），不是终端屏幕最后几行；终端回放缓冲在前端，没接。
- **没做**：交互对话「可能卡住」（什么算卡住未定，避免误报）；错误提示条之外的行内报错（`setError` 一类）不进出错记录，靠后台失败那一条兜住。
- **形象「小桌」**（同日用户三轮：「一点不像项目助手，做一个 Mesa 品牌的形象」→「要像 Claude 的像素小人一样生动，但不是像素风」→ 深色改、按时间换样子、盘腿重画）：
  原创卡通小工作台（Mesa = 西班牙语「桌子」，产品即工作台），桌面头顶 + 桌裙脸 + 两条桌腿呼应 M，桌上一摞文献与 M▁ 光标；平面粗描边、零投影零渐变；
  深色主题也用浅色那套米白身子（深底上像贴纸）。动作：平时晃 / 眨眼，问着托腮 + 头上三道光标，答完举手蹦，没问成皱眉冒汗；没在问时按本地时间：
  早上咖啡、白天挥手、傍晚台灯、夜深盘腿睡。否决过的：直接用应用图标当头像（「不像助手」）、只有一个头的小机器人与三个纯字标方向（「太简陋」）。
  **2026-11-09 改成逐帧精灵图**（用户：「没有 Codex 的宠物生动」，二选一拍板「用出图模型孵一张精灵图」，否决「矢量里学机制」）：借 Codex hatch-pet 的流程——
  一张基准图定长相（以旧矢量小桌为参考改画：更圆、脸更大、绘本线条），每个状态以基准图为参考出一行动作条，切帧、按身高统一大小、统一基线、拼图，
  逐行看浅 / 深两张联系表质检，不对的整行重出、不跨批次拼帧。八行：站着、挥手、在想（托腮抬眼）、蹦一下、没问成（垂头丧气）、盘腿睡、早上咖啡、傍晚台灯。
  深色主题同一张：外圈烤一道米白贴纸边，深底上墨线、脚和 z 不隐掉。挥手放两遍、蹦一遍后回站着，没问成停在最后一帧，站着时点大图蹦一下。
  不做 hatch-pet 的 16 个朝向与左右走（小桌只在面板里）；也不做「等你回」一行（没有对应的时刻，挂上去只是又一个挥手）。重孵材料与步骤 `scripts/buddy-sprite/`。
  排版：顶栏形象 + 名字 + 项目名；空状态三个问题是细线列表不是卡片；回答首句加粗带琥珀竖线；输入框钉底，连接与清空记录在输入框下一行。
- **问题分流**（同日用户：「问怎么换模型也要看项目记录吗，问答逻辑交互逻辑好好完善」）：本地按字面分 howto / project / mixed / chat（`classifyQuestion`，不多调一次 AI）。
  howto 只带说明书摘录 + 一点项目概况（说明书编译期打包进后端，`assistant_guide_search` 按段打分，常问几类由 `GUIDE_TOPICS` 直接指到小节）；project 带快照（90 秒缓存）；
