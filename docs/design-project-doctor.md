# 项目体检：老项目、乱操作都能走下去（2026-11-18）

> 状态：五期同日落地（`feat/project-doctor`）。规则以 `docs/conventions/pipeline.md`「项目体检与老项目升级」为准。

## 起因

打包版用户在第一步、精读两步的评审里都被「主文件夹里还有没保存的改动」拦住，提交面板却说没有改动，随后「卡在提交中」。
当天逐个修了（porcelain 首行被 trim、豁免清单前后端不一致、提交无限等待、主文件夹笔记与本步重叠时 git 拒绝合并），
用户随即拍板：**不能等用户去发现**——老项目、旧模板会一直存在，用户总会在 git、工作树、工作区上做奇怪的操作，要根治。

病根有三：

1. **项目没有结构版本。** Mesa 改项目结构（`.gitignore` 规则、台账位置、档案卡字段、模板里的命令）后，老项目停在旧样子；
   兼容逻辑散在 27 处各自判断，漏一处就是一个死结。
2. **git 状态的判断散在各入口。** 锁文件、没做完的操作、工作树目录丢失、分支被删、手动合并……评审页、工作区页、
   步骤卡、退回修改、并入最新各查各的；任何一个入口没查到，用户就撞在 git 的原始报错上。
3. **没有乱操作的测试。** 现有测试只走正常路径。

## 不变式

> **任何一个入口拦住人时，都必须同时给出一个点得动的出口；点完以后，原来要做的事能接着做。**

入口指：开工、继续 / 新开一轮、退回修改、按意见重写、退回上一步补料、跟进、打开评审、提交、保存进项目、归档、恢复。

## 三件事

### 一、项目体检（后端一个入口）

`project_doctor::check(project_root, workspace_id?, intent)` 把主文件夹和这一步工作区的异常状态列全，每条带：

- `code`：机器名（测试与前端按它分支）
- `text`：一句白话，说清现在是什么样
- `fix`：处理办法，分三类
  - **自动**：不丢任何东西、不替人做判断的（删超过 30 秒的残留锁、`git worktree prune` 已不存在目录的登记、补 `.gitignore` 的 Mesa 忽略行、把 Mesa 自有档案提交进历史）——体检时直接做，事后在结果里写一行「已替你处理：…」
  - **一键**：要人点一下、点前说清后果的（放弃没做完的 git 操作、切回主分支、重新挂载工作区、补记在 Mesa 外合并过的一步）
  - **去处理**：要人看内容做选择的（冲突选边、主文件夹里人自己的改动要不要存）——给跳转按钮
- `blocks`：这条拦不拦当前 intent（同一状态对不同入口拦法不同：主文件夹有人自己的改动拦「保存进项目」，不拦「退回修改」）

已有的零散检查并进来，不再各写一套：评审页健康度里的锁 / 没做完的操作 / 分支、工作区页的漂移修复（工作树丢失、
未登记、分支被删、停错分支、仓库挪走）、`bringLatest` 前的工作副本未提交、合并前的豁免与重叠先存。

新补的状态（今天发现的）：

| code | 什么情况 | 出口 |
|---|---|---|
| `merged_outside` | 这一步的分支已在主线里，但没有 Mesa 的评审记录（人在 Mesa 外合并过） | 一键：人确认后补记一条「在 Mesa 外合并、人工确认」的记录（2026-11-18 用户拍板） |
| `project_id_shared` | 两个文件夹的档案卡是同一个项目 id（整个复制过项目文件夹） | 一键：给这一份换新 id，各走各的 |
| `worktree_on_wrong_branch` | 工作区被人切到别的分支 / detached | 一键：切回这一步的分支（工作区干净时） |
| `worktree_dirty_for_round` | 开新一轮前工作副本有没提交的文件 | 一键：一起提交进这一步（原 `commitLeftovers`） |

### 二、项目结构版本与逐级升级

档案卡加 `layout = N`（缺省视为 0）。`project_upgrade` 是一张有序的升级表，每级：

- 只追加或改 Mesa 自己的东西，不改人写的内容；能重复跑（第二次什么都不做）
- 有一份那一代老项目的样本（`tests/fixtures/projects/layout-<N>/`），测试从样本升到最新，断言结果
- 升级在体检的「自动」类里做，做完写回 `layout`

第一级就是今天的 `.gitignore` 补忽略行。以后谁改项目结构，必须同时加一级升级和样本，否则「最新版样本 = 新建项目」那条测试不过。
模板内容（步骤说明、验收条件）仍走现有的「Mesa 提出、人勾了才换」，不进自动升级。

### 三、乱操作场景测试

后端一套场景测试：真 git 仓库里走完整的一步——开工 → AI 写并提交 → 体检 → 评审 → 保存 → 下一步开工 → 退回上一步补料 → 并入最新 → 再保存。
每两步之间注入一种乱操作，断言**不变式**：体检要么没有拦的项，要么每条拦的项都有出口，按出口处理（自动的已做，一键的照做）后，
原入口能做成。乱操作清单（随发现增补）：

- 主文件夹：改了已跟踪笔记 / 台账；自己提交了；`git checkout` 到别的分支；detached；合并 / 变基做到一半；残留 `index.lock`；
  删了 `.gitignore`；手动把这一步的分支合并进来；手动删了这一步的分支
- 工作区：目录被删；目录还在但登记没了；切到别的分支；有没提交的改动；合并做到一半；残留 `index.lock`
- 项目：整个文件夹挪走；整个复制了一份接着用；老档案卡（无 id、无 layout、旧模板命令）；老 `.gitignore`；台账被跟踪

### 补：对话启动这一层（2026-11-18 发版后）

v0.2.1 发出后用户撞上「此 Run 不支持恢复」：更新重启后恢复出的标签带着已结束的 runId，点「跟进更新」就地开新一轮被拒。
前三件只覆盖了 git / 工作副本层，没覆盖「重启后恢复出的标签 → 在里面开对话」这一层。补上：标签上的旧 Run 能否沿用集中到
`runs::carried_run_id`（旧记录不挡路，另登记），对话文件夹没了先 `heal_missing_worktree` 放回来；矩阵测试 120 种组合守着；
发版前在 Mesa Dev 重启后走一遍步骤卡入口列进规则。

## 不做

- 不替人决定内容：冲突选哪边、人自己的改动要不要存，永远是人点。
- 不取消跟踪老项目里已进历史的文件（`git rm --cached` 会和在途工作区分支互相删改）。
- 不在 Mesa 关着时做任何事；体检只在入口被点时跑。

## 分期

1. 场景测试骨架 + 现有入口在各乱操作下的现状清单（先把死结找全）
2. `project_doctor` 后端：状态目录、自动处理、一键处理；并入已有零散检查
3. 前端各入口统一先过体检（一个共用的拦截条 / 弹层），旧的零散提示删掉
4. `layout` 与升级表、老项目样本
5. 在 HER 综述拷贝上把每一步的退回修改、重做、评审、保存实跑一遍
