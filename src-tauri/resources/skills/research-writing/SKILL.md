# 实证科研论文写作

## 适用范围

用于有研究问题、方法、结果和讨论的实证论文或分析报告。先读任务书、研究设计、结果表和现有文献笔记，再写作；不要把综述写作方式套到实验结果上。

## 对话里改一段（轻量模式）

本技能装在 CLI 的技能目录里，用户在普通对话里贴一段 Introduction 说「帮我改改」也会用到。那不是写作步，下面「写作流程」第 1 步要读的任务书、设计和结果表不是前提。

**怎么判断**：当前目录没有 `TASK.md`，用户给的是对话里的一段文字（或点名一个文件里的某段），要的是润色、改写、缩写或翻译——走轻量模式。

- 改好的文字直接回在对话里；用户点名了文件、明说「改到文件里」，才改那个文件的那一段。不新建 `manuscript/` 下的文件。
- 「核心约束」照旧：不编数据、样本、显著性和文献；数字和结论方向不动；原文里的 `[@键]` 原样保留。
- 原文里看着站不住的论断，不替用户改成别的事实——在改好的文字后单独列出来，说明为什么存疑。

## 核心约束

- 只使用项目已有的研究问题、方法、结果和 `references.bib`。不得编造数据、样本、显著性、实验条件或文献。
- 若有 `manuscript/outline.md` 和 `manuscript/section-status.md`，按大纲和允许集写。结论只用「## 结论条目」里状态为已认可的编号。
- 审查报告里没有被写成接受或修改的条目，不得据此改数字、因果、样本或结论范围。
- 数字、方向和结论必须能回溯到分析表、结果章节或图表；证据不足写 `[待核实]` 或 `[待补实验]`，不要用流畅措辞掩盖缺口。
- 按 IMRaD 组织：Introduction 说明问题、研究空白和贡献；Methods 对应设计；Results 只报告观察结果；Discussion 区分解释、局限和后续工作。
- 从已有成稿转 LaTeX 时只改排版与引用命令，不改学术观点、数字与结论。
- 负结果、失败实验、离群值和与假设不一致的结果必须保留并说明处理规则，不因结果不理想而事后换分析口径。
- 引用只使用 `references.bib` 已存在的键（源稿 `[@bib键]`）；缺条目先补齐可核验元数据并标注待核，不凭记忆生成。docx/PDF 的引用样式按 quarto-render：先看项目 PDF 再由人选定，不设默认。

## 写作流程

1. 读取 `TASK.md`、项目全局设定、研究设计、`analysis/results-table.md`、`analysis/findings.md`、图表说明和文献笔记，建立“论点—证据—来源”表。
2. 先列出每节要回答的问题与证据，再成文。每个主要结论至少绑定一个数字、表/图或可定位的文献来源。
3. 生成 `manuscript/draft.md` 或任务书指定的稿件文件；图表只引用已有文件或用明确占位，不复制或虚构图片。
4. 做一致性检查：术语、样本量、分组、指标、方向、有效数字、图表编号和引用键前后一致。
5. 另列局限、未决事项和需要人工确认的作者信息/投稿信息，不能把这些内容悄悄填成事实。

## 数字追溯（固定脚本，结果进 Mesa 评审页的核验清单）

正文成稿（流水线里写结果、定稿的步骤）后，把要核的数字登记进 `manuscript/numbers.json`，再跑技能目录里的 `scripts/num_check.py`（不复制进工作区；`python3` 在 Windows 上换成 `python`）：

- 登记：结果、摘要和讨论里来自分析输出的每个数字各一条：`{"id": "N001", "location": "manuscript/<稿件>.md:<行号>", "value": "<正文里的写法>", "source": "<结果文件>", "path": "<JSON 键路径>"}`；CSV 结果用 `row`（第几行数据）或 `match`（`{"列名": "值"}`）加 `column`；正文写百分数而结果是小数时加 `"scale": 100`。只登记真从结果文件来的数，引用文献的数字、样本量设计值不登记。
- 运行：`python3 <技能目录>/scripts/num_check.py --root <工作目录> --coverage`。脚本按正文显示的小数位算舍入误差逐条比对，写进 `.ccode/checks/num-check.jsonl`。`--coverage` 默认递归扫 `manuscript/`，正文在别处时加 `--files <文件>`；登记文件不在默认位置时用 `--numbers <路径>`。
- 处理：拦下的（正文与结果对不上、结果文件取不到值）先回结果文件查原因再改正文，**不得为了过核验改结果文件**；`--coverage` 列出的未登记小数 / 百分数，是结果数就补登记，不是（如引用别人的数）在交付说明里一句带过。

## 投稿前检查（固定脚本，结果进核验清单）

定稿、要交给期刊或导师前，对最终稿（Markdown / Quarto / LaTeX，或人给的 Word）跑一次技能目录里的 `scripts/ms_check.py`（不复制进工作区；`python3` 在 Windows 上换成 `python`）：
`python3 <技能目录>/scripts/ms_check.py [稿件 ...] --root <工作目录>`，不给稿件就扫 `manuscript/` 下的 md / qmd / tex，Word 稿要点名。

- 查：作者名与邮箱拼写差一点（以邮箱为准）、开了 `number-sections` 又手写标题编号（拦下）、Word 里自动编号与手打编号混用、图注 / 表题编号重复或跳号（拦下）、图注写了 Adapted from 却没有出处、重复词与常见语病、同一单位几种写法、同一对符号连接号不一、英美拼写混用、有没有结论 / 展望节。结果写进 `.ccode/checks/ms-check.jsonl`。
- 处理：拦下的改正再跑；待你判断的逐条看，期刊有规定的按期刊统一（单位、拼写、连接号），不确定的列进交付说明交人定。脚本只读，不改稿件。

## 交付自查

- IMRaD 四部分齐全，研究问题与贡献在引言和讨论中一致。
- Results 没有混入未经分析支持的因果表述；Discussion 明确哪些是结果、哪些是解释或推测。
- 每个表/图在正文中被引用，图注说明样本、指标和条件；图只引用已有文件；没有数据的图写明缺哪项分析并标 `[待补实验]`，不写「待绘制」占位（占位一进正文就没人回头补）。
- 文中引用键均能在 `references.bib` 找到；不确定的事实带 `[待核实]`。

## 验证与写作边界

- 读取已批准的设计版本、偏离记录、数据/代码/环境版本和复算证据；没有时只做带状态的草稿，不把统计报告存在当通过。
- 主要论断表同时记录支持范围、替代解释/反证和未决事项；事实、假设、推测、结论分开。同数据探索后补检验不自动确证，不显著不自动证明无效。
- 核心引用回原文做支持性核验，和 bib 键检查分开；摘要-only 不支撑无法从摘要核实的定量/方法/因果主张。
- 数据/清洗/指标或原文版本改变，标出失效的表图与段落，重算重验后才复用；补实验先回设计→执行→分析→复算，再同步摘要、讨论与回复信。
- 投稿前人确认结论范围、共同作者/贡献、利益/资助/AI 使用披露、数据代码可用性；核心阻塞问题未关闭不得称可投稿。按证据决定篇幅与发现数，允许负结果和证据不足。**词数不够不是缺陷**：禁止为凑篇幅加背景铺陈或同义复述。某节薄，只回设计/结果表/笔记/原文补可定位证据；没有更多证据就保持短并标 `[待核实]` 或 `[待补实验]`。论断直接说，必要局限写一次；真实不确定写清来源，不要叠三层 hedging。

## 验收入口

有 TASK.md 时沿用其中的验收摘要/质量状态合同，不重复建表；轻量模式不写这一段；不在流水线里但按写作流程成稿时，在本报告开头写：回答、关键证据入口、未验证、影响结论的问题、待人决定。状态为待审/有条件接受/证据通过（限定范围）/阻塞；推荐不等于人工批准。
