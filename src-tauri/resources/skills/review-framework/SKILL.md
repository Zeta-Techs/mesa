# 综述框架构造

本技能规定综述/论文框架的设计方法：**根据最新精读文献的前言内容提取研究空白 + 拆解权威综述的框架范式 → 融合构造出自己的综述框架**。框架不是凭空拟的目录，每章说明对回答问题或理解证据的作用，不强迫每章制造空白。框架质量取决于能否回答核心问题、解释分歧并诚实呈现证据边界，不按空白数量评分。

## 何时使用

- 综述流水线中的「综述大纲」步骤（简报会指向本技能）
- 用户要求为综述或论文设计章节框架、讨论「这篇综述该怎么搭结构」时

前置条件：`notes/` 下已有精读笔记（含「局限」「可引用点」字段），`papers/included.md` 中已有纳入文献清单，`references.bib` 引文库可用。`papers/included.json` 里 `decision=excluded` 的篇（人在评审里移出的）笔记与引文条目照旧留着，但不用：不算进覆盖声明的篇数、不引用它的键。

### 对话里聊结构（轻量模式）

本技能装在 CLI 的技能目录里，用户在普通对话里问「这篇综述该怎么搭结构」也会用到。那不是大纲步。

**怎么判断**：当前目录没有 `TASK.md`，用户也没说「写出 outline.md / 出大纲文件」——走轻量模式，上面的前置条件不适用。

- 在对话里给框架建议：按手头有的材料（已有笔记、用户在对话里说的问题和文献）说两三种可选骨架、各自适合回答什么问题；材料不够就直说缺什么，不编文献、不宣称「无人研究过」。
- **不写 `outline.md`**：它是初稿步和拼图步直接照着走的正式大纲，对话里不新建、不改写。用户要落成文件，告诉用户可以在 Mesa 开综述流程的「综述大纲」步，或在对话里明说「按完整规范出 outline.md」，再按下文做。

## 前置：判定综述形态

动手前先判定产出形态，写入 outline.md 头部；形态决定章节数与详略基线：

- **学位论文综述章**：按论文问题选择覆盖范围，不要求穷尽所有空白；
- **期刊独立综述**：聚焦一条核心问题，章节从简；
- **引言内嵌 mini 综述**：不拆范式卡片，直接按「背景→空白→占位」三段构造，以下第二步跳过。

## 规范

### 一、提炼研究空白清单

0. `notes/angles.md`（精读步写的可写点清单）与 `notes/skim.md`（研究论文速读表）在时，从可写点的候选角度起步、用速读表看综述之后各方向出了什么：每个角度带着已有综述覆盖、时效对照与重合度，空白清单在它上面补，不从零提炼；重合度高的照列，不因「别人写过」删掉。
1. 通读 `notes/` 各笔记的「局限」与「可引用点」两节；对最新精读的一批文献，回到原文前言（Introduction 末段）核对作者自述的研究空白——前言中的 gap 是待检主张，须查最邻近工作与反例；作者自述不能自动成为领域事实。
2. 汇总为研究空白清单：**每条空白必须标注来源笔记**（笔记文件名或 bib 键），多条文献指向同一空白时合并为一条并列出全部来源。
3. 空白描述写「缺什么」，不写「我想做什么」；仅凭单篇文献主观抱怨、无第二来源佐证的孤立空白保留但在清单中标注「孤证」。
4. **每条空白标注类型**，写进清单，供第三步映射章节功能。六类及识别信号：
   - **证据**：结论有断言但缺数据支撑（「有待实证」「尚需检验」）；
   - **知识**：该问题整体上无人研究（少见，须格外谨慎，多半实为孤证）；
   - **实践**：研究发现与实际操作脱节（「研究说该做 X，实践中无人做」）；
   - **方法**：已有问题缺合适的研究手段或测量（「现有方法无法……」）；
   - **经验**：结论未在具体人群/情境/边界条件下验证（「是否适用于……尚不清楚」）；
   - **理论**：现象缺统一解释框架，各家说法并存（「机制尚不明确」）。
5. **禁令：不得宣称「无人研究过 X」**。无第二来源佐证的此类断言一律降格为孤证，诚实写法是说明邻近工作做了什么、漏了什么：「邻近工作做了 A、B，未覆盖 C」。

### 证据综合先于框架定案

在 outline.md 增加紧凑证据表：问题/研究对象、方法与可比性、主要结果、偏倚或局限、原文位置、支持强度与冲突。至少对核心主张回原文核验支持范围；摘要-only 不支撑摘要无法核实的细节。系统综述按已批准方案评估风险和证据确定性；叙述性综述可用透明的定性评价，不伪造评分。

**代表性工作对比表在大纲里就定**：要横向比较性能或效果的节（材料、方法、干预一类），在该节写「表：」一行定好列与行——列 = 关键指标 + 测试条件（取自笔记「方法」的可复现细节与「主要结果」的测试条件），行 = 拟引用（可写）的键。条件不同的数并列时各写各的条件，不跨条件算比值或排名；笔记里写「原文未报告」的格照填，不让初稿去补。

写清该框架相对旧框架解释了什么、或仅提供更新/教学整合。候选框架供人选，不用“覆盖 gap 更多”自动定案；允许证据不足、不形成统一答案。

初稿要按本大纲写。拟引用必须分成两档，否则初稿只会堆键或满篇「待核实」：

- **可写正文**：有全文精读笔记（notes/index.json 里 reviewStatus=reviewed、fulltextStatus=fulltext），出现在证据表，且支持强度不是题录级。
- **仅线索**：仅摘要级笔记、只速读过没有精读笔记的、题录级、只用来定位的综述。初稿不得用它们写定量结论或机制细节；仅摘要的只可写摘要实际报告的信息，键后标「（仅摘要）」。

只用 references.bib 里有的键；人在评审里排除的篇（papers/included.json 里 decision=excluded）不引用，交代它被排除时也不写 @键（成稿时 @键 会被当成引用），这两类 Mesa 会直接拦下。

证据表出现的论断编号（C1…）必须在表下全部定义。图表占位写已有数据从哪来（哪张表、哪条已完成的计数）；没有现成数据就改成不依赖新数的示意图，禁止写「将从文献池计数」却不附表。

每章（有小节则每小节）写 **用图计划**，只许用笔记「可引用图」里的条目。**一张拼图对应一个论点**：从几篇里各取撑这个论点的那一块子图，写成「拼 图N（论点一句话）= (a) [@键1] Fig.2c + (b) [@键2] Fig.3a + (c) [@键3] Fig.4d」，至少 2 块、至少来自两篇，块数按版面可读性定（双栏一行约 3 块，9 块排 3×3；一页放不下就按子论点拆成两张图）；整张本身就是一幅示意图 / 照片时才写整张。不要把两篇的整张多联图并排当拼图。**拼图只取研究论文的子图**（2026-11-12 用户拍板）：综述（含 Account，`papers/included.json` 里 kind=review）里的总结图不拼——那多半本身就是转引，照搬也显不出你的综合；要借它的总结思路，写「自绘 图N（论点一句话）= 参考 [@综述键] Fig.n + [@研究键] …」，初稿按 schematic-forge 自己画一张总结图 / 示意图，要点与连线各有出处。综述图里要的是某篇原始数据，就追到它引的那篇研究论文，在那篇的笔记可引用图里取块。凑不成则写「仅引用 [@键] Fig.n」。同一块子图（同一篇、同一图号含子图字母）只放进一张拼图，Mesa 会查重复。禁止点名笔记未登记的图号。禁止写「初稿全部待绘制」——那会让初稿 TASK 把空图当合同。需要文献池计数才能画的图，先在大纲附表给出计数，否则改成不依赖新数的「仅引用」。

要横向比较几篇文献（性能、条件、方法）的节，另写一行 **表计划**：「表 N（比什么一句话）= 列：… ；行：[@键1]、[@键2]…」。数值只取笔记里有出处的，初稿按它出 markdown 对照表；不需要表的节不写这一行。

### 二、拆解权威综述为范式卡片

0. 综述有「综述卡」（笔记里的「结构骨架」「覆盖范围与时效」两节）时直接用它补齐五项，不回原文再拆一遍；没有的才按下面拆。
1. 从 `papers/included.md` 中选取 **适量有代表性的综述类文献**（问题相关、方法透明且证据可追溯者优先；刊物和被引数仅作发现线索）；纳入清单中没有综述类文献时，如实说明并跳过本步，不得虚构范式。
2. 对每篇拆解其章节框架，写成一张**范式卡片**，五项必填：
   - **结构逻辑**：章节按什么线索组织（主题聚类 / 时间线 / 方法分类 / 问题驱动……）
   - **详略配比**：哪些部分重笔（如方法对比占全文比例）、哪些一笔带过
   - **论证顺序**：背景→现状→对比→展望，还是问题→方案→评估→开放问题等实际推进次序
   - **开篇策略**：以什么钩子开场（反常发现 / 文献矛盾 / 未解问题）
   - **过渡逻辑**：节与节之间靠什么推进（暴露假设 / 给出反例 / 转换视角……）
3. 范式卡片只记录结构事实，不摘抄内容；注明该范式适合回答哪类问题。

### 三、融合构造框架

1. **问题做主线、证据做约束、范式作参考**：以最能回答核心问题、解释证据分歧且适合目标读者的范式为主线骨架，把每条研究空白对应到框架中的具体章节位置——空白是章节理由之一，必要背景与方法也可因理解问题而存在。
2. 一个空白可由多个章节共同回应（在对应关系中注明）；一个章节可回应多个空白。
3. **空白类型提示章节功能**：方法空白→方法对比章、经验空白→情境/边界条件章、理论空白→整合框架章；其余类型按其内容就近落章。
4. **章节权重按回应空白的重要性分配**，禁止按文献数量均分；章节总数是预算，禁止一空白一章。
5. **取舍规则**：
   - 范式冲突时（结构逻辑不兼容），按核心问题、解释力、证据可比性和篇幅预算选骨架，落选范式的局部优点（如某节的论证顺序）可作为节内参考吸收；
   - **每章说明对理解问题的作用**；必要背景、方法和综合章节不必牵强挂某个 gap，不因无新颖性而删掉必要解释；
   - 空白无法落进任何范式时，允许新增章节，但必须在该节标注「空白驱动新增」。

### 一问一答定框架与覆盖检查（TASK.md 要求时）

融合之前不直接写整份大纲，先和人一起定：`outline.md` 顶部建「## 定框架记录」表（`| 问 | 问题 | 人的选择 | 日期 |`），按顺序**一次只问一个**，每问经 `.ccode/help-wanted.md` 写一条（建议选项标推荐、各选项后果一行、依据引 `angles.md` 条目或笔记），人答了写进表再问下一个：

1. 核心问题还对吗（取 `papers/screening.md`「核心问题与边界」）
2. 选哪几个角度（`angles.md` 多选，可自填）
3. 读者是谁、读完带走哪一句（按 2 给两三句候选）
4. 以哪篇综述的结构为骨架，或不照搬
5. 章节草图（你起草一版，人逐节保留 / 合并 / 删 / 改名）
6. 覆盖检查后哪些节要补料

表里已有答案的不再问；人改了表里某一行，之后都按新的来。不替人选，不写「必须创新」——重合度是给人看的证据，取舍是人的事。

章节草图定下后写「## 覆盖检查」表：

```markdown
| 节 | 可写正文篇数 | 仅线索篇数 | 最新一篇年份 | 判断 | 建议 |
|---|---|---|---|---|---|
| 3.2 失活机理 | 2 | 3 | 2020 | 薄 | 补检：近三年原位表征工作 |
| 3.3 动力学 | 1 | 0 | 2023 | 薄 | 补读：[@Wu2023] [@Li2024] |
| 4 展望 | 6 | 2 | 2025 | 够 | |
```

两列填篇数（键写在各节的拟引用里，不写进这张表），「可写正文 / 仅线索」与上面分档同一口径；只在速读表里、没有精读笔记的篇一律算仅线索。**篇数以 Mesa 数的为准**：Mesa 按各节拟引用里的键和 notes/index.json 的笔记状态另数一遍，评审页里对不上的会标出来；下一轮按 Mesa 的数改表，不要坚持自己数的。你只判断这一节要回答的问题，这些文献撑不撑得住：判断只写「够」或「薄」，后面跟一句理由；薄的在建议里写「补检：要补的方向」（清单里没有，要回检索补）或「补读：[@键]…」（已纳入、只速读过的，从速读表里挑撑这一节的）。第 6 问把薄节列成选项；人选不补的，判断改成「薄·不补：理由」。人选要补的，等补料回来、跟进完再写二级逻辑（每节的小节顺序、每小节要回答什么、用哪几篇、用什么图表）。

### 四、产出 outline.md 必须附覆盖声明与「框架推演」段

1. **覆盖声明**：写在文首，声明「本框架基于 `notes/` 下 N 篇精读笔记与 M 篇权威综述」，未纳入/未精读的文献范围如实列出——agent 只能看到已有笔记，不得把局部材料当文献全景。
2. **框架推演**：末尾固定附「## 框架推演」段，包含三块内容，供评审核对：
   - **空白清单**：逐条列出，标注类型与来源笔记，孤证已标注；
   - **范式卡片**：每篇权威综述一张（五要素）；
   - **融合理由**：选了哪个范式做骨架及为什么（问题、证据分歧、读者与篇幅）、每个空白落到哪节、哪些惯例章被删或新增及理由。
3. **完成自评**：以下逐条勾验，不满足项保持待审，不得因结构齐了就勾完：
   - 每章具备要点/拟引用/章节作用三件套（研究空白适用时对应）；
   - 核心空白已回应或说明未覆盖理由，章节作用明确；
   - 每条空白已标类型与来源，孤证已标注；
   - 必要背景/方法章说明其作用，不牵强挂靠空白；
   - 覆盖声明已写；
   - 全部引用键存在于 `references.bib`；
   - 每章拟引用已分可写正文/仅线索，可写键均在证据表且非题录级；表内论断编号全部定义；图表占位有已有数据来源；每章/小节有用图计划（拼或仅引用，源图来自笔记可引用图）。

## 反模式

1. 无目的按时间或作者罗列——若研究问题本来是历史演变，可按时间组织并说明论证意义；
2. 「无人研究过 X」式伪空白；
3. 一文献一章、一空白一章的均分结构；
4. 章名宏大但无要点、无引用、无空白回应的空壳章；
5. 把题录级、摘要级文献整章铺进「拟引用」，留给初稿去堆砌。
6. 把「篇幅总预算」写成初稿必须凑到的词数——那是读者预期，初稿不得当完成配额。
7. 把空白编号 G1 写进初稿正文；G 编号只留在本文件「框架推演」。初稿用白话写该空白（「机理路径未统一」），不要把 G1 当领域术语。
8. 用图计划写成「初稿待绘制」；初稿只能「拼成文件」「自绘成文件」或「见 Fig.n」。
9. 把综述 / Account 里的总结图写进「拼」——改成追原始研究论文的子图，或「自绘」。

## 产出格式

`outline.md`（写入综述工作区根目录）：

```markdown
# 综述大纲

> 形态：期刊独立综述｜覆盖声明：本框架基于 notes/ 下 12 篇精读笔记与 3 篇权威综述，未覆盖……

## 1. 引言
- 要点：……（按问题需要）
- 拟引用（可写）：[@bib键1] [@bib键2]
- 拟引用（线索）：[@bib键3]
- 用图：拼 图1（论点一句话）= (a) [@bib键1] Fig.2c + (b) [@bib键2] Fig.1b + (c) [@bib键3] Fig.4a（凑不成则仅引用 [@bib键1] Fig.2）
- 表：表 1（几种催化剂的活性对比）= 列：材料、条件、关键指标；行：[@bib键1]、[@bib键2]（不需要表的节不写）
```
