三个文件各管一件事，下面逐个说，最后用一张表对比。

**text-reveal.ts — 流式文字的匀速放出**

解决的问题：实时预览的文字是一块一块到的，到一块贴一块，画面一顿一顿地跳，长回复时尤其明显，读的人跟不上节奏。

怎么解决：到达只改「目标文本」，画面上显示多少由它自己管：每帧放出积压量的一部分（积压 × 帧时长 ÷ 220ms），积压多时放得快、积压少时放得慢；切口只落在安全位置，不把 Markdown 标记切成两半。

**stable-props.ts — 不陪跑重画**

解决的问题：终端页把每个标签的聊天层、状态栏画在同一个大组件里，传下去的回调全是内联闭包——任何一个标签的实时预览出一行字，所有标签的整段对话都跟着重画；memo 挡不住，因为闭包每次渲染都是新的。

怎么解决：memoWithLatestFunctions 包一层：比较 props 时函数一律算相等，其余 props 只比一层（数组/对象看引用，空数组视为相等）；同时把 props 里的函数换成按路径缓存的「转发函数」——子组件跳过重画后手里拿着的旧函数，被调用时顺着路径去 latest ref 里取这一次渲染的新闭包来执行，不会拿到过期状态。depths 指定哪些 prop 里嵌着函数要往下找几层（对象 2 层、数组 3 层）。另有 frozen 开关：藏着的标签直接跳过重画，等露出来那一下再按最新数据画一次。

**chat-handoff.ts — 聊天层与终端层交接的纯逻辑合集**

解决的问题：聊天层和终端跑在同一个 PTY 上，它要判断哪些事自己能办（直切 /model、y/n、Esc）、哪些必须交还给终端（认不出的确认、选择器、登录），以及「发出去的话 CLI 到底收下没有」——而且不能为九家 CLI 各写一份 TUI 菜单解析器。

怎么解决：一组纯函数把「发出的内容」和「会话文件 / 终端屏记录下的内容」做容错比对：落盘可能带残留草稿、Windows 上 Codex 会吞 emoji，所以包含即算、去空白和增补字符再比；只认发送之后才出现的记录，避免重发同一句时气泡被误摘。斜杠命令按家分治：Claude 会写成 command 块、Kimi/Codex/AGY 发出即本机执行（认得出结果行就收尾，或等终端静、或这轮结束直接落记录），Qwen 排队到下轮。

**三者对比**

| 文件 | 解决什么问题 | 核心机制 | 用在哪 |
|---|---|---|---|
| text-reveal.ts | 流式文本一块块到，显示一顿一顿跳 | 到达只改目标，每帧按时间常数放一部分积压；安全切口 | 聊天层实时预览的打字机效果 |
| stable-props.ts | 内联闭包让 memo 失效，一处更新全页重画 | 函数比较恒等 + 按路径转发到最新闭包 + frozen 冻结隐藏标签 | 终端页多标签的聊天层 / 状态栏重画控制 |
| chat-handoff.ts | 聊天层不复制 TUI 解析器，也要知道发的话收下没有、该不该交还终端 | 发出内容 vs 会话文件/屏幕记录的容错比对，按家定规则 | 聊天层收尾、斜杠命令、审批交接、乐观气泡与翻页 |

共同点：三个都是纯逻辑模块（配 tests/ 同名测试），把「判断」和「React 渲染」分开，组件只消费它们的结论。
